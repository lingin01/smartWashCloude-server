# PLC点位与清洗历史保存方案

> 前期材料：本轮新增D201、D203～D206、M50等点位后的统一规则见[新版统一方案](unified-plc-business-and-data-plan.md)。原状态推导、整次往返记录和旧写点建议不再作为实施口径。

> 2026-10-23更新：用户明确“上行保存核心采样，下行只保留异常事件点”。最新实时/历史/详情口径见[上行历史与页面数据方案](realtime-upward-history-and-detail-plan.md)。本文原先关于整次往返、双向连续历史和计数归属的建议已由新方案调整；点位事实继续作为参考。

本文件仅整理业务方案，不修改程序、点位配置或数据库。依据2026-10-22提供的PLC点位说明，使用已经明确含义的事实；未明确的阶段数字、周期信号和写入编码不纳入本版设计，不猜测、不预留占位实现。

系统规模：一台PLC、四台动力设备、八路索拉力。保留一个大厅入口以及清洗、命令、安全、统计四个业务服务。数据过期、新鲜度阈值和按时间推算离线不在方案范围内。

## 1. 点位的取舍

“不进入核心”仅指后端的常规业务不依赖它，不是删除PLC内部程序。

| 用途 | 已明确的点位 | 使用方式 |
|---|---|---|
| 新版系统/单机状态 | D201、D203～D206 | 状态主来源；映射及有效性见新版统一方案 |
| 控制电源 | M0 | 独立显示24V控制电源状态，与通信在线分开 |
| 系统故障及急停 | M1、M2、M3、D3 | 主状态、故障原因、故障/急停事件 |
| 运行许可 | M4、M11、M12 | 显示允许运行和当前模式的安全许可，不当成正在运行 |
| 模式和自动启动 | M10、M13 | 区分自动/手动、自动是否已启动 |
| 运行与中断 | M7、M110、M6 | 自动运行、有轴运动、中断停止的事实 |
| 正常到位 | M8、M9 | 正常回原位、下降到位；按实际观测记录 |
| 同步方向 | M20、M21 | 同步上行/下行信息 |
| 四机独立方向 | M22～M29 | 各自的上行/下行，不把整体方向无条件复制给单机 |
| 电机和编码器异常 | M30～M37 | 分别关联四台设备的故障原因 |
| 过程异常和回退 | M40、M210～M215 | 保存过程事件，区分异常发生与最终退出清洗 |
| 拉力异常 | M300～M306 | 过大、过小、整体及各机两索不平衡 |
| 高度/编码器异常 | M310、M311 | 清理部件不平衡、编码器不跳值 |
| 计数 | D10～D14 | 分别保存上/下行完成、上/下行故障和中断次数 |
| 八路拉力 | D40～D47 | 核心测量；已经是kg，不重复换算 |
| 四机速度、同步速度 | D61～D65 | 分开保存，cm/s换算为m/min |
| 驱动器力矩原值 | D70～D73 | 原值及按明确公式计算的等效力 |
| 四机高度 | D80～D83 | 核心测量；cm换算为m |
| 驱动器错误详情 | D300～D307 | 异常发生或变化时关联保存 |

以下数据有诊断价值，但第一版不必进入每帧核心历史：

| 点位 | 原因 |
|---|---|
| D30～D37 | 传感器原始数据；常规拉力先用已明确的D40～D47 |
| D48～D52 | PLC平均值；后端可以从有效拉力计算，不必重复作为原始测量存储 |
| D53～D60、D85～D88 | 编码器原始量、转速；常规业务已有高度和运行速度 |
| D66～D69 | 单轴连续运行时间；不能替代整次清洗时长 |
| M100～M106、M205、M206 | PLC受控和定时辅助；不作为实际运动或完整清洗的独立依据 |
| D1000～D1017 | 顶底记录和负载参考，属于标定/调试数据，不每帧重复保存 |

空白或含义未确认的点位不列入本版业务字段。上下限高度不写死，也不从测试编码器值直接推导米制限位。

## 2. 系统状态

主状态只有五种：待机、运行、检修、故障、离线。模式、方向、控制电源、运行许可和故障原因单独表示。

| 主状态 | 方案规则 |
|---|---|
| 离线 | 实际PLC通信失败，不根据采样时间判断过期 |
| 故障 | 实际急停或故障信号有效；保留具体原因 |
| 检修 | 正常通信、无故障，处于手动模式 |
| 运行 | 正常自动模式下正在执行清洗；已确认的过程停留仍属于该次清洗 |
| 待机 | 在线正常，当前没有执行清洗 |

建议控制电源关闭时显示“待机，控制电源关闭”，保留PLC通信状态，避免把电源关闭解释为网络断开。

M2=1表示急停；M1=1且M2=0按已提供说明解释为故障。M3和D3保留为总故障及详细原因。不能用D3=0否定独立急停输入，也不把总故障无条件归因于四台电机。

手动模式下某台正在运动，仍可显示“检修”，另显示其方向和测量值。数据缺失不补成0或“正常”，不增加第六种业务主状态。

## 3. 单台动力设备

| 设备 | 拉力 | 高度 | 单机速度 | 力矩原值 | 提升/下放 | 电机/编码器异常 |
|---|---|---|---|---|---|---|
| 1 | D40、D41 | D80 | D61 | D70 | M22、M23 | M30、M34 |
| 2 | D42、D43 | D81 | D62 | D71 | M24、M25 | M31、M35 |
| 3 | D44、D45 | D82 | D63 | D72 | M26、M27 | M32、M36 |
| 4 | D46、D47 | D83 | D64 | D73 | M28、M29 | M33、M37 |

每台需要：业务编号、五态、模式、方向、两路拉力及均值、高度、当前适用的速度、力矩原值/等效力、故障原因和采集时间。没有独立驱动器在线反馈时，不声称已经检测出每台独立通信状态。

两索都有效才给本机两索均值。同步速度与单机速度分别保存；非当前工况的数据不当成有效实测0。单机故障分别归属，不把其他三台显示成相同电机故障。

明确的工程量换算：

- 拉力：D40～D47已经是kg，保留其PLC取整精度。
- 高度：cm÷100，统一为m。
- 速度：cm/s×0.6，统一为m/min。
- 驱动器原值按提供公式换算等效力：`原值×0.35×163.0883×1.0÷(9.80665×0.16)`，结果按等效kg展示，不能标成N·m。

四机均高、最大高度差可计算，但不冒充独立圆环高度测量。缺测通道不参与有效均值。

## 4. 每一次清洗

建议一条清洗记录对应一个自动往返周期：从实际开始，到正常回到本次原位，或因明确的中断、急停、故障终止而结束。正常和未完成的记录都保留。

原位在顶部时可以先下后上，原位在底部时可以先上后下，不写死先后方向和运动高度。

保存过程：

1. 实际开始时创建本次清洗记录，关联设备和后续采样。
2. 运行中持续保存测量、状态变化和异常，不等整次结束才保存。
3. 正常返回原位以实际观测到的M8完成事实为依据；M9是下降到位信息，不单独当成整个往返完成。
4. 中转、停止观察、PLC回退恢复的过程继续关联同一记录，不把每次短暂停止都拆成新清洗。
5. 清洗明确结束时补充结果和摘要。没有取得完成依据，就不记正常完成，不按速度、时间、高度或单程次数补算。

M8是约1秒信号，轮询可能漏采；本方案不承诺依靠该脉冲能无损识别所有完成次数。D10、D11各自保持上/下行单程计数含义，不相加除2当作完整清洗次数。

一条清洗记录需要：设备、开始/结束或最后观测时间、结果、过程方向、运行参数、八索和四机的统计摘要、相关异常/操作及数据完整情况。首次接入已经在运行的清洗，不虚构实际启动时刻。

现场自动启动没有可验证后台账号时，来源记为现场/PLC，操作人留空；不能把当时登录的用户当成实际操作人。

## 5. 历史保存

先用三类业务数据组织，不在本轮创建表或编写SQL：

| 数据 | 内容 | 作用 |
|---|---|---|
| 清洗记录 | 每次清洗的身份、起止、结果、参数和摘要 | 历史列表、单次详情 |
| 测量帧 | 时间、设备、所属清洗、八索/四机测量、状态和有效性 | 曲线及后续分析 |
| 事件 | 故障、急停、中断、恢复、状态和用户操作变化 | 解释清洗过程 |

四机八索是固定规模，建议一帧保存一组核心测量，不为每个点分别建表。未处于自动清洗时的测量也可以保存，但不冒充自动清洗记录。持续故障按变化记录事件，不在每帧重复创建相同故障。

实时显示和历史保存使用同一份业务采样，但用途不同：页面可取最新值；历史不能因为更新最新值而覆盖上一帧。用户未打开页面，后台仍然采集和保存。

数据库暂时不可用时需要保留待保存数据，提交成功后才确认完成；如要求重启后继续保存，待保存数据必须落在持久磁盘，不能只有内存队列。重试应避免重复记录。已入库历史和待保存文件都要纳入备份考虑。

数据库/服务/PLC断线期间没有采到的数据不补造，历史曲线保留缺口。长期历史不设置自动删除规则，后续容量规划按实际采样频率、启用字段和磁盘情况确定。

容量先按可计算的帧数讨论：若采用2帧/秒，全天约17.28万帧、365天约6307万帧。每帧实际字节数尚未由最终存储结构确定，本版不写未经验证的GB/年结论。

## 6. 实时和历史怎样展示

实时首页：系统五态、电源、模式、许可、四台设备卡片、八路拉力、速度和高度；显示采集时间，但不按时间戳判定过期。

历史列表：每条清洗的开始、结束或最后观测时间、时长、结果和异常摘要。点开一条后展示：

- 八路拉力、四机高度、当前适用速度及等效力曲线，单位分开。
- 故障、急停、中断和恢复的事件时间轴。
- 有效样本数量、最大/最小和采样平均值；采样平均不称为时间加权平均。
- 可验证的后台操作账号；现场动作不虚构账号。

查询按清洗或时间范围分页，避免一次把所有历史发给前端。长时间图可以减少显示点数，但显示处理不能等同于删除原始历史，也不能隐藏异常峰值或填平缺口。

## 7. 下发操作

只按已确定的业务操作下发，不提供任意寄存器写值功能。

新版急停请求采用本轮给出的M50写1；M15留旧含义，不双写或自动回退。写请求成功和设备实际停止分别记录，远程反馈关系见统一方案。不设计写0解除急停。

运行参数修改作为已确定的业务需求保留；本版不编写未明确的启动时间编码、毫秒存储区关系、具体报文映射或生效判断，也不扩展新的写入能力。

远程启动、复位、解除急停、暂停/恢复和单机升降不进入当前开放操作。后台操作人从登录账号取得。

## 8. 服务职责和整体流程

| 模块 | 职责 |
|---|---|
| 大厅 | 统一入口，选择查询、操作或设备数据路径 |
| 清洗服务 | 维护系统/单机状态、每次清洗过程，编排操作和查看历史 |
| 命令服务 | 管理命令状态、排队和下发结果 |
| 安全服务 | 检查登录权限及已经确定的操作条件 |
| 统计服务 | 保存与查询历史，计算摘要和图表数据 |
| 设备管理/DAO | 设备档案、数据读取和数据库事务 |

采集流程：PLC → 采集缓冲 → 上层表示入口主动取数据 → 大厅 → 清洗服务 → 状态及本次清洗整理 → 统计服务保存 → DAO → 数据库。

实时流程：推送入口 → 大厅/权限检查 → 清洗服务只读快照 → 页面。

历史流程：用户查询 → 大厅/权限检查 → 清洗服务编排 → 统计服务历史查询 → DAO → 列表/详情/曲线。

操作流程：登录用户 → 大厅 → 安全服务 → 清洗服务 → 命令服务 → 下发缓冲 → PLC；写结果由上层接入取回，再进入清洗编排和命令状态处理。

系统和清洗过程状态只在清洗模块修改，命令状态只在命令模块修改。各业务服务委派自己的辅助类，上层调用下层，下层不反调上层。同一规则只在所属位置处理，不在每一层重复判空或重复校验业务参数。

当前代码仍是此前的四服务架构与7表基线；上述每次清洗、逐帧历史及查询属于设计方案，不表示已经实现。

单次运行落库、自然日历边界、历史预计算、持久缓冲、异常补传及曲线查询的细化方案见[运行历史与周期统计方案](run-history-and-period-statistics-plan.md)，同样仅为设计文档。
