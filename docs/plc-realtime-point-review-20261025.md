## 1. 结论与对象归属

这批点位能够支撑系统与四台动力设备的主要实时状态、方向、八路拉力、电机力矩换算的等效拉力。四台高度需要先完成编码器字序和各自底部值测试；区间速度需要同一连续运行段内的有效高度和 PLC 计时增量。

现有代码具备通信、32 位解码、线性换算、快照和 SSE 基础，但尚未按本次点位完成业务适配，不能仅换配置就宣称已经接通。

```text
系统
├─ 动力设备1 → 传感器1、传感器2
├─ 动力设备2 → 传感器3、传感器4
├─ 动力设备3 → 传感器5、传感器6
└─ 动力设备4 → 传感器7、传感器8
```

以上传感器顺序作为点位对照，实际设备/传感器编号及接线归属须配置确认。现有内部 `deviceId` 标识 PLC 通信设备；动力设备使用独立 winch 身份，传感器使用独立 sensor 身份。页面组织以系统为根。

### 状态和方向

- D201：1运行、2待机、3检修、4故障。正常读到的状态按PLC定义映射，连接状态由TCP层独立提供。
- D203～D206：0待机、1运行、2故障，各自定位对应动力设备，保留原码。系统检修、总故障与本机原始状态分别表达。
- 各台方向分别读取自己的上下行信号。上=1/下=0表示上行；上=0/下=1表示下行；都0表示没有上下行指示；都1表示信号冲突，不选择任一方向。
- 没有上下行指示不单独证明机械已经停止。状态码和方向不一致时保留各自事实与说明。
- D202 本次仅明确与 M201 的自动模式语义有关，没有给出完整数值枚举。保留原值，不自行定义上/下行码，也不在手动模式沿用该值推断四台方向。
- M3=1表示总故障，M3=0表示该故障位未激活。D201、M3与D3不一致时标记来源不一致，不静默清除其他明确故障依据。

## 3. 测量换算

### 八路传感器拉力

按用户公式，每一路分别处理：

```text
tensionKg = (raw - 10) × 0.001 × 101.9716
          = raw × 0.1019716 - 1.019716
tensionT  = tensionKg / 1000
```

现有解码器使用 `raw × scale + offset`，可表示该公式：scale=0.1019716，offset=-1.019716。D30～D37 的数据类型作为接入配置确认。正常读值直接按公式换算；原始值小于10时会得到负值，不自动截成0或据此判硬件故障。

每台两索总拉力应由两路有效值相加；两路平均值另行命名。电机力矩换算值是独立来源，不能用两索平均值或合计替代。缺一路时完整两索总拉力未确认，仍可展示有效单路。

### 四台电机力矩换算

按用户公式，D70～D73分别换算：

```text
equivalentForceKg = raw × 0.35 × 163.0883 / (9.80665 × 0.16)
```

可用线性比例表达，近似系数36.37895267497055。实现中保留给定公式和足够精度，最终显示时再舍入。字段明确标为“电机力矩换算的等效拉力”，不与力矩原始值或两索合计混用；实际值类型和倍率需要现场核对。

### 编码器分层高度

每台独立配置 `bottomEncoderCount`，按自己的有符号32位编码器值计算：

```text
r = (encoderCount - bottomEncoderCount) / 8192

r <= 12：heightM = r × 1.043
12 < r <= 24：heightM = 12.516 + (r - 12) × 1.1069
r > 24：heightM = 25.7988 + (r - 24) × 1.171
```

上述公式来自用户给出的厘米公式换算为米；12圈处为12.516m，24圈处为25.7988m，分段连续。第三层可用圈数及机械限位尚未提供，不推定最大高度。

四台底部值分别等待实测，实测后写入各台配置，运行中按配置计算，不新增“未标定”状态判断。不得把首次读数或0自动当作实测底部值，也不把负高度自动改成0。四台高度可明确展示“四机平均高度”，其数值不等于另有测量来源的系统/圆环真实高度。

### 32位字序测试

用户提供的测试值1234567890对应十六进制 `0x499602D2`：高16位18838，低16位722。读取D0/D1核对两种字序是否能正确还原该已知值。现有解码器支持INT32及ABCD/CDAB等顺序；最终配置以实测为准，不能默认测试结果。其他32位字段的类型和字序也应按PLC定义核对。

### 速度

D66～D69是各台连续运行计时，停机后重新计数。它们可作为已确认同一连续运行段的时间依据：

```text
intervalSpeedMPerMinute = abs(heightNowM - heightPreviousM)
                         / (axisSecondsNow - axisSecondsPrevious) × 60
```

这是观测区间平均速度。只有高度有效、段归属明确、计时差大于0且方向无冲突时才计算；首次采样、计时重置、方向改变或整数秒未递增时，不输出一个伪造速度。方向另行表达，不用速度正负代替方向位。不能用“当前绝对高度 / 当前运行时间”作为实时速度；也不能跨重启沿用旧段基准。

## 4. 故障定位

| D3 | 解释 | 定位 |
|---|---|---|
| 0 | 无故障码 | 保留其他状态来源，不单独覆盖D201/M3事实 |
| 10～13 | 电机1～4使能故障 | 对应动力设备；D300～D303可提供补充原码，含义待明确 |
| 15～18 | 电机1～4运行故障 | 对应动力设备；D304～D307可提供补充原码，含义待明确 |
| 20～27 | 拉力1～8异常 | 对应索/传感器测量通道；原因可能是钢绳或连接等，不直接认定传感器损坏 |
| 28～35 | 传感器1～8故障 | 对应传感器设备 |
| 40～43 | 编码器1～4读数异常 | 对应动力设备的编码器来源及相关高度/速度质量 |

通道/本机故障只影响有依据的对象和测量，不能将总故障解释成四台全部硬件故障，也不把没有出现在D3中的七路自动标为正常。D3只有一个当前码，无法仅凭它表达任意多路并发故障；若需要完整并发列表，需确认PLC还提供哪些独立信号。

## 5. 次数、时间和远程写入的范围

- D10：PLC定义的完成上行次数；不能直接当成今日次数、服务启动以来次数或全部上行尝试数。计数保留/清零/回卷规则仍需确认。
- M204：用户补充确认，自动模式一次运行结束触发，上去再下去算一轮完成。历史列表一次上行一条，并关联所属往返轮次。信号保持/清零方式暂未确认，异常退出是否触发、轮次开始和可靠关联仍待确认。M204不等于单独上行结束，也不能每读到一次1就新增一轮。主流程详见[实时与历史主流程分析](plc-realtime-history-main-flow-20261025.md)。
- D16：本次自动运行计时，启动开始计、停止/中断后重新计；不能当累计工时，也不能单独证明实际机械运动时间。
- M15：本次最新说明指定的远程急停写1目标。属于控制链路；实时采集不得因更新展示而自动写入。实际映射和执行反馈仍须核对。
- D100/D101/D102及D110/D114：远程参数写入和单位、回读关系需要另外确认。特别是“启动时间”指时刻还是启动延时尚不明确，不能直接把毫秒数编码为HH:mm。它们不阻挡已确认实时读点的适配。
