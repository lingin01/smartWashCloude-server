## 一 修订结论

原说明主要记录了前端现有行为，包括前端判断阈值、推导状态、计算总拉力和统计结果。修订后，这些行为不再作为正式职责约定。后端完成业务数据加工，并把结果、状态、名称和提示内容一并返回。

| 项目 | 修订后约定 |
| --- | --- |
| 查询对象 | 统一使用 `systemCode`，例如 `QJXT-01`；不再默认查询 `TANK-03` |
| 系统与设备关系 | 一个系统对应四台动力设备，每台动力设备对应两个传感器；各对象都有独立编码 |
| 系统与动力设备工况 | 待机、运行、检修、故障、离线五种；待机显示黄色 |
| 首页更新 | 先获取初始快照，之后由后端每 1 秒推送一次最新数据 |
| 详情和拉力对比图 | 作为查询快照展示，取消每 5 秒自动刷新；进入、主动刷新、重试或切换查询范围时读取数据 |
| 状态和阈值 | 后端根据数据库配置与设备数据判断，前端只显示返回状态及提醒 |
| 故障定位 | 后端明确故障对象；设备故障标识该设备，单传感器故障标识该传感器 |
| 名称 | 后端返回实际显示名称，如“动力一号设备”；前端不再根据组号自行拼接 |
| 曲线和统计 | 总拉力、平均值、极值、有效样本、周期对比、历史结果均由后端处理 |
| 页面跳转 | 取消首页设备故障、离线状态和异常测点的告警跳转；保留查看设备详情及独立告警中心 |
| 详情字段 | 删除未展示的 `ratedLoad`、`ratedSpeed`；`setSpeedMPerMinute` 改为必返 |
| 旧接口 | 不再把旧趋势查询、独立运行对比、独立伺服趋势的兼容方案纳入本次正式对接 |

标记中删除的是当前工况枚举里的 `EMERGENCY_STOP` 和旧兼容判断。**急停按钮及急停请求保留**，历史记录仍可记录“急停”这一实际结束原因。

视频预览继续不纳入本次范围。其余页面共 12 个，其中历史巡检和数据分析仍为占位页。

## 二 前后端职责边界

### 2.1 前端负责的内容

1. 展示后端返回的系统信息、设备状态、传感器读数、曲线、统计和历史记录。
2. 根据明确的状态码套用固定文字样式和颜色；优先展示后端返回的业务名称、状态说明及业务提示。
3. 处理查询条件、设备选择、图例开关、分页、弹窗、返回和查看详情等页面交互。
4. 做基础输入检查，例如必填、数字格式、开始时间不能晚于结束时间，以及页面现有的参数范围提示。后端仍需执行完整校验。
5. 进行小数位、日期和单位格式化。吨与公斤换算属于展示处理，不改变后台原始值及统计口径。
6. 显示加载中、没有数据、保存成功、请求失败、连接中断等简单提醒。
7. 将用户确认后的查询条件或操作请求提交给后端，展示后端返回结果。

前端可以对已返回的某条曲线进行显隐、选择某次记录和读取某个采样点；不因此重新计算业务状态、合计值或统计结论。

### 2.2 后端负责的内容

| 后端责任 | 需要返回的结果 |
| --- | --- |
| 接收设备数据并维护对象关系 | 系统、动力设备、传感器编码与实际名称、关联关系 |
| 维护数据库配置 | 当前有效的预警值、安全保护值、运行参数及生效范围 |
| 判断设备工况与测点状态 | 最终状态码、中文状态说明、故障对象及必要提示 |
| 处理实时数据 | 同一采样时点的快照、平均值、方向、在线性和更新时间；首页每秒推送 |
| 数据质量处理 | 有效值或 `null`、质量标记和缺失原因，不能用 0 冒充缺失 |
| 钢绳数据配对与合计 | 经过时间、高度、方向等规则匹配的总拉力及合计质量 |
| 曲线整理与统计 | 排序后的曲线、周期平均、加权均值、最大最小及实际样本数 |
| 历史运行判断 | 本轮结果、结束原因、异常次数、完成次数及当时的参数快照 |
| 告警处理 | 告警产生、分类、恢复、归档、去重、排序、筛选和统计 |
| 周期比较 | 本次与上次、历史平均、环比、同比的实际比较范围与结果 |
| 数据查询与导出一致性 | 稳定分页、完整日期索引、查询总数，以及同一查询范围的完整导出数据 |
| 操作执行 | 参数校验、保存及下发、急停命令处理、权限控制和执行回执 |

具体控制、保护和恢复算法由后端结合设备侧能力实现，不在前端文档中编造。前端不根据某个读数自行判定是否应停机或恢复。

### 2.3 必须从前端移出的业务处理

| 现有或原说明中的处理 | 修订后的做法 |
| --- | --- |
| 比较 `pressure` 与 `alarmThreshold`、`safetyValue` | 后端返回传感器最终 `status`、`statusText` |
| 通过多台设备状态推导系统状态 | 后端返回最终 `systemStatus`、`systemStatusText` |
| 系统故障后将其他设备统一显示待机或故障 | 后端逐台返回真实工况，前端不联动改写 |
| 用两路传感器相加得到总拉力 | 后端返回独立总拉力序列和统计 |
| 按 `sampleCount` 计算加权平均与最高最低 | 后端计算并返回统计对象 |
| 根据事件数组猜“正常完成”“异常完成”“异常结束” | 后端返回最终运行结果及其中文说明 |
| 根据等级或内容猜告警类别、阈值类别和处理要求 | 后端明确返回类别、阈值类别、结果文字及处理要求 |
| 前端生成历史周期、可查询日期和同比数据 | 后端返回实际周期分组、日期索引和比较结果 |
| 前端用演示常量补阈值、显示编号、默认生产设备 | 从服务端实际配置返回；缺失时显示未配置或没有数据 |

## 三 系统编号与设备层级

### 3.1 对象层级

```text
系统 QJXT-01
├─ 动力一号设备  WJ-01
│  ├─ 传感器 PS-01  钢绳1-1
│  └─ 传感器 PS-02  钢绳1-2
├─ 动力二号设备  WJ-02  → 两个传感器
├─ 动力三号设备  WJ-03  → 两个传感器
└─ 动力四号设备  WJ-04  → 两个传感器
```

`QJXT-01` 是整个系统编号，不是四台动力设备共用的设备编号。示例中的动力设备和传感器编码用于说明层级，实际编码及名称由后端返回。

### 3.2 字段命名

| 字段 | 含义 | 修订要求 |
| --- | --- | --- |
| `systemCode` | 系统编号 | 统一用于查询、写操作、响应、推送、页面上下文和导出；替换原系统含义的 `tankCode` |
| `systemName` | 系统显示名称 | 对应标注中的系统名称，由后端配置返回 |
| `systemHeight` | 系统总高度，m | 首页使用该字段，不固定写死 30m |
| `systemCurrentHeight` | 系统实时高度，m | 首页实时读数与示意图使用同一返回值 |
| `winchCode` | 单台动力设备编号 | 仍保留，用于定位具体动力设备 |
| `winchName` | 动力设备显示名称 | 返回“动力一号设备”至“动力四号设备”等实际名称，前端直接显示 |
| `groupNo` | 动力设备组号 | 用于设备布局、关联和排序，不用于猜测状态或拼接业务名称 |
| `sensorCode` | 单传感器编号 | 定位具体测点 |
| `sensorName` | 测点显示名称 | 后端返回实际名称，如“钢绳1-1” |
| `recordCode` | 运行记录编号 | 定位一次历史运行 |

目标页面地址示例为 `/dashboard?systemCode=QJXT-01`、`/command-center/winch/WJ-01?systemCode=QJXT-01`。历史等路径中的系统参数也统一命名为 `systemCode`；具体 URL 层级可以沿用原结构。

系统编号应来自登录后的系统配置或当前选择。即使目前只部署一套系统，也应由后端配置给出，前端不自动回退到 `TANK-03`。编号不存在、没有权限或缺失时，由接口返回明确说明，页面显示提示。

### 3.3 状态与颜色

| 对象 | 状态码 | 中文 | 展示要求 |
| --- | --- | --- | --- |
| 系统、动力设备 | `IDLE` | 待机 | 黄色提示，保留独立状态 |
| 系统、动力设备 | `RUNNING` | 运行 | 沿用运行样式 |
| 系统、动力设备 | `MAINTENANCE` | 检修 | 沿用检修样式，并显示文字 |
| 系统、动力设备 | `FAULT` | 故障 | 对应故障对象红色提示 |
| 系统、动力设备 | `OFFLINE` | 离线 | 沿用离线样式 |
| 传感器 | `NORMAL` | 正常 | 展示有效读数 |
| 传感器 | `WARNING` | 拉力提示 | 展示后端预警结论 |
| 传感器 | `ALARM` | 拉力异常 | 展示后端保护阈值相关结论 |
| 传感器 | `FAULT` | 传感器故障 | 标识具体故障传感器，不改写设备本体工况 |
| 传感器 | `OFFLINE` | 离线 | 展示后端确认的离线状态 |

系统不再使用重复的 `tankStatus`、`tankStatusText` 旧字段。动力设备保留一个权威工况字段 `operatingStatus`，配套 `statusText`；不再同时依赖旧 `status` 做兼容推断。

### 4.2 正式对接接口

以下沿用 15 个现有页面 HTTP 方法与路径组合，**输入字段及返回责任按本文修订**。这里的“沿用”仅指地址基础，不能认定当前代码已支持全部修订字段。路径相对于 API 基地址。

| 方法与地址 | 主要输入 | 后端返回与职责 |
| --- | --- | --- |
| `POST /auth/login` | `username`、`password` | 登录结果和令牌 |
| `POST /auth/logout` | 认证上下文 | 退出处理结果 |
| `GET /auth/user-info` | 认证上下文 | 当前用户资料、角色、权限 |
| `POST /auth/refresh` | `refreshToken` | 一致的令牌刷新结果 |
| `GET /command-center/home` | `systemCode` | 首页完整初始快照 |
| `POST /command-center/emergency-stop` | `systemCode` | 急停请求的受理或失败结果 |
| `GET /command-center/winch/detail` | `systemCode`、`winchCode` | 单台设备详情快照 |
| `GET /command-center/winch/tension/trend` | `systemCode`、`winchCode`、`viewType`、`comparisonView` | 统一拉力对比、总拉力及统计 |
| `GET /command-center/archive` | `systemCode`、设备和分析条件、完整比较日期 | 一次返回两图与汇总 |
| `GET /command-center/alarm-dashboard` | `systemCode`、日期、设备、测点、类别、视图和分页条件 | 已处理的告警列表及统计；新增查询字段需联调 |
| `GET /command-center/history/list` | `systemCode`、单次范围与分页 | 完整运行结论和日期索引 |
| `GET /command-center/history/detail` | `systemCode`、`recordCode` | 单次详情、各来源曲线和统计 |
| `GET /command-center/parameter-settings` | `systemCode` | 本系统当前参数 |
| `PUT /command-center/parameter-settings` | `systemCode` 与三项运行参数 | 校验、保存及执行阶段的明确结果 |
| `GET /users` | 关键词与分页 | 筛选后的只读用户列表 |

实时通道单独约定；导出接口在第七节列为新增建议，不计入上述 15 项。

下列内容不再作为本次页面正式契约：旧 `rangeType` 趋势查询分支、`/command-center/winch/tension/run-comparison`、`/command-center/winch/torque-force/trend`，以及与当前单次详情无关的旧历史响应结构。伺服曲线仍需要展示，由统一对比接口返回。

## 五 首页数据与每秒推送

### 5.1 加载与更新方式

1. 页面取得有效 `systemCode` 后，调用首页接口获取初始完整快照。
2. 以同一个 `systemCode` 建立实时订阅，由后端每 1 秒推送一次最新快照。
3. 前端按系统编号核对消息归属，用新快照更新页面读数、状态和图形。
4. 切换系统后释放旧订阅，加载新系统快照并重新订阅。
5. 连接中断时前端提示“数据连接中断，请重新连接”，并保留明确的更新时间或旧数据标识；不能根据连接中断自行宣布设备已经故障或离线。

推送使用 WebSocket 还是 SSE、连接地址与鉴权方式由后端确定；**每 1 秒推送一次是已明确要求，具体通道地址尚未确定**。连接心跳、顺序、重连恢复和异常响应需要在实际通道契约中约定。

### 5.2 首页返回字段

下表为修订后的最小业务数据，均位于 `data`。没有数据的可空数值仍需保留字段并返回 `null`，不能省略后由前端编造。

| 字段 | 类型 | 含义与提供方 |
| --- | --- | --- |
| `systemCode` | string | 系统编号，后端返回 |
| `systemName` | string | 系统名称，后端返回 |
| `systemStatus` | string | 五种系统工况之一，后端最终判定 |
| `systemStatusText` | string | 待机、运行、检修、故障、离线等中文说明 |
| `online` | boolean | 后端确认的系统在线性，不代替所有子对象的状态 |
| `systemHeight` | number | 系统总高度，m |
| `systemCurrentHeight` | number 或 null | 当前有效高度，m |
| `isMoving` | boolean | 实际是否运动，由后端判定 |
| `movementDirection` | string | `UP` 上行、`DOWN` 下行、`STOP` 停止 |
| `averageTension` | number 或 null | 后端计算的有效传感器平均拉力，t |
| `averageSpeed` | number 或 null | 后端计算的动力设备平均速度，m/min |
| `updatedAt` | string | 本快照采样或更新时间，带明确时区 |
| `winches` | array | 本系统四台动力设备及各自状态 |
| `sensors` | array | 八个传感器及各自状态、读数和配置 |

首页初始响应和每秒推送采用同名字段，避免同一概念同时出现 `tankCode`、`systemCode` 两种写法。建议推送也采用完整业务快照；该消息包装方式需与实际通道一起确认。

### 5.3 动力设备与传感器对象

| 动力设备字段 | 类型 | 说明 |
| --- | --- | --- |
| `winchCode` | string | 独立设备编号 |
| `winchName` | string | 完整显示名称，例如“动力一号设备” |
| `groupNo` | integer | 当前为 1 至 4，用于布局和关联 |
| `operatingStatus` | string | `IDLE`、`RUNNING`、`MAINTENANCE`、`FAULT`、`OFFLINE` |
| `statusText` | string | 后端提供的状态文字 |
| `direction` | string | `UP`、`DOWN`、`STOP` |

### 5.4 故障定位与交互

系统状态为 `FAULT` 时，后端仍需逐台返回真实设备状态，逐个返回真实测点状态。前端只高亮实际异常对象：

- 动力二号设备本体故障：动力二号设备标红；其他设备按各自返回状态显示。
- 钢绳1-2的传感器故障：该传感器显示红色和“传感器故障”；不能据此将整台动力设备自动标为本体故障。
- 后端因实际控制策略使其他设备待机：其他设备应明确返回 `IDLE`，前端再显示黄色待机，不能从系统故障自行推断。

最小定位依据为各对象编码、所属关系、最终状态和状态说明。若需要进一步说明系统故障来源，建议补充 `faultSources`，包含对象类型、设备/传感器编码和原因；该字段是对接建议，不代表已经存在。

取消首页设备故障/离线状态和异常测点到告警页的跳转。页面仍可保留正常的“查看详情”、选中设备、简短悬浮提示和独立告警菜单；提示仅显示后端数据。此修订不新增故障定位页面。

### 5.5 急停操作

前端保留“长按急停”和持续按住 3 秒的防误触交互。满足条件后提交：

```json
{"systemCode":"QJXT-01"}
```

若需区分命令阶段，建议回执补充 `commandCode`、`commandStatus` 和 `message`，并明确受理、下发、执行成功或失败的含义。具体命令状态枚举需后端确认，不用当前工况枚举中的旧 `EMERGENCY_STOP` 替代执行回执。

### 6.4 曲线与统计返回要求

沿用 `kind`、`units`、`series`、`heightMin`、`heightMax`、`heightLimits`、`dataRange`、`asOf`、`updatedAt` 等主结构。补充的总拉力及统计字段属于本次接口修订方案，前后端需同步实现。

| 对象 | 必需内容 |
| --- | --- |
| 分组 `units[]` | `id`、`name`、实际起止时间、`dataThrough`、`empty`；运行分组提供 `runState`，统计分组提供实际有效样本信息 |
| 曲线 `series[]` | `unitId`、`sourceRole`、`name`、来源编号、`unit`、排序后的 `points`，以及本曲线的最终统计 |
| 采样 `points[]` | `time`、`height`、`value`、`quality`；有速度和方向时提供 `speed`、`direction`；汇总点提供实际 `sampleCount` |
| 统计 `statistics` | 后端计算的 `averageTension`、`maxTension`、`minTension`、`validSampleCount`；没有有效样本时力值为 `null`，有效样本数为 0 |
| 取点对应关系 | 后端准备各来源可对照的采样标识；建议提供 `pointKey`，前端直接索引已有点，不自行配对计算 |

- 两根钢绳数据在时间、高度、方向、有效样本等条件下的匹配；不具备合计条件时总拉力返回 `null`。
- 各周期基于有效原始样本的统计与加权平均，不将周均、月均简单等权相加。
- 原始运行曲线保留真实先后顺序和回退过程；平均曲线按约定高度整理。
- 区分原始运行峰值、平均曲线最高点等不同口径，并返回对应结果。字段含义不能随前端显示名称随意变化。
- 伺服力值的实际采集或换算、质量处理；不能直接复用钢绳总和。

前端右侧表格直接展示后端统计；鼠标移到某点时展示该点已有数值与速度。前端不再调用加权均值、原始极值、两绳配对和总拉力计算函数生成业务结果。

### 7.5 历史导出

导出日期范围、记录总数、筛选和业务字段均以后端结果为准。推荐由后端生成 CSV，前端只选择范围、发起请求并下载，避免浏览器通过多次分页自行拼装不一致的历史快照。

| 输入 | 用途 |
| --- | --- |
| `systemCode` | 实际系统编号，用于数据范围和文件名称 |
| `exportType` | 建议 `RUN_LIST` 运行列表、`RUN_SAMPLES` 单次采样 |


前端保留默认/自定义选择、必填、格式与范围提醒。后端负责最终合法性、默认值来源、运行间隔与速度限制、保存、作用设备及实际下发。前端的校验不能代替后端校验。

读取和保存响应应返回已保存参数快照及明确的生效阶段。若当前仅平台保存成功，提示必须说明“参数已保存”；只有后端确认设备生效时，才可以提示“参数已生效”。需要区分阶段时建议增加 `applyStatus`、`message`，字段与枚举需后端确认。

预警值与安全保护值属于后端数据库配置，本次不额外增加前端阈值设置页面，也不把它们塞入这三项运行参数。

### 8.2 登录和用户管理

登录仍提交用户名和密码，后端处理真实认证、权限、令牌刷新与退出。前端负责表单和结果提醒。若刷新令牌轮换，后端返回完整新令牌，前端按约定保存，不自行解释权限或过期策略。

用户管理保持只读列表。前端提交关键词、`page`、`pageSize`，后端完成账号、姓名、角色搜索、排序和分页，返回 `list`、`total`、`page`、`pageSize`。角色显示名称建议同时由后端返回，不依赖前端猜测未知角色。

### 8.3 尚未开放的页面

模型管理维持待开放内容，历史巡检与数据分析维持“该功能正在开发”。本轮不增加模型上传、模型运算、巡检任务或新分析模块接口。没有页面需求的字段不列入本次必返清单。

## 九 统一响应与页面提醒

### 9.1 普通响应与字段规则

普通 JSON 接口沿用：

```json
{
  "code": 200,
  "message": "查询成功",
  "data": {}
}
```

| 规则 | 说明 |
| --- | --- |
| 业务结果 | 后端返回最终结果码及可读 `message`；前端展示，不编造业务失败原因 |
| 数值与单位 | 拉力基础单位 t，高度 m，速度 m/min；后端返回明确单位，前端可转换显示 |
| 时间 | 采用明确时区，例如 `2026-10-24T14:00:00+08:00`；统计日和截至时间由后端确定 |
| 空值 | 无有效值返回 `null`，数组无记录返回 `[]`；0只表示实际数值为0 |
| 状态一致性 | 编码、中文说明、读数质量和统计结果来自同一口径；前端不解决相互矛盾的业务字段 |
| 身份一致性 | 每个响应带有对应系统/设备身份；切换对象后不能混用旧对象响应 |
| 历史可追溯 | 参数、阈值、名称归属及业务结论采用事件发生时的实际记录 |

### 9.2 前端允许保留的简单提醒

| 场景 | 前端职责 | 示例文案 |
| --- | --- | --- |
| 输入为空或格式不对 | 提交前直接提示 | 请选择系统、请输入正确时间 |
| 请求进行中 | 显示加载状态 | 正在加载数据… |
| 请求业务失败 | 展示后端 `message` | 使用服务端实际返回说明 |
| 服务端未返回可读说明 | 使用简短兜底 | 请求失败，请重试 |
| 网络不可达或实时断开 | 提示连接问题 | 网络连接异常、数据连接中断 |
| 后端返回空结果 | 展示空态 | 所选范围暂无数据 |
| 后端返回预警或异常 | 展示状态与后端提示 | 拉力提示、拉力异常、传感器故障 |
| 参数或命令操作 | 按后端回执展示阶段 | 参数已保存、急停请求已受理 |

“请求失败”标红不理解为取消错误反馈。按本次要求，简单提醒仍属于前端职责；业务失败原因由后端返回，前端仅在缺少说明时兜底。

字体体系与整体深蓝界面沿用现有页面规范。本次明确增加待机黄色显示、保留具体故障对象红色标识；字体与颜色属于前端展示配置，不需要后端返回 CSS，也不用于反推业务状态。

## 十一 实施与验收清单

### 11.1 后端需要交付

- 提供按 `systemCode` 查询的真实系统配置、设备关系和名称。
- 首页初始快照与每秒实时消息采用同一字段语义，带实际更新时间。
- 返回包含待机的五种系统和设备工况、传感器最终状态及可定位对象。
- 读取数据库阈值并完成判断，前端无需再次比较阈值。
- 返回独立伺服、钢绳总拉力、统计、历史结论和实际比较周期。
- 详情必返设定速度，不再要求额定载荷与额定速度。
- 完成告警筛选、去重、结果说明、统计和分页。
- 返回真实日期索引、历史参数快照与稳定分页，明确导出实现。
- 返回参数保存/生效和急停受理/执行的真实阶段与提示。

### 11.2 前端需要调整

- 将系统含义的 `tankCode`、固定生产编号及重复状态字段改为统一契约。
- 使用后端名称，不按组号拼“动力一号设备”等业务名称。
- 首页接入每秒推送；详情取消周期刷新。
- 移除阈值比较、状态汇总、故障推断、两绳合计、业务统计及历史结果推断。
- 从后端返回的来源序列与统计中直接渲染右侧表格和曲线。
- 删除设备故障/离线和异常测点到告警页的跳转。
- 展示待机黄色和具体故障红色，保留正常设备与测点的各自状态。
- 按接口结果显示错误、空态、加载、保存与命令回执，不虚报设备已执行。

### 11.3 对照验收场景

| 场景 | 应看到的结果 |
| --- | --- |
| 查询 QJXT-01 | 请求、响应、推送和导出均归属同一系统，无 TANK-03 自动兜底 |
| 首页读数变化 | 后端每秒推送真实快照，前端按消息更新，不生成模拟变化 |
