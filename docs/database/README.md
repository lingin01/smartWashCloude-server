# 数据库基线与迁移

新版点位及完整业务口径见[统一方案](../unified-plc-business-and-data-plan.md)，字段/索引继续由下面的页面驱动设计补充；当前建表基线仍未变更。

2026-10-24页面职责修订见[前后端对接修订](../frontend-backend-contract-alignment.md)。目标设计已补充公共systemCode与内部身份映射、配置保存/生效版本、当次参数与告警触发阈值快照、后端总拉力和比较统计；页面t、数据库kg，各类缺失在新页面显式返回null。当前额定载荷/额定速度不再作为本次页面新增字段要求，此文不删除任何已有列。

告警中心复用目标`cleaning_exception_event`的明确告警事件，补类别/级别、定位对象和触发配置；归档与恢复分别记录，未恢复统计覆盖全部历史，不恢复旧通用`t_alarm`。目标仍为10业务表＋1导出技术表；所有新增列、公共编号唯一键及配置生效闭环仍待实施。

导出记录列表的`cleaning_export_task`仅为[导出方案](../data-export-plan.md)中的技术表设计：在10张目标业务表之外补充任务元数据，不存原始行或文件BLOB；当前7表基线没有增加该表。

页面字段对应的下一版目标表设计见[页面驱动的数据库设计](page-driven-database-design.md)。该文件仅为方案，没有变更下面的7表基线，也没有执行迁移。

唯一新库建表基线是 [schema.sql](../../src/main/resources/schema.sql)，在预先选定的目标库执行。包含t_user、三张PLC拓扑表、三张历史表；不包含凭据表、旧通用设备/告警表或尚无实现的业务表。IF NOT EXISTS不是升级机制。

旧库迁移使用 [migrate_legacy.sql](migrate_legacy.sql)。操作前备份并暂停应用写入，再在实际目标库手动执行。该脚本不是启动脚本，DDL不能依赖事务回滚。

脚本先检查所有待删除旧表和身份列冲突。只允许删除空的旧表；任何待删除表存在数据都会在清理DDL开始前失败，必须先独立归档。保留账号、拓扑和历史数据，将四张保留表中的旧身份列改成device_id。保留原有标识值，因此PLC配置id必须使用对应的device_id，不把通信地址当业务编号。

脚本可在已迁移库重跑，保留库中的扩展列，不自动压缩或清空历史。不支持把任意未知表结构强行转换成基线；发现两种身份列同时存在时拒绝操作。旧表/列名只为迁移识别出现在本文件所链接的脚本中，应用和新库不再使用。

当前DAO保存历史批次、分段和逐路测量；不会从实时缓存自动生成历史，历史保存开关也不会补齐轮次或采样整理。历史可靠恢复、内容冲突校验、曲线查询和保存年限属于后续工作。
