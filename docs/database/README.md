# 数据库基线与迁移

唯一新库建表基线是 [schema.sql](../../src/main/resources/schema.sql)，在预先选定的目标库执行。包含t_user、三张PLC拓扑表、三张历史表；不包含凭据表、旧通用设备/告警表或尚无实现的业务表。IF NOT EXISTS不是升级机制。

旧库迁移使用 [migrate_legacy.sql](migrate_legacy.sql)。操作前备份并暂停应用写入，再在实际目标库手动执行。该脚本不是启动脚本，DDL不能依赖事务回滚。

脚本先检查所有待删除旧表和身份列冲突。只允许删除空的旧表；任何待删除表存在数据都会在清理DDL开始前失败，必须先独立归档。保留账号、拓扑和历史数据，将四张保留表中的旧身份列改成device_id。保留原有标识值，因此PLC配置id必须使用对应的device_id，不把通信地址当业务编号。

脚本可在已迁移库重跑，保留库中的扩展列，不自动压缩或清空历史。不支持把任意未知表结构强行转换成基线；发现两种身份列同时存在时拒绝操作。旧表/列名只为迁移识别出现在本文件所链接的脚本中，应用和新库不再使用。

当前DAO保存历史批次、分段和逐路测量；不会从实时缓存自动生成历史，历史保存开关也不会补齐轮次或采样整理。历史可靠恢复、内容冲突校验、曲线查询和保存年限属于后续工作。
