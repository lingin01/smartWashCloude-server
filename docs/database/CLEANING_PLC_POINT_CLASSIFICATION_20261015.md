# 清洗系统 PLC 点位分类与数据说明

整理日期：2026-10-15。现场依据：[PLC 程序第二版本](D:/文件整理/桌面归档/正在处理项目/清洗/盒子/plc程序第二版本.docx)。适用项目：原 SmartWashCloud-Server 的 Modbus TCP 接入。

本文按系统信息、设备信息、数据点、故障四类整理。PLC 的 m/d 名称、点位含义和后端业务字段分开记录；本轮只整理说明，不修改运行配置、不启用读写、不改 PLC 或 Java 代码。

m/d 是 PLC 逻辑点位名称，不是已经确认的 Modbus 协议地址。下文所有点位仍需核对协议地址、区域／功能码、数据类型、占用字数、字节序、倍率、无效码和读写权限。单位栏不代表已经确认数据编码。

## 1 系统信息

### 1.1 系统状态与控制事实

| 内容 | 点位／来源 | 文档含义 | 后端用途及边界 |
|---|---|---|---|
| 控制电源 | m0 | 0 未上电；1 控制柜 24V 控制线路上电 | 单独保留控制电源事实；能读取 PLC 不等于控制电源已开启 |
| 故障或急停汇总 | m1 | 0 无故障急停；1 故障或急停 | 结合 m2 区分原因；不能直接当作普通运行异常 |
| 急停状态 | m2 | 0 未急停；1 按下急停 | 现有 emergency；急停展示故障。上行状态不等于下行急停指令地址 |
| 系统总故障 | m3 | 0 无故障；1 总故障 | 现有 fault；结合 d3 解释故障原因 |
| 允许运行 | m4 | 0 不允许运行；1 允许运行 | 操作许可事实，不是正在运行 |
| 复位 | m5 | 原表 0 栏写“复位”，1 栏为空 | 有效极性、是命令还是状态均待确认，不建立复位下行操作 |
| 中断停止 | m6 | 1 停止／中断；0 为“/” | 独立停止原因；不能等同 m2 急停，也不新增用户暂停功能 |
| 自动运行中 | m7 | 自动模式下，1 运行中；0 栏“/” | 现有 running；0 的静止／等待含义须与 PLC 核对 |
| 完整运行正常结束 | m8 | 正常启动后回到原位时置 1，持续 1 秒 | 轮次完成候选事件，不作为持续系统状态 |
| 下降正常到位 | m9 | 下降正常到位时置 1，持续 1 秒 | 下降终点事件；不是整轮完成 |
| 模式 | m10 | 0 自动；1 手动 | 现有 manualMode；按用户约定，手动展示检修 |
| 自动安全条件 | m11 | 0 自动不安全；1 自动安全 | 安全条件事实，不是故障码 |
| 手动安全条件 | m12 | 0 手动不安全；1 手动安全 | 手动／检修许可事实 |
| 自动模式已启动 | m13 | 自动下 0 未启动；1 已按启动；手动不适用 | 自动启动使能，区别于 m7 实际运行指示；不由服务器下发启动 |
| 同步提升方向 | m20 | 1 同步提升 | 现有 up，表示整体上行 |
| 同步下放方向 | m21 | 1 同步下放 | 现有 down，表示整体下行 |
| 运行过程异常 | m40 | 0 运行正常；1 运行异常 | 用于异常片段，不能直接等同最终故障；自恢复时仍可能保持正常运行 |
| 未定义状态 | m41 | 原表两值及备注均空 | 保留，不采集为某个已知业务状态 |

“0 栏为空／/”不自动解释为事件复位完成，也不直接推定某个状态极性。m7=0 用于待机分类前，应确认其有效含义；其他事实应相互核对而非凭一个 bit 猜整个流程。

### 1.2 用户看到的系统状态

| 展示状态 | 推荐业务判断口径 | 与其他字段的关系 |
|---|---|---|
| 离线 | 通信失败，无法取得有效系统状态 | 区分 communicationOnline 与 statusValid；电源 m0 不代替网络在线 |
| 故障 | 有效 m2 急停或 m3 最终总故障；d3 用于说明 | m1 用于核对；m40 单独异常不直接升级故障 |
| 检修 | 通信／状态有效，无上述故障，m10=1 | 现场手动检测，单机移动与不移动均是检修 |
| 运行 | 通信／状态有效，无故障，m10=0 且 m7 指示运行 | m13 自动已启动与 m7 运行分开保存 |
| 待机 | 通信／状态有效，无故障，m10=0 且 PLC 明确未运行 | 不等同离线，不凭速度 0 判定 |

优先级建议是离线／状态未知、故障、检修、运行、待机。这里是分类口径，不表示本轮修改了已有转换器。m0=0、m4=0、m6 中断应保留各自事实；在只有五种展示状态时，它们最终的中文解释需现场确认，不强行伪装成急停。

### 1.3 系统数据

| 系统数据 | 来源 | 后端字段／口径 | 注意事项 |
|---|---|---|---|
| 圆环整体高度 | 独立点位未给出 | ringHeightMeters，m | d80～d83 是四机高度；不能拿某一机或四机均高冒充明确圆环高度 |
| 四机平均高度 | d80～d83 | groupAverageHeight，m | 独立的派生参考值；不是新增 PLC 点位 |
| 四机高度差 | d80～d83 | heightSpread，m | 最大减最小，缺失通道不能冒充四机完整结果 |
| 八索平均拉力 | d40～d47；d52 为 PLC 已算均值 | groupAverageTension，业务 kg 命名 | 明确是八路平均。后端已有计算，d52 可作核对，避免混用两套有效样本范围 |
| 八索拉力合计 | d40～d47 后端求和 | 建议另设 totalTension，当前未新增 | 总拉力≠平均拉力；d52 不能作总拉力。完整合计须八路有效 |
| 同步整体速度 | d65 | groupSpeed，m/min | 与 d61～d64 的使用场景不同，不复制成四个单机实测速度 |
| 四机平均速度 | 仅 d61～d64 均明确有效时 | groupAverageSpeed，m/min | 单机和同步速度不同时有数据，自动作业时未必能取得这个均值 |
| 系统运动方向 | m20／m21 | UP／DOWN／STOP／UNKNOWN | 两位同时为 1 时不猜方向；单机方向另用 m22～m29 |
| 采集时间 | 服务端采集时钟 | sampledAt | 文档没有 PLC 时间戳点位，不宣称这是 PLC 内部时间 |
| 清洗轮次事实 | m8、m9、d10、d11 等 | 后续会话／轮次识别 | 单趟方向计数与一轮上下往返不同，不能直接换成轮次数 |

文档中 N 是拉力原始工程单位。现有业务字段使用 kg 名称，实际力的展示应明确“公斤力”的口径及现场换算；不把 N 原值直接改标签为 kg，也不把转矩 Nm 直接标成 kg。圆环自重不是八路平均值，索测量合计也不能不考虑机械工况直接拿来核对自重。

### 2.3 单台动力设备详情字段

| 详情内容 | 来源／计算 | 说明 |
|---|---|---|
| 编号、名称、位置 | 数据库档案 | 不把 d80 或 m30 当设备编号 |
| 状态 | 通信、m10、对应电机／编码器故障及本机运动事实 | 五种状态同系统；仅一台电机故障不能标四台都故障 |
| 本机运动方向 | 对应 m22～m29 | 当前 Java 转换器尚未映射这些单机方向，不能声称已实现 |
| 本机高度 | 对应 d80～d83 | cm→m；零点、精度和方向仍待确认 |
| 本机实测速度 | 对应 d61～d64 | 仅文档说明的单机运行场景；同步时的无数据不能当 0 |
| 本机两索平均拉力 | 两路拉力后端平均；d48～d51 可核对 | 两路均有效才是完整两索平均 |
| 本机两索合力 | 两路求和，后续另设字段 | 不等同两索平均，不能用平均值代表本机承载合力 |
| 两路传感器值 | 对应 d40～d47 | 与 sensorId／ropeId 一起保存有效性 |
| 转矩力 | 文档未提供点位 | 当前 winchTorque／torqueKg 仅为预留，不从拉力虚构转矩力 |
| 累积运行时间 | 没有明确单机累计点位 | d16 是本次自动运行时间，不能填成设备终身累计时间 |
| 两索预警／安全值 | 点位及配置来源未明确 | 单索阈值，不直接拿平均拉力替代；本轮不设演示数值 |

现有转换器在没有 winchRunning 时会借用系统运行事实，在本机方向上借用整体方向。由于 PLC 已给 m22～m29，后续应补单机方向映射／有效性，而不是把当前回退视作最终实现。系统故障、单机故障和各单机因系统联锁而停止是三个不同事实。

## 4 故障与异常

### 4.1 故障相关点位

| 点位／情况 | 作用域 | 文档含义 | 展示／记录方式 |
|---|---|---|---|
| m1 | 整个系统 | 故障或急停汇总 | 和 m2、m3 核对，不独立制造重复告警 |
| m2 | 整个系统 | 急停已触发 | 系统故障，原因明确为急停；不能推断是哪一台电机坏了 |
| m3＋d3 | 整个系统 | 总故障＋故障原因码 | 故障状态与中文说明，具体数字码表待提供 |
| m30／m31／m32／m33 | 绞机 1／2／3／4 的伺服电机 | 0 正常；1 异常 | 标记对应设备，不把四台都认定发生相同硬件故障 |
| m34／m35／m36／m37 | 编码器 1／2／3／4 | 0 正常；1 异常；异常不能自动，但可进入手动 | 标记对应编码器，保留 PLC 的模式许可事实 |
| m40 | 当前运行过程 | 出现运行异常 | 记录异常片段／恢复过程，不直接标最终故障 |
| m11=0／m12=0 | 自动／手动安全条件 | 不安全 | 保留原因待确认，不能当作已知 d3 故障码 |
| 读取失败 | 通信 | 后端无法取得有效状态 | 系统／设备离线；不是 PLC 自身产生的 d3 故障 |

m30～m33 仅是伺服电机状态，不能据其“正常”断定绳索一定正常。拉力异常、偏离 20%、恢复次数、第五次最终失败、单索预警／停机等具体原因或点位没有在这份文档中明确给出，不自行分配故障数字。

### 4.2 d3 故障码表需要补充的列

| 列 | 内容 |
|---|---|
| PLC 原始故障码 | 实际数字／位掩码；由 PLC 提供，不由后端猜 |
| 故障名称 | 对应真实原因 |
| 作用对象 | 系统、某绞机、编码器、某索／传感器 |
| 触发与恢复条件 | 何时出现、何时清除，是否锁存 |
| 故障级别 | 提示、预警、最终故障等实际分类 |
| 是否允许自恢复 | 由 PLC 控制策略说明，不由云端主动尝试运行 |
| 用户显示大类 | 对用户的稳定分类，不直接暴露全部技术错误 |
| 用户显示文本 | 统一消息目录提供，不散落在业务流程 |
| 技术记录 | 原始码、时间、对象、运行方向／高度、事件 ID |
| 是否可同时出现 | d3 是单一码、优先码还是位集合；若只保留最近码，不能当完整事件清单 |

文档写“另附故障码表”，当前附件正文并没有具体对应数字。故障码表不能用示例 1／2／3 冒充正式现场值。

## 5 记录数据与点位事件的边界

实时数据包含系统和单机状态、方向、高度、八索拉力、可用的单机／同步速度、预留转矩力及采集时间。实时最新值允许合并；历史事件不能只靠最新快照覆盖。

自动清洗的一轮是正常上下往返，不是 d10 的一个上行计数或 d11 的一个下行计数。m8 给正常回原位事件，m9 给下降到位事件；先与现场确认反向起始、异常恢复、中断及重启时的计数／脉冲行为，后续才形成可靠轮次。

正常上行历史按距上一个已留历史点累计 0.5m 留点，不按相邻轮询帧差判断。正常下行不做同密度留点；下降出现异常保存真实方向和位置，异常开始／结束额外保留。m40 是否持续表示整个异常区间、何时复位尚不明确，不能把一个瞬时脉冲强行变成异常持续时间。

m8／m9 只保持 1 秒，即使名义 500ms 采样，仍可能因网络重连、读取预算或实时快照合并而漏掉。后续应使用 PLC 计数增量或锁存／确认机制核对；现有实时通道不承诺无损捕获所有轮次事件。计数不能凭空恢复未读取到的历史拉力数据。

手动／检修移动单独作为检修操作记录，不混进自动轮次曲线。自恢复过程保留原轮次异常事实，不自动创建新轮次；最终失败必须有 PLC 明确事实，不能从 m40 推断已尝试五次。
