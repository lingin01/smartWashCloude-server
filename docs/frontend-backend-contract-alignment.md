## 2. 既有事实与本轮范围

一台PLC、四机八索、Modbus TCP直连；大厅与清洗、命令、安全、统计四个业务服务保持。新增页面对象是表示层的对接模型，清洗模块决定状态/记录/异常事实，统计模块准备统计与历史，门面委派内部辅助类，不另加第五业务服务。

继续保存所有已选UP用途的原始测量；正常DOWN仅实时，DOWN异常仅事件与有限快照。生产统计只取明确PRODUCTION_UP，恢复/检修UP留原始但不虚增生产次数。RUN仍为生产上行单程，不把它说成已经确认的完整清洗CYCLE。

采集数据**不做时间校验**：不按年龄、先后、与当前时钟偏差拒收或判断离线。updatedAt/asOf用于说明读数、查询和统计范围。两索合计的关联采用已确认采集帧、对象、方向、分段及有效性事实；不能把附件“时间、高度匹配”扩展成猜测时间容差、数据过期或按相同高度拼接不同过程。

M50写1仍是新版急停目标，协议配置待核实；写应答不等于现场停机，不保证M2响应关联。远程启动、复位、解除急停、暂停/恢复、单轴升降仍不开放。阈值判断移到后端，不表示新增后端自动保护下发、远程恢复或绕过PLC联锁。

## 3. 必须明确的衔接点

### 3.1 编号、五态和空值

systemCode从后端实际授权系统配置取得，不根据单机组号或固定TANK编号生成；QJXT-01只是合法配置示例。新页面请求不同时传另一套deviceId/system_id让客户端选择优先级。

正常业务态只有五种。无法确认状态时返回statusValid=false、状态字段null及说明，不用未知编码冒充IDLE/OFFLINE。isMoving与方向同样只能基于明确事实；D201=1并不能证明已经产生实际位移。单PLC不能证明四台独立链路分别离线。

有效读值与状态结论分别表达：阈值缺失时拉力可以有效，但没有证据的NORMAL/WARNING/ALARM结论不可编造。明确PLC故障仍照实展示；阈值null并说明未配置。共享急停导致本机FAULT需说明SYSTEM_EMERGENCY，不声称四台电机都损坏。

### 3.2 设定速度与系统高度

setSpeedMPerMinute是成功详情的必返有效数值，读取已确认生效版本/已确认现场配置。仅平台保存、仅PLC写应答或一条实际速度都不能证明“当前有效设定”。准备好前返回409 CONFIGURATION_NOT_READY及说明；不以0、默认10、额定速度或实际速度填成功详情。首页其他已知事实仍可单独展示。

systemHeight为真实系统配置高度，systemCurrentHeight为具有明确来源的系统当前高度；没有来源时显式null并说明。附件systemHeight标成number，不能据此捏造30m。四机均高不冒充独立环体高度，显示范围不当机械限位。

### 3.3 次数与时长

todayCompletedCount继续沿用已确定口径：**今日开始的生产上行记录中，已确认完成的数量**，countBasis=STARTED_DATE并返回中文说明。附件“今日实际完成次数”没有提供改为结束日的明确规则，本轮不悄悄改变跨日计数。完成日口径若将来需要，另列指标。

原始测量按采集日，事件按真实发生/首次观测日，可靠运动区间跨日拆分。记录历时不等于有效运动时长，四机工时合计不等于系统时长。未知工时返回null及覆盖说明，不让缺失部分被当作0。

“后端返回处理次数”不创造其数据来源；D3=50不能还原五次处理过程。页面需要该列时明确返回null、说明未提供逐次处理事实，异常事件数和告警数分别计算。

### 3.4 比较范围与有界查询

DAY视图返回今日、昨日、本月、本年；MONTH返回本月、上月、去年同期；YEAR返回本年、去年同期。去年同期采用与当前比较区间相同的日历位置及已明确截止，不再固定为去年全年。后端回传请求范围、实际覆盖、对齐方式、可比性和空态原因。

自然日期左闭右开；查询日期格式和起止关系检查是输入规则，不是校验采样时间。闰日或不等长月份按对应日历处理、明确实际边界；不按固定365天或固定30天偏移。无法形成相同统计边界/来源/粒度时返回不可比与null变化率，不拼接数组或填0补全年。已结束周期从预计算读取，必要边界切片未准备好时显示准备中，由后台补计算，不在页面请求里扫描全月/全年原始帧。

统一对比一次返回本批分组的四来源、右侧统计和取点关系。COUNT多次运行和单次四机大量采样仍分批/按范围读取，响应明确complete、总分组数、已加载数量、游标和粒度；“一次准备”不解释为一口气把数据库给前端。来源显隐只选择已返四来源，前端不重算总力或并集次数。

availableDates是本系统全历史可查询运行日期，独立于当前页和列表日期筛选，读取轻量日期目录。长年限按独立日期游标分批传输，响应明确未完整；不能把一页十条或当前筛选中的日期叫完整日期索引。

### 3.5 告警与导出

告警复用真实事件来源及必要配置快照。activeCount覆盖所有已触发而尚未确认恢复的告警，含恢复情况未确认项；不受历史日期窗口裁剪。归档、运行终止与告警恢复分别记录，不能相互替代。历史阈值/对象名称采用发生时版本，不用新配置改写旧触发。

独立异常通过同一alarm-dashboard接口的recordKind=EVENT、view=HISTORY分页查询，未关联RUN或isAlarm=false也能先查询列表再查看详情。默认ALARM列表和告警统计仍只计算真实告警，不为方便查询把所有事件变成告警。

附件GET history/export是建议新增，并未要求删除已有导出任务设计。本版沿用已确定的后台任务、导出记录列表、完整发布后下载，页面入口统一到/api/command-center/exports；不另造同步小导出和浏览器分页拼CSV两套路径。页面RUN_SAMPLES映射内部UP_SAMPLES，原始UP用途逐行保留，DOWN只导出事件点。

文件仍以实际执行时的一致快照生成，完整后才发布；页面systemCode和单位写入任务范围。文件不是数据库备份，也不因页面暂时隐藏来源而删除本次已存原始数据。
