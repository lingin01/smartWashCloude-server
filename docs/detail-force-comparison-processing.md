# 详情拉力对比图：数据范围、后端计算与页面对接

修订日期：2026-10-25。依据日期为2026-10-24的[项目总结与详情拉力对比说明原文](reference/detail-force-comparison-report-20261024.md)，补充[前后端职责对齐](frontend-backend-contract-alignment.md)、[页面接口契约](external-api-contract.md)和[数据库设计](database/page-driven-database-design.md)。本轮整理方案，没有修改Java、前端或数据库。

## 1. 先区分现状与目标

| 范围 | 已知情况 | 不能据此认定 |
|---|---|---|
| 新附件报告的前端 | systemCode、状态/详情字段和旧内容已清理；详情已取消5秒刷新 | 本仓库没有前端源码和测试运行记录，不将报告中的255项测试当作本轮验证 |
| 前端拉力对比 | 当前三个来源，仍在页面生成SUM/SENSOR_SUM、查同高度点、计算均值和极值 | 已经由真实后端计算四来源及统计 |
| 前端首页 | 生产分支首次HTTP快照；开发演示0.5秒运动效果 | 已接通后端每秒完整推送 |
| 前端告警/导出/参数 | 报告仍有页面过滤分页、浏览器CSV、三参数保存快照 | 后端筛选、导出任务或参数生效阶段已经完成 |
| 当前后端 | 实际接口见[当前接口参考](current-api-reference.md)，仍为deviceId及旧响应 | 新command-center路由、历史、预计算、四来源已经实施 |

附件中的源码路径是前端后续实施定位资料；本轮不尝试在这个Java仓库修改同名文件。原始模拟数据、截图及已报告测试结果只作前端对照依据。

本轮目标是使后端给出可直接展示的四来源、采样关联、统计、默认分组和缺失说明。前端保留选择、图例、单位/日期格式化、分页和加载提示，不配对、相加、求均值或判断运行结果。

## 2. 三个区域分别看什么

| 区域 | 数据范围 | 后端提供什么 |
|---|---|---|
| 左图“全部次数” | 当前查询范围内已加载的多个运行分组，叠加各组曲线 | units、series、分段、加载完整性及续读游标 |
| 右上“该高度实际数据” | 当前unitId中被命中的一个sampleKey | 同键四来源的value、speed、time、height、质量与缺失说明 |
| 右下“本次运行统计” | 当前unitId对应的完整逻辑曲线，包含尚未传输的点 | 各series.statistics及unit.ropeExtrema |
| 平均模式右上 | 当前统计周期的一个基础高度桶 | 桶范围、均值/平均速度、有效样本数；不是某一时刻现场帧 |
| 平均模式右下 | 当前周期完整基础高度桶集合 | 加权均值、最高/最低平均、数量和统计口径 |
| 页面顶部详情 | 本次主动查询得到的设备快照 | detail响应；不被下方历史光标改写 |

选中第9次运行时，右侧两表都属于第9次；左图显示20次不表示右侧是20次汇总。右下统计不受图例显隐、曲线分页或鼠标高度改变。两单绳整体极值也不会因只勾选一根绳而变成单根极值。

尚未悬停时，上表为空，右下使用后端defaultUnitId。COUNT默认先取具有明确依据的进行中记录，否则最近确认完成记录，再取实际存在的其他记录；排序采用真实边界及稳定记录编号，未确认边界仍如实标注。PERIOD优先本视图当前周期的非空组，再取其他非空组；全部为空返回null。后端必须让defaultUnitId属于首批实际返回的units，不能指向被省略或尚未加载的分组。重试游标不重选默认对象，用户明确选择后也不被后续加载覆盖。

“全部次数”仍分批加载，并显示已加载数/总数；附件固定20次是模拟规模，不改为生产接口无限返回。单次51点、回退601点同样不是PLC采集固定配额。

## 3. 本轮采用的字段与结构

沿用`GET /api/command-center/winch/tension/trend`，Query仍为systemCode、winchCode、viewType=FORCE_COMPARISON、comparisonView=COUNT/DAY/MONTH/YEAR，另有既定的曲线预算与游标。不另加“总力接口”和“右表统计接口”。

| 位置 | 本轮确定的目标 | 与上版/附件的衔接 |
|---|---|---|
| data.defaultUnitId | string或null | 后端决定首屏默认分组并保证在本批中 |
| units[].includedRunCount | integer或null | 四来源参与曲线的去重运行并集，替代上版recordCount；不是平均权重 |
| units[].sourceIncludedRunCounts | 四来源数量对象 | 各来源各自的去重运行数，替代sourceRecordCounts，不可相加当并集 |
| units[].ropeExtrema | maxTension、minTension、metricBasis、unit、message | 只含两单绳集合，不含ROPE_TOTAL和SERVO |
| series[].sourceRole | SENSOR1/SENSOR2/ROPE_TOTAL/SERVO | SUM/SENSOR_SUM不再作为正式页面来源枚举 |
| series[].statistics | 当前分组完整逻辑曲线统计 | 供右下直接展示，具体口径见第5节 |
| series[].rawStatistics | 当前分组完整生产原始测量统计 | 单独保留瞬时极值及无高度有效测量，不由平均曲线推算 |
| segments[].points[].sampleKey | 后端生成的不透明关联键 | 取代尚未实施的pointKey，页面协议只维护一套键 |
| points[].sampleFrameId | 真实采集帧标识或null | 与sampleKey不同：平均桶没有真实帧 |
| data.pointReadings[] | unitId、winchCode、sampleKey及各来源读数 | 保留集合名称，内部改用sampleKey；展示索引不重新配对 |

已明确的结构继续使用`series[].segments[].points`，保留换向/回退/缺口；不照搬附件示例的平铺points而丢段。分组范围仍用startTime/endTimeExclusive、dataFrom/dataThrough，时刻带时区、范围右开。runState仍为IN_PROGRESS/ENDED/UNCONFIRMED，runResult另列，不能用RUNNING/COMPLETED两值掩盖终止或未知结果。

只有目标文档更名，当前Java内部ID、已存事实和原参考文件不改。前端需要同步类型/消费代码；改完文档不意味着现有页面可以立即读到这些字段。

## 4. 同一采样怎样关联，哪些值可以参与

原始sampleKey由后端依据真实采集实例/帧、本机、分段及已确认采集关联生成，不用“高度＋格式化时间”拼唯一键。相同高度多次经过必须不同键；只有具备共同关联证据的来源才共享一个键。不同采集实例、其他运行或不同时刻的数据不能为了补表格凑在一起。

PERIOD的sampleKey由周期、本机、基础高度桶规则版本和桶位置确定，只表示相同统计区间，time与sampleFrameId为null。四来源可以有不同有效数量；共享桶键不代表四条均值用了相同原始样本，ROPE_TOTAL仍单独聚合配对样本。

前端只建立unitId/winchCode/sourceRole/sampleKey索引。右表和图表标记共同使用命中键；无对应值显示null与原因，不按最近时间、唯一同高度点或插值补齐。精确点查询提交recordCode及sampleKey，后端解析真实帧；不对平均桶请求伪造原始点。

| 数据情况 | 统一处理 |
|---|---|
| 有限数值0且通道确认有效 | 是有效样本，正常保留，不以0代表缺失 |
| GOOD或PARTIAL | 仍须有本通道数值有效依据；PARTIAL不是所有通道都有效的通行证 |
| INVALID/OFFLINE、明确缺失或非有限值 | 不参加该来源数值统计；返回null和实际质量原因 |
| 有效原始点 | sampleCount=1；不能因为字段没传就由前端默认1 |
| 无效原始点 | sampleCount=0、value=null，可保留断点位置和真实原因 |
| 平均桶 | sampleCount为实际有效样本数；0时value=null，未构建则状态NOT_BUILT、数量null |
| 缺高度但拉力有效 | 保存在原始历史并参加rawStatistics；不造高度，不参加高度曲线statistics |
| 已确认异常但读值仍有效 | 峰值仍保留；故障结论本身不等于测量无效 |

这些是通道有效性与集合归属规则，不是采集时间检查。不比较采样年龄、时钟偏差或相邻时间先后来拒收、丢弃或判离线。采样序号负责过程顺序，时间保留用于显示与日历归属。

## 5. 后端具体计算什么

### 5.1 两索总拉力与速度

先在真实同帧、本机、分段/用途及有效性证据下配对，再计算`total=rope1+rope2`。不匹配时总力null，但不删除各自有效的单绳值。均值和极值从这组实际合计样本计算，不能把两根绳各自的最大值相加，也不能相加不同样本集合的独立均值。

ROPE_TOTAL速度使用该配对观测对应的、已确认适用的本机运动速度，不能将两路速度相加，也不能默认复制钢绳1。无法明确适用来源则速度null；力值有效并不要求速度也有效。周期平均速度仅合并配对集合中有独立速度依据的speed_sum/speed_valid_count，不拿拉力样本数当速度分母。独立伺服始终来自D70～D73及已确认换算，不能用总拉力代替。

### 5.2 右下statistics、原始rawStatistics与两索ropeExtrema

| 对象/模式 | 平均值 | 最大/最小 | 数量与范围 |
|---|---|---|---|
| COUNT statistics，metricBasis=RAW_CURVE_SAMPLES | 完整可画曲线有效原始值的和/数量 | 该完整原始曲线集合瞬时极值 | validSampleCount为真实有效点数，不是本响应点数 |
| PERIOD statistics，metricBasis=HEIGHT_BUCKET_MEANS | 完整基础高度桶的sum合计/count合计 | 所有非空基础桶均值的最高/最低 | validSampleCount为桶内真实有效采样数之和，bucketCount为非空基础桶数 |
| rawStatistics，metricBasis=RAW_VALID_SAMPLES | 该分组有效生产原始值的和/数量 | 同一集合原始瞬时极值 | 包含有效但缺高度的值，scope明确，不混回退/检修 |
| unit.ropeExtrema | 不提供混合平均值 | COUNT取两单绳完整曲线原始集合；PERIOD取两单绳完整基础桶均值集合的极值 | 同步返回metricBasis与说明；不含总力和伺服 |

statistics中averageTension、maxTension、minTension均为t。PERIOD的maxTension/minTension按新附件表示最高/最低平均，metricBasis固定为HEIGHT_BUCKET_MEANS；原瞬时极值移至rawStatistics，取消上版同时混列maxAverageTension/minAverageTension的结构。这是一项明确的目标契约修订，不能仅换界面标签而保留旧字段解释。

空且已经完成计算的集合，数量0、力值null；统计尚未准备好时返回NOT_BUILT/UPDATING与说明，未知数量null。不能让“没有计算”和“确认没有样本”都显示0。

周期总力先对生产原始样本求合计再进入高度桶。独立来源统计用各自有效集合，不强求四来源样本数相同。参与运行数独立去重，不能作有效样本权重；跨日同一次运行不能相加成两次。

### 5.3 统计与显示分辨率分开

右侧统计由完整逻辑集合计算，不从传给浏览器的500点、当前5个分组或前端已加载数组重算。COUNT统计可读持久运行/设备摘要；PERIOD使用固定heightRuleVersion的基础高度桶与预计算结果。基础桶宽度仍以实际确认配置为准，不根据模拟图猜精度。

图形为预算合并桶或保留峰值抽点时，响应标明aggregation和实际显示粒度；右下统计仍使用完整基础桶。缩放、maxPointsPerSeries、分页和图例不能悄悄改变最高/最低平均。图上粗粒度极点与基础桶统计可能不同，返回metricBasis、heightRuleVersion、scope与说明供页面正确标注。

数据库继续保留原始sum/count/min/max及各自速度统计；COUNT可画集合的摘要与全有效测量摘要分开。已经结束月份预计算保存，查询合并少量摘要/基础桶，不每次重扫原始全月。具体字段见[数据库设计](database/page-driven-database-design.md)，不为两个右侧表另建一套业务历史。

## 6. 新附件模拟数据怎样使用

附件第9次运行给出的22.5m采样仅作前端对照：

| 来源 | 附件原值t | 当前演示显示t | 速度m/min |
|---|---|---|---|
| SENSOR1 | 0.640 | 0.64 | 10 |
| SENSOR2 | 0.568 | 0.57 | 10 |
| ROPE_TOTAL | 1.208 | 1.21 | 10 |
| SERVO | 1.199 | 1.20 | 10 |

原值相加是0.640＋0.568＝1.208，不相加格式化后的字符串。附件两单绳整体0.660/0.372与总力1.230/0.760是不同集合的极值。单独舍入后的均值也不可相加回推总力均值。

这些数字来自用户提供的报告，本轮未重新运行其模拟生成器。报告明确模拟平均含上行、下行及回退；后端正式默认统计仍只纳入PRODUCTION_UP，不能为复现截图而保存正常DOWN或把恢复/检修计入生产。模拟51/601点、每天20次、205天及0～30m坐标不是现场能力、保留年限或机械限位。

模拟迁移可用原完整数据验证“计算搬到DEV响应后效果相同”；正式接入另用用途明确的UP数据验证生产口径，两者分别验收，不承诺正式统计与混合方向的模拟均值相同。图表显示范围与真实heightLimits继续分开。

后端按存储精度计算，在页面边界kg转t，不提前保留两位。前端最后格式化；报告中JavaScript对0.575显示0.57属于现有演示行为，不能据此改数据库值。实施前用相同原数值核对当前格式化与导出规则；本轮不默默替换舍入算法来追求截图一致。

## 7. 服务流程、实施范围与验收

```text
用户主动查询 → 表示层/大厅 → 安全服务 → 清洗服务编排
  → 统计服务查询运行、UP摘要、基础高度桶
  → 统计模块内部关联/合计/统计辅助类
  → 页面组装：默认分组、四来源、sampleKey、两种统计、缺失说明
  → 前端按分组与键展示，不再做业务计算
```

清洗模块仍唯一维护系统、运行和事件事实；统计模块不自行改运行结果。命令状态仍归命令服务，设备管理/DAO仅提供身份、配置和读写，不回调上层。不增加第五个业务服务，也不把所有算法塞进门面。

实施先对齐类型与完整示例，再完成真实数据保存/预计算及后端查询，前端逐处改为消费结果。附件提及的共享matchingPoint等函数需核对其他历史页面调用，不能在本仓库凭路径直接删除前端工具。每秒首页推送、后台导出、告警过滤分页和参数生效闭环继续按既定独立方案实施，不能因本次图表字段整理而标成完成。

验收关注：

1. 四来源、右表和图表标记共用sampleKey；同高度不同经过、缺点及无效通道不串样。
2. defaultUnitId一定在首批，空态为null；全部次数的左图与当前unit的右表范围分明。
3. 单绳整体、总力、伺服、平均桶极值、原始瞬时峰值各自正确；无高度有效值只进入对应原始统计。
4. 配对缺失、速度无依据、有效0、零样本及未构建均能区分，不以样本数量猜运行次数。
5. 分页、降采样、图例和单位切换不改变完整分组统计；历史月份读取预计算，响应有界。
6. 正式生产统计不纳入正常DOWN、恢复/检修用途；采集时间不作拒收或离线条件。
7. 当前前端报告、后端真实实现和目标接口分别注明，只有实际联调后才称迁移完成。
