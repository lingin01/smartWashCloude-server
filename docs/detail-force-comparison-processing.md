## 1. 当前两个页面分别显示什么

| 项目 | 系统单次运行详情 | 动力设备详情 |
|---|---|---|
| 对象 | 一次系统记录，四台设备可选 | 一台设备，多次运行或多个周期 |
| 接口 | history/detail | winch/detail及winch/tension/trend |
| 来源选择 | ROPE1、ROPE2、SERVO；四台最多12条，无总拉力按钮 | SENSOR1、SENSOR2、SERVO、SUM；目标SUM消费后端ROPE_TOTAL |
| 默认展示 | 动力一号、钢绳1号、吨 | COUNT、首个运行分组、SENSOR1、吨 |
| 右侧表 | 当前所选曲线的高度、拉力、速度逐点表 | 当前分组曲线的逐点表；PERIOD为平均拉力、平均速度 |
| 图表联动 | 附件报告已支持命中曲线后切换右表；未做定位某行、自动滚动或行反向定位 | 附件报告通过右侧下拉选曲线，未绑定与历史页相同的联动 |
| 导出按钮 | 导出本次实际保存的系统采样，不随当前图例缩小范围 | 当前无本次导出按钮 |

**两个页面的旧“右上四来源单点表＋右下均值/极值表”都已删除。** 右侧现在是一条曲线的逐点表，不是悬停点四来源列表，也不是本次均值和极值汇总。新截图不能继续套用旧“第9次、22.5m、1.21t”的说明。

历史页顶部entry仍显示本次结果、参数快照和单绳极值；动力页顶部仍是当前设备查询快照。鼠标取历史点不改写顶部当前高度、当前拉力或当次参数。

上述现状来自附件，本仓库未独立运行其前端源码、300项测试或9项浏览器模拟检查。报告中的演示成功不证明真实PLC采集、后端接口与落库已经完成。

## 2. 当前前端处理与后端目标

| 环节 | 附件报告现状 | 本轮目标 |
|---|---|---|
| 历史图 | 三来源，不生成两绳总力或四机平均；仍按时间、方向、质量整理 | 后端明确来源、绳号、过程顺序、用途及质量，页面按返回顺序显示 |
| 动力图SUM | 浏览器按height/time/direction/sampleCount配对相加，速度沿用第一来源 | 后端提供ROPE_TOTAL，页面只选择已返回来源，不重新配对或求和 |
| 平均曲线 | DEV生成高度平均；生产请求直接取接口 | 后端读取已预计算的基础高度桶及实际有效数量，不用模拟公式替代 |
| 悬停关联 | 当前按高度及最近时间联动，尚无统一sampleKey | 后端提供稳定sampleKey，重复高度不串样，不拿邻近时间补缺值 |
| 右侧统计对象 | 新布局不再展示旧均值/极值双表 | 不强制返回statistics、rawStatistics、ropeExtrema、defaultUnitId |
| 概况/报表 | entry极值、运行结果和归档summary仍有用途 | 保留后台摘要与统计能力，后端直接返回实际结论及中文说明 |

去掉旧右表契约不等于删除数据库sum/count/min/max、周期预计算或历史极值。是否另返统计对象应由真实调用需求决定；本次最小图表响应不携带一套未展示的旧表字段。

PLC负责判断普通/严重错误和拉力状态；后端整理信号、事件与采样统计，不比较每笔拉力和阈值自行新增故障。阈值修改及PENDING/APPLIED流程见[PLC事件与阈值方案](plc-alarm-and-threshold-processing.md)。

## 3. 两个查询需要的最小数据

### 系统单次详情

`GET /api/command-center/history/detail`必传systemCode、recordCode。现有前端yearGrouping=MONTH仅作为兼容参数接收，不把RUN改成月统计。目标补resolution、cursor及响应预算，按下一节分批返回。

| 返回对象 | 核心内容 |
|---|---|
| entry | 稳定记录编号、真实/观测边界、运行结果与中文、当次参数、异常次数、全系统单绳极值及完整性 |
| sensors | 八路单绳；每路明确id/name、winchCode、groupNo、ropeNo=1/2、实际sensorCode，不从S1后缀猜归属 |
| servos | 四路独立伺服；实际设备与来源关系，不用两索之和代替 |
| 曲线分段 | segments及其points，保留换向、回退、缺口和采集次序；页面需适配分段展示 |
| 范围与读取状态 | heightMin/heightMax、真实heightLimits、asOf、resolution、complete、nextCursor、实际粒度与覆盖说明 |

历史图不要求ropeTotals、四机合计、四机平均、默认分组或整套旧统计双表数据。ROPE1/ROPE2是历史页面选择角色，映射到每台ropeNo=1/2；不能直接把它们当作全系统某一个固定传感器ID。

### 单机多次/多周期趋势

`GET /api/command-center/winch/tension/trend`传systemCode、winchCode、viewType=FORCE_COMPARISON、comparisonView=COUNT/DAY/MONTH/YEAR，以及resolution/cursor/预算。COUNT为BATCH，DAY/MONTH/YEAR为PERIOD。

units提供id/name、真实范围、rangeLabel、dataThrough、empty及原因；series明确unitId、sourceRole、实际来源关系、单位及分段。目标来源为SENSOR1/SENSOR2/ROPE_TOTAL/SERVO，当前前端SUM/SENSOR_SUM选择值需适配。单位仍t、m、m/min。

图表runState目标为RUNNING/COMPLETED/null，只表达进行中/已结束/无法确认；COMPLETED不能证明成功完成。独立recordState保留IN_PROGRESS/ENDED/UNCONFIRMED，entry.runResult及中文结论另列。不得因图表分组“已结束”把故障终止改成成功，也不把未知状态补成COMPLETED。

首次按明确稳定顺序选择首个已返回分组，后续游标不覆盖用户选择，不新增强制defaultUnitId。includedRunCount表示参与运行去重数，点sampleCount表示有效采样数，两者不混用。

## 4. 逐点表完整，但每次响应有界

两个图表查询都复用自己的接口，使用`resolution=OVERVIEW|RAW`区分读取目的，不为每个表格行另开接口：

| resolution | 返回含义 | 页面如何表达 |
|---|---|---|
| OVERVIEW | 为图形预算抽取/合并的概览，保留峰值和缺口，明确aggregation | 可先画概览，不能称右表已经包含全部原始采样 |
| RAW，COUNT/RUN | 分批返回请求记录/来源范围内实际保存的原始点，不降采样 | cursor继续，最后complete=true才可称该范围已完整加载 |
| RAW，PERIOD | 分批读取所选周期完整基础高度桶 | 是完整平均点表，不能把统计桶说成现场原始帧 |

接口返回本批范围、已加载数量、完整性及nextCursor；没有可靠总数时不报假总量。“完整”限定于本次明确范围与实际已存数据，不保证设备从未漏采。概览与RAW使用相同身份及分段规则，统计桶另列实际粒度和规则版本。

前端可按滚动/继续加载追加同一曲线数据；尚未完成时明确“已加载部分”，不能静默截断。完整导出仍走后台任务与一致快照，不能用已加载500点代替本次全部历史，也不能为右表一次把多年数据库返回浏览器。

## 5. 点序、质量、配对与速度

原始点建议包含sampleKey、sampleFrameId、采集序号、time、height、value、speed、direction、motionRole、通道质量和缺失说明。后端按采集实例/序号和连续段给出稳定过程顺序，不因相同高度而去重，不用高度排序覆盖上行/回退的真实经过。

sampleKey是不透明关联键，依据真实帧、本机和分段生成；相同高度的不同经过必须不同键。只有具备共同采集关联的来源才共享键，缺失同键值返回null，不按最近时间拼表。PERIOD键对应周期、设备、基础桶与规则/计算版本，time和sampleFrameId为null，不伪造真实采样时刻。

有效0正常保留；缺失、INVALID/OFFLINE或非有限力值返回null并断线。GOOD/PARTIAL仍须有本通道有效依据。拉力和速度分别表达有效性，拉力缺失不自动清掉有效速度；原始点有效sampleCount=1、无效=0，平均桶为真实有效数量，未知不按1补权重。高度缺失的有效拉力仍入原始历史和概要极值，不造高度点。

动力ROPE_TOTAL先按已确认同帧、本机、方向/用途及通道有效性配对，再对原值求和。缺一索或无法配对时总力null，单索有效值仍保留。总力速度使用该帧已确认适用本机速度，不能相加两索速度或默认抄第一来源。独立伺服始终使用真实独立反馈。

平均总力先逐点合计后聚合共同有效样本；不相加不同集合的单绳均值。高度平均保存sum/count/min/max，速度用自己的有效和/数量，历史月份提前计算。吨/公斤和小数位最后格式化，显示坐标0～30m、1.4t/3t不是限位或保护阈值。

**采集时间不作校验。** 不因时间早晚、年龄、时钟偏差或补入延迟拒收、丢弃或判离线；排序和去重使用稳定采集身份，时间用于实际记录与日历查询。图形插值不当作现场采样，缺口不能连接成连续实线。

## 6. 正式保存范围和概况极值

新附件明确当前前端RUN图能显示UP/DOWN及回退，DEV还有完整下降轨迹；这是前端现状。用户此前确定的正式保存范围继续为：所有已选UP用途保存原始，生产统计只取PRODUCTION_UP，正常DOWN只实时展示，DOWN异常仅事件及有限快照。本文不把演示下降曲线转成正常DOWN连续入库要求。

所以正式接口只能提供实际保存的UP段与明确标注的异常事件点，不能声称具有完整下降原始曲线。恢复/检修UP可按用途查看，默认生产均值不纳入；未确认用途不补造。事件峰值统计与保存方式见事件方案，不靠补造正常下降曲线实现。

entry.maxTension/minTension是本次生产UP记录内全系统八条单绳的有效原始采样极值：取一个最大值和一个最小值，不相加八路，不含伺服/双绳合计，不随所选动力设备或图例改变。缺通道和观测缺口要说明覆盖范围；不能把当前图上最高点当全系统历史极值。四台同步仍是一条系统运行记录。

旧附件第9次、51/601点、每天20次及固定演示日期只作旧演示回归参考，不作为新截图身份、PLC采样配额或生产统计等值承诺。当前附件虽称“一轮”，正式RUN仍按既定生产上行单程解释，完整往返边界未确认时不擅自合并。

## 7. 实施和核对顺序

1. 对齐两种详情DTO、三/四来源、绳号关系、runState与最终结果映射，再按Controller清单补接口。
2. 清洗模块维护真实运行/事件事实，统计模块查询原始、摘要和基础桶并准备派生总力；设备管理/DAO不回调上层，不增加第五个业务服务。
3. 前端消费后端顺序、sampleKey和ROPE_TOTAL，移走生产配对计算；保留来源选择、表格索引、单位格式化和加载提示。
4. 验证重复高度不串样、无效点断线、有效0、独立速度、分批完整性、全系统八索极值、异常点与正常DOWN未归档的区别。
5. 验证新图没有旧统计双表强制依赖；阈值编辑不重算告警；演示测试、接口联调、PLC真实生效分别记录，不提前宣称完成。
