# 实时数据、上行历史、运行详情与高度平均曲线方案

日期：2026-10-23。本文仅为设计文档，不表示代码、数据库表或接口已经实现。

依据：用户上传的《前端页面与后端数据字段对接说明》v1.0、已提供的PLC点位表，以及当前后端代码。本文中的“上行/下行”均指设备提升/下降方向，不指网络上传/下发。

本轮确定的规则优先于附件中的旧设计：**正常上行持续保存核心采样；正常下行只做实时展示，不保存连续测量；下行发生异常时保存事件点及必要快照。** 继续保留大厅与清洗、命令、安全、统计四个业务服务，不增加数据过期判断。

## 1. 先统一实时、历史、详情和统计的含义

| 数据/页面 | 表达什么 | 数据来源 | 是否长期保存 |
|---|---|---|---|
| 首页实时数据 | 此刻系统、四台动力设备、八路钢绳的状态和测量 | 清洗服务的最新业务快照，SSE推送 | 最新快照本身不反复入库；上行/异常按归档规则另存 |
| 单机实时详情 | 本机当前高度、速度、两索及电机等效力，附本机历史摘要 | 最新快照＋配置＋已保存运行/统计 | 配置与历史各自保存，不把整个页面对象当一条采样 |
| 上行历史列表 | 每次业务上行的起止、结果、次数与摘要 | 上行运行记录 | 保存，分页查询，不携带曲线数组 |
| 单次历史详情 | 列表中某一次上行的事实、参数、采样、异常 | 同一个记录编号关联的数据 | 保存；按概要、曲线、事件分别加载 |
| 下行异常历史 | 下降过程中实际发生过什么异常 | 异常事件与触发/恢复/终止快照 | 保存；不创建假的上行记录 |
| 日/月等统计 | 一个自然周期内的运行数量、时长及测量摘要 | 后台预计算结果 | 保存，可因补传而修正 |
| 高度平均曲线 | 某周期、某设备、某来源在相同高度区间的平均拉力 | 上行有效采样形成的高度统计 | 提前计算保存，不在浏览器扫描历史 |

**实时能显示下行，不等于历史能回放正常下行。** 按本次取舍，正常下行以后不能提供完整曲线、完整过程导出或由采样推导的全程极值。

## 2. 附件与前期方案中需要调整的内容

| 附件/前期方案内容 | 本版处理 |
|---|---|
| `Cloud`、`boxId`、盒子身份链和`/api/cloud/cleaning/boxes/...` | 不恢复。当前是PLC直连，使用`deviceId`及现有路由前缀 |
| 旧`CleaningRun`、`CleaningCycle`等源码索引 | 不能当作当前实现；相应旧类型已清理，不据此设计调用链 |
| 附件区分LEG、CYCLE，演示RUN按LEG解释 | 延续区分；本版建议现阶段RUN页面使用上行单程，不宣称其等于完整清洗轮次 |
| 完整轮次固定先下降再上升 | 不采用；原位和先后顺序没有这样固定，不推算完整次数 |
| 上/下行平均、全部方向平均 | 本次历史曲线和测量统计固定`directionScope=UP`，不提供完整下行/全方向平均 |
| 前一版后端方案中的时间桶曲线 | 附件主图横轴是高度，必须增加按本机高度分组的统计；时间桶不能替代高度桶 |
| 正常下行原始采样导出 | 不支持。导出上行原始采样和单列的下行异常事件快照 |
| “同一次异常五次处理”的逐次明细 | 无已确认来源的不生成`attemptCount`、逐次结果；D3=50保留实际故障含义，不补出五条处理记录 |
| 定时/人工启动、最近维护、阈值、机械限位、进度 | 有实际来源才返回；自动模式不等于定时启动，0～30m绘图区不等于限位，不能用`height/30`伪造进度 |
| 摄像头和播放会话 | 属于独立页面能力，本版不纳入PLC采样历史，不创建相应实现 |

附件仍可作为页面字段参考，但不能把“规范扩展”、演示记录和旧源码描述解释为当前后端已支持的功能。

## 3. 身份和“一次运行”的口径

### 3.1 身份关系

使用明确配置的关系：系统 → PLC设备`deviceId` → 四台`winchId` → 每台两根`ropeId`及对应`sensorId`。

- `QJXT-01`作为附件中的系统显示编号参考，通过配置取得；不是四台动力设备共有的内部主键。
- 页面`systemCode/tankCode`映射到实际系统，`winchCode`映射到`winchId`，不按数组下标或编号末尾猜测设备身份。
- `recordCode`与本版上行记录`recordId`一一对应。列表、详情、事件关联和导出都使用这个标识。
- `sampleFrameId`定位一次采集帧，`sampleId/sequence`定位记录中的采样。运行序号不是采样序号，也不是完整清洗次数。

### 3.2 本版记录单位

为贴合附件现有RUN页面按LEG解释的口径，本版建议现阶段一条生产运行记录表示一次已经识别的业务上行过程，`recordScope=LEG`、`directionScope=UP`。系统同步上行生成一条系统记录，四台动力设备在这条记录下分别保存测量与统计，不生成四次系统运行。

“只保存上行采样”本身不意味着完整清洗的业务定义改变。以后若展示完整往返，必须明确使用CYCLE及已确认的实际周期边界；其测量仍可只保存UP、下行只保留异常。本版不新增未确认的完整周期识别，也不把上行单程次数改名为完整清洗次数。

换向、恢复动作应以实际业务关联区分。异常回退中的短暂提升不自动增加一次生产上行；检修提升与生产提升分开标识、统计。实际方向明确为UP的测量按上行规则留存，未识别业务归属的采样不强行挂到最近一条记录。

本方案不编写尚未确认的上行开始/到位点位组合。M8是正常回原位信息，不是所有上行都适用的专用完成信号；M9是下降到位，不作为上行完成。D10保留其上行完成计数含义，但不能仅凭一个计数补造每条记录的起止和曲线。边界不能确认时，保留实际数据并标记记录未确认，不按高度、速度或理论时长推断完成。

## 4. 上行保存、下行只记异常，具体保存边界

| 实际情况 | 实时显示 | 长期保存 | 纳入上行平均 |
|---|---|---|---|
| 生产上行 | 全部有效实时值 | 上行采样、记录变更、异常事件 | 有效且符合统计范围的通道参与 |
| 正常下行 | 全部有效实时值 | 不保存连续采样，不生成正常下行运行记录 | 否 |
| 下行异常发生 | 显示当前异常和测量 | 一条异常事件及发生时快照 | 否 |
| 同一异常持续 | 持续显示 | 不每帧新增事件；关键变化更新同一事件 | 否 |
| 下行异常恢复/终止 | 显示实际结果 | 补充恢复/终止事实和当时可取得的必要快照 | 否 |
| 检修或回退提升 | 显示实际方向和测量 | 上行采样带实际用途/模式，不冒充新生产运行 | 默认不混入生产上行平均 |
| 方向未确认 | 保留未知显示 | 记录异常或缺失事实，不假定UP来生成完整历史 | 否 |

下行异常快照至少说明：事件编号、设备、实际发生/观测时间、DOWN方向、故障/急停原因，以及当时相关设备的高度、速度、两索拉力、电机等效力和有效性。有需要时保留同帧相关设备读数用于解释不平衡。

事件点不是一段正常下行曲线；默认不保存事件前后持续采样窗口。事件快照中“当时最大值”也不能标成整个下行过程的真实峰值。

下行事件只有在明确属于某个业务记录时才建立关联。不能按“离上一条上行最近”随意绑定，更不能让上行结束后的独立下行异常改写那条上行的完成结果。系统历史需要提供独立的异常事件入口，避免没有关联运行编号的下行事件无法查看。

四台方向不一致时按本机实际方向选择历史通道：某台提升的数据不能因整体方向是DOWN而遗漏；其他正在正常下降的通道也不因此被连续归档。未归档通道与测量无效通道分别说明，不能填0。

## 5. 实时数据和单机实时详情

当前真实接口是：

- `GET /api/cleaning/devices/{deviceId}/realtime`
- `GET /api/cleaning/devices/{deviceId}/realtime/stream`，SSE。

当前响应有外层`Result.data`和内层实时对象`data`。页面适配不能取错层级，也不能继续请求附件中的旧盒子地址。历史和单机详情属于待设计查询，不因附件列出路径就已经存在。

| 页面字段/内容 | 来源或当前字段 | 本版规则 |
|---|---|---|
| 通信、快照可用性 | `available`、`data.status.online/statusValid` | 分开显示；通信失败与请求失败分别处理 |
| 系统五态 | `data.status.systemStatus/systemStatusTextZh` | 待机、运行、检修、故障、离线；未知事实不冒充正常 |
| 本机状态与方向 | `data.winches[].status/direction` | 按`winchId`关联，不复制整机状态给四台 |
| 本机高度/速度 | `heightMeters/heightValid`、`speed/speedValid` | m、m/min；使用本机测量 |
| 两根钢绳 | `data.ropes[].tension/valid`及身份 | 后端kg，页面t时除1000，只转换一次 |
| 本机钢绳总拉力 | 同帧两根独立有效钢绳相加 | 不用`tensionAverage`代替总和；缺一根则合计为空 |
| 电机等效拉力 | `winches[].torqueKg/torqueValid` | 独立反馈换算的等效kg，可转换为t，不标为N·m，不用两索之和替代 |
| 环体高度 | `ringHeightMeters/heightValid` | 无独立有效来源就留空，不能用四机均高替代 |
| 本机额定值、维护、阈值、限位 | 设备配置或维护记录 | 当前没有来源的字段显示暂无数据，不造默认业务值 |
| 本日次数、已完成数、累计时长 | 已保存的上行记录/预计算 | 明确上行口径，不能拿`PROCESS`样本数代替 |
| 当前/上一条记录 | 本机参与的真实上行记录 | 当前记录不填写未来结束时间；没有记录就为空 |

实时上行、下行都正常推送，离开页面解除订阅。`sampledAt/sequence`用于关联与排序，不用于数据过期判断；页面按附件要求不增加“更新时间”说明行。

## 6. 上行历史列表

列表只返回记录摘要，默认按上行开始时间筛选，开始时间倒序、唯一编号作为第二排序键。页面沿用附件每页10条；服务端限制页大小，不返回所有采样。

| 字段 | 本版含义 |
|---|---|
| `id/recordCode` | 上行记录唯一标识，所有页面一致 |
| `kind/recordScope/directionScope` | `RUN/LEG/UP`，不是完整往返次数 |
| `startedAt/endedAt` | 已确认的上行记录起止，不含普通下降时长 |
| `state` | 进行中或已结束，结束不等于正常完成 |
| `runResult/terminationReason` | 已确认的完成/终止事实和原因；不足以判定则说明未确认 |
| `durationSeconds` | 本次记录历时，可包含本次上行中的等待；不冒充有效运动时长 |
| `motionDurationSeconds` | 有可靠区间依据的有效上行运动秒数；无依据不补算 |
| `maxTension/minTension` | 本次有效上行钢绳采样极值，单位明确，不含电机、两绳总和或下行异常值 |
| `abnormalCount` | 属于该上行记录的异常事件数；不等于处理尝试数 |
| `sequenceNo` | 展示顺序，不作为记录主键或完整清洗次数 |
| 数据完整说明 | 是否存在已观测的采集中断、记录边界未确认、归档缺口 |

`entries`只含当前页；`total`表示当前筛选范围的总记录数。可用日期从日期索引/日汇总获取，不能从这一页十条记录猜测。上行记录日期与独立下行异常日期分开说明；只有异常的日期可以在异常入口查看，不制造一条RUN来撑日期。

累计多年的日期索引可按日历窗口查询；如果沿用附件“完整availableDates”，应查询已经维护的轻量日期目录，不扫描全部原始帧。真实历史日期范围由后端提供，不沿用演示数据的2026年起点和固定截止日。

## 7. 单次详情与结果展示

单次详情包含四部分：同一条`entry`概况、上行采样曲线、记录内异常事件、参数及各机统计摘要。沿用附件的`sensors/servos`曲线角色时，它们都明确只覆盖UP；独立下行异常使用单独的`downExceptionEvents`展示，不塞进上行曲线。

概况保留附件七项：开始时间、记录时长、运行结果、异常次数、启动来源、最大/最小钢绳拉力。有来源才返回启动方式；AUTO是模式，不证明是定时启动。

结果分开表达过程是否结束、是否确认到位、异常是否恢复：

- 已确认上行完成，异常记录完整且无异常：正常完成。
- 已确认上行完成，记录内已发生异常均有明确恢复事实：异常完成。
- 明确中断、急停或故障退出：按真实终止原因显示，不要求先凑齐五次失败。
- 完成、恢复或异常覆盖情况无法确认：显示已知事实与未确认部分，不强行归为正常完成。

附件中的`COMPLETED/FAULT_TERMINATED`和五次条件不足以涵盖上述情况，前端需扩展终止原因和未确认展示。`attemptCount/outcome`无真实来源时为空，不从D3、当前状态或峰值倒推处理过程。D3=50仍按原故障说明展示。

概要、曲线和事件分开按需请求，避免详情响应一次携带全部采样和全部事件。若继续使用附件单响应结构，也必须增加有界曲线和事件分页信息，并同步修改前端消费方式；不能返回前半段后让页面误以为整条记录已经完整加载。

完整异常列表可校验总数与`abnormalCount`一致；分页事件则单独返回总数，不能要求`abnormalCount`等于当前页长度。

## 8. 高度曲线、悬停和统计表

### 8.1 原始上行曲线

每个点携带记录、动力设备、来源角色、连续上行分段、采样标识/帧标识、时间、本机高度、实际速度、数值及通道质量。钢绳1、钢绳2、独立电机反馈分别保留身份。

原始点按采集顺序连接。经过同一高度两次不代表同一点；回退、换向、通信中断后的片段不能按高度排序后连成一条实线。正常下行不归档，连接线不能跨过它制造“连续上行”。

悬停锁定具体记录/分段/采样帧。两索合计只使用本机同帧且均有效的读数；四台高度分别使用本机高度，不能因为同高就取不同时间拼成同时测量。没有严格配对值就留空，不由前端任取附近点凑齐。

绘图减少点数时保留峰值与缺口。降采样概览不能充当精确原始快照；需要精确悬停时按点标识读取对应帧，或将概览返回为明确的区间聚合对象。

### 8.2 原始曲线与平均曲线必须区分

附件横轴是高度，不是时间。高度平均使用实际本机高度分箱，保存分箱起点、宽度/边界和统计规则版本。分箱宽度要依据测量精度明确配置，本版不猜定现场精度。

不同设备、钢绳、电机和方向不能混入一个桶；平均曲线固定UP。没有样本的高度桶为空，不插值成“真实点”，不为0～30m绘图区补齐采样或机械限位。

每个来源/高度桶保存有效值之和、有效样本数、最小/最大及必要速度统计：

`高度平均拉力 = 有效拉力之和 ÷ 有效样本数`

合并日/月结果时累加和与数量，不等权平均每日/每月均值。默认采用附件的样本加权，不实现未明确区间规则的时间加权。速度平均使用速度自己的有效样本数，不能借用拉力数量。

平均点的`height`是统计高度坐标，`time`若沿用附件字段，只能表达统计范围/快照，不冒充现场采样时刻。返回`statisticalBasis=SAMPLE`、`directionScope=UP`、实际统计范围和高度分箱信息。

两索总拉力平均只能从“两索同帧均有效”的配对集合单独聚合；不能相加两个样本集合不同的独立平均值，即使两者`sampleCount`相等。

### 8.3 数量与右侧表口径

- `units[].sampleCount`按附件表示参与该曲线组的运行记录数；`points[].sampleCount`表示该高度/来源的有效采样数。两者不能互换，按后端明确规则分别维护。
- 顶部记录极值使用本次有效上行钢绳原始数据，不随图表勾选变化；右表按当前设备/来源统计。有效性判断落实到通道，不能因整帧部分通道缺失就把其他有效通道改成0。
- 悬停只改变“该高度实际数据”，不改变“本次上行统计”。电机仍为独立反馈，不从钢绳值生成。
- “最高平均/最低平均”是高度平均曲线的极值，不能标成期间原始测量的最大/最小。
- 0～30m、1.4t/3.0t是附件显示范围；原值不裁成坐标上限，也不由其生成阈值或固定27m限位。

## 9. 日、月、季度、半年、年预计算

### 9.1 两类汇总分别保存

周期报表保存次数、结果、已知上行时长和异常分类；高度统计保存本周期每设备、每来源、每高度桶的和/数量/极值。已有按时间桶的设想可用于独立时间趋势，不能替代本版高度平均曲线。

附件的TODAY、YESTERDAY、MONTH、PREVIOUS_MONTH、YEAR、PREVIOUS_YEAR由真实自然周期与实际数据范围取得。季度、半年沿用同一规则扩展，不建立另一套原始数据。

后台计算链路：

`上行采样/事件/结果提交 → 持久待更新标记 → 日报表与日高度桶 → 月/季度/半年/年结果 → 查询直接读取`

当前周期后台持续更新；已结束月份提前算好保存，不等用户点击才扫描原始帧。迟到数据或跨日运行的结果变化，只重算受影响的周期。任务失败保留上一成功版本与待更新标记，不能假报0。

历史没有去年数据时，不生成去年曲线或零线。附件要求的空周期元数据可以保留，但应明确`empty=true`，展示“无历史数据”。

### 9.2 日期和计数归属

业务时区使用`Asia/Shanghai`，采用左闭右开边界。以下是固定查询示例，不代表当前日期：

| 周期 | 开始，包含 | 结束，不包含 |
|---|---|---|
| 2026-10-22当日 | 2026-10-22 00:00:00 | 2026-10-23 00:00:00 |
| 2026年10月 | 2026-10-01 00:00:00 | 2026-11-01 00:00:00 |
| 2026年第四季度 | 2026-10-01 00:00:00 | 2027-01-01 00:00:00 |
| 2026年下半年 | 2026-07-01 00:00:00 | 2027-01-01 00:00:00 |
| 2026年 | 2026-01-01 00:00:00 | 2027-01-01 00:00:00 |

自然月不是固定30天，闰年按日历计算。为了使附件列表、`todayRunCount/todayCompletedCount`与周期结果分布一致，本版**运行次数及其完成/终止结果统一归属该记录的开始日**；完成数是该批记录中已确认完成的数量，不是当天所有结束事件数。

例如上行在22日23:58开始、23日00:08完成：22日有一条上行，23日完成后回填22日这条记录的结果并更新相关汇总。若十分钟均为可靠上行运动区间，运动时长分别归属22日2分钟、23日8分钟；测量仍按各帧采集日期归属。界面可写“今日开始的上行：已完成/总数”，避免误解。

这调整了前一版“完成次数按结束日”的建议。以后若需要“今日实际完成事件数”，必须另外命名、按结束时间统计，不能复用同一个`completedCount`。

`durationSeconds`是记录历时；`runningHours`本版只能明确为累计有效上行运动小时，不能由“仅上行＋下行异常”推导完整上下行工时，也不能将采样数乘固定间隔作为真实运动秒数。系统时长不乘4；四台之和另称设备工时合计。

异常统计区分上行记录内异常和独立下行异常。下行事件不增加`runCount`，不进入上行完成数或上行测量极值；系统异常总数可按唯一事件标识合并，不能在关联展示时重复计数。

## 10. 数据库存储对象与查询方式

以下是逻辑存储对象，不是本轮新增的表或DDL：

| 对象 | 关键内容 | 查询重点 |
|---|---|---|
| 上行运行记录 | `recordId`、设备、业务用途、起止/结果、参数快照、摘要、数据完整说明 | 设备＋开始时间＋稳定编号 |
| 上行采样 | 设备、记录、分段、采样帧、时间、各机上行测量/有效性 | 记录＋时间/序号；设备＋时间 |
| 异常事件 | `eventId`、方向、设备、可空的关联记录、原因、恢复/终止、有限事件快照 | 设备＋事件时间，关联记录 |
| 周期报表 | 设备、周期类型/边界、计数/时长/测量摘要、规则及结果版本 | 设备＋周期类型＋起点唯一定位 |
| 高度统计 | 周期、设备、来源、UP、高度桶、有效和/数量/极值、配对总拉力统计 | 周期＋设备/来源＋高度桶 |

四机八索固定规模可采用固定测量列保存一帧；混合方向时仅归档属于UP的正常测量通道，下行异常快照另存。不能把“未按策略归档”冒充“传感器测量无效”。不按每根钢绳建表，也不为五类周期复制五份原始历史。

当前7表中已有批次/分段汇总，不能还原逐帧高度曲线。实施前需要单独审阅迁移与旧数据标记；缺少原始采样的旧段只能作为段摘要展示，不能生成假原始曲线。

查询只返回页面需要的范围：

- 列表：每页10条摘要和该范围总数，日期目录单独维护。
- 单次概要：一个记录及有限摘要，不内嵌全部原始帧。
- 曲线：指定记录/周期、设备、来源、高度/时间范围；限制每序列及全响应点数，返回实际粒度与是否聚合。
- COUNT“全部次数”：可列出符合条件的记录范围，但曲线分批加载；标明已加载/总记录数量，不一次拉取当日所有记录的完整曲线。
- 事件：按设备、方向、时间或关联记录分页；下行事件有独立入口。
- 周期平均：读取预计算的高度桶及元数据，前端不汇总数据库全量样本。

缩放后再取局部细节；单位切换不重复读取同一份曲线。分页和曲线预算属于服务端约束，不能只依赖浏览器自觉少请求。大量导出由后台任务读取，下载文件不等于把全部原始数据加载到页面对象中。

## 11. 缓冲、失败和重启

现有`PlcMessageBuffer`会合并同设备快照，`TelemetryHistoryBuffer`只是2048个批次的内存队列，两者都不能直接保证本版上行和下行事件不丢。

拟议流程：

```text
PLC读到原始帧/实际通信结果
  → 底层有界、有序采集通道
  → 上层PLC表示入口主动取帧
  → 大厅 → 清洗服务更新状态、识别记录/异常、选择归档数据
      → 最新业务快照 → 实时推送（上行、下行均显示）
      → 上行采样/异常事件/必要记录变更 → 持久待保存缓冲
          → 统计服务保存器 → DAO事务 → 数据库
          → 提交成功后确认缓冲消费
          → 后台统计器 → 周期报表/高度桶
```

归档选择必须在旧帧被最新值覆盖前完成。采集通道允许正常下行在内存中被短暂处理，但持久历史缓冲只接收选中的上行、异常和必要记录变更，不把正常下行先全量落磁盘再称为未保存。

下层通道和DAO只暴露读取/确认/保存能力，不回调上层服务。业务选择由清洗模块的辅助类处理，统计模块的保存器管理持久缓冲与事务，四个服务门面负责调用编排，不把全部算法写进门面。

已经安全写入持久缓冲的数据采用稳定标识重放：事务提交采样、关联事件/记录变更、待统计标记，成功后确认消费。响应丢失使用同一标识重试，由唯一约束防止重复，统计重算覆盖结果而非再次累加。

持久缓冲的接受点必须以可靠刷盘为准。采集到但尚未写入它的数据、服务停止期间未采到的数据，不能承诺断电不丢或事后补齐；有序内存通道也不是永久日志。缓冲满、磁盘故障应明确暴露归档失败/缺口，不能无限堵住控制线程。

数据库暂时不可用时，已接收数据保留在持久缓冲，恢复后分批补入；单通道异常不丢掉其他有效上行数据。PLC通信失败和恢复记录为实际事件，历史显示缺口，不以采样时间判断过期，也不使用最后数值填平曲线。

补入数据按原采集时间归属高度桶和周期；运行结果变化还要更新其开始日的记录计数。重算标记持久化，重启后继续；计算中又有新数据时保留后续重算要求，防止旧结果覆盖新变化。

## 12. 导出、容量与实施边界

运行汇总导出覆盖已经查询的范围，不只当前10条；单次采样导出涵盖该条记录实际保存的所有上行设备/来源，不受图表隐藏项影响。下行异常另列事件时间、原因和快照，不能标成完整下行采样。大范围任务式导出保留筛选与结果版本，避免分页变化导致漏行/重复。

永久测量量级应按“采样频率×实际归档上行时长＋异常快照”估算，不能再用全天原始帧数直接当本方案容量，也不能假定恰好减少50%。还需计入记录、事件、高度桶、索引、待保存缓冲和备份。上行原始历史与事件不自动删除，长期容量按实测规划。

实施顺序：先落实记录边界与方向归档，再完成持久保存与事件查询，随后完成列表/详情和高度曲线，最后完成五类周期预计算、分页导出及容量验证。没有明确来源的PLC阶段、处理次数、启动方式和限位不补写。

验收要覆盖：实时下行仍可见而无正常下行采样；下行异常可独立查到且不污染上行均值；四机身份与同帧配对正确；上行异常回退不虚增生产次数；跨日归属一致；补传/重启不重复；平均按和与数量合并；无去年数据不造线；峰值/缺口不被简化曲线掩盖；页面、列表、详情、导出口径一致。
