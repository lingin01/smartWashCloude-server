# 首页推送、查询快照、上行历史与页面统计方案

日期：2026-10-24。依据本次《前后端职责与页面接口修订说明》更新。本文为目标设计，没有修改前端、后端实现、数据库或PLC配置。

页面职责、公开编号、状态名称和响应规则以[本轮前后端对齐说明](frontend-backend-contract-alignment.md)及[对外接口说明](external-api-contract.md)为准；PLC事实、运动用途和保存边界沿用[统一方案](unified-plc-business-and-data-plan.md)。本文解释这些规则怎样落到页面、查询与历史。

一套系统、一台PLC、四台动力设备、八路索拉力，后端Modbus TCP直连。上行/下行指机械提升/下降。生产上行与回退/检修上行留核心原始；正常下行只实时展示，下行异常留事件点。采集数据不做时间校验，未知点位语义、阈值、机械限位、处理尝试不编造。

## 1. 前端显示结果，后端提供业务结论

| 责任 | 后端返回 | 前端处理 |
|---|---|---|
| 对象身份 | systemCode、winchCode、sensorCode、实际名称及关系 | 显示、选择和切换，不按组号猜名称 |
| 状态和故障 | 系统/单机最终工况、传感器状态、中文说明、故障对象 | 按明确状态套样式；待机黄色，实际故障对象红色 |
| 测量和质量 | 数值或显式null、单位、质量及缺失原因 | 格式化，不用0补缺失 |
| 两索合计 | 已配对的ROPE_TOTAL序列、读数、质量和统计 | 直接展示，不自行相加或用邻点凑齐 |
| 运行结果 | 最终结果、结束原因、启动方式的码和文字 | 展示，不从事件数组推断结论 |
| 历史统计 | 均值、极值、有效数量、周期分组及比较结果 | 显隐曲线、选择已加载记录，不重算业务统计 |
| 交互 | 可用范围、错误原因、操作阶段 | 输入检查、提交、分页、加载/空态/失败提醒 |

新页面响应的拉力单位为t，库内继续kg，由后端查询/表示转换一次；页面切换kg/t属于展示格式化。新页面必需的可空字段显式返回null，空集合为[]，有效0保留。当前Java接口仍可能省略null，属于需要适配的现状，不能把它当新页面契约。

这里的后端统计/合计由清洗和统计模块自己的辅助类完成；四个服务门面仍只编排。页面不接收CSS或由颜色推导业务。阈值来自已确认数据库配置，缺失就返回未配置说明，不沿用演示阈值判断NORMAL。

## 2. 页面对象与读取方式

| 页面 | 表达什么 | 读取与保存 |
|---|---|---|
| 首页 | 当前系统、四机八索状态和读数 | 先HTTP完整快照，后每1秒完整推送；上/下行都显示 |
| 动力设备详情 | 查询时本机状态、读数、设定速度和历史摘要 | 查询快照；进入、主动刷新、重试时读取，不持续订阅 |
| 拉力对比 | 查询截至时刻的一次/多次上行及周期平均 | 用户切换查询范围时读取；无5秒定时刷新 |
| 上行历史列表 | 每次已识别生产上行的起止、结果、参数和摘要 | 长期保存，分页，不携带全量采样 |
| 单次历史详情 | 同一recordCode的事实、曲线、总拉力、统计与异常 | 有界组合响应，缩放/继续加载仍受预算 |
| 告警中心 | 系统/设备/测点异常及恢复、归档事实 | 独立分页；下行异常无运行关联也可见 |
| 数据归档 | 左侧变化图、右侧比较图及最终汇总 | 后端准备两图、实际比较范围和变化率 |
| 导出记录 | 已提交范围的任务及文件 | 后台生成，完整后下载；不让浏览器拼接全库 |

首页故障/离线设备和异常测点不再跳转告警页；保留正常查看详情、选择设备、简单提示和独立告警中心。视频不在本期；模型管理待开放，历史巡检、数据分析占位，不增加无来源业务接口。

实时能显示下行，不等于历史能回放正常下行。未保存的下行全程曲线、全程极值、全程原始导出仍不能提供。

## 3. 公开编号和一次记录

### 3.1 页面编号与内部主键分开

页面统一以公开系统编号systemCode查询，例如配置中的QJXT-01；系统不是四台动力设备共用的设备编号。每台有winchCode/winchName，每个测点有sensorCode/sensorName，均由后端返回。groupNo只用于布局、关联和排序。

内部继续用system_id、PLC deviceId、winchId、ropeId、sensorId及其明确绑定。清洗服务解析公开编号到内部关系，不把改页面字段当成重命名数据库主键或重建盒子链路。页面不再使用系统含义的tankCode，也不默认回退TANK-03。

recordCode贯穿列表、详情、事件与导出。sampleFrameId定位实际采集帧，后端pointKey定位可对照的本机来源读数；展示序号不是记录主键或清洗次数。

### 3.2 现阶段RUN是生产上行单程

一条已识别生产记录为RUN/LEG/UP，四台同步参与仍是一条系统记录。完整往返CYCLE是另一个业务对象；只保存上行不改变实际完整清洗定义，也不意味着现在能可靠识别完整周期。

M8是正常回原位的约1秒脉冲，原位可在上方；M9是下降到位；M204已有描述是上去再下去完成。未确认组合不写成通用上行开始/完成算法。D10/D11不能相加除2、按固定高度或理论时长补出记录。边界不明时保留观测、采样和未确认结果，不造正常完成。

同一过程中的回退提升使用RECOVERY_UP，不新增生产次数；手动检修提升使用MAINTENANCE_UP；方向UP但用途不明为UNCLASSIFIED_UP。四类上行原始都保留，默认生产统计只纳入PRODUCTION_UP。未关联采样不强挂最近一条记录。

## 4. 首页初始快照与每秒推送

目标入口：

- `GET /api/command-center/home?systemCode=...`：完整初始快照。
- `GET /api/command-center/home/stream?systemCode=...`：SSE，每1秒发送完整最新业务快照，结构与初始响应一致。

即使采集序号未改变也按每秒要求发送，不把保活注释当成业务快照。updatedAt保留实际采样/业务快照时刻，不能为了每秒推送改成伪新采样。推送顺序与连接状态单独维护，采集实例/序号用于事实顺序，不用采样时间决定是否接受历史。

切换系统先释放旧订阅，再读取和订阅新系统；客户端核对消息systemCode，避免串数据。断流只提示“数据连接中断”，保留实际updatedAt或明确旧视图说明，不由前端宣布PLC故障/离线。重连重新读取完整快照；首页推送不是历史补发，后台归档不依赖页面在线。

| 首页字段 | 来源与含义 |
|---|---|
| systemCode、systemName | 实际系统配置；不硬编码示例名称 |
| systemHeight | 已确认总高度配置；未知不填30m，也不由曲线绘图区反推 |
| systemCurrentHeight | 独立有效系统/环体高度；无来源返回null，不用四机均高替代 |
| systemStatus、systemStatusText | 后端最终五态：IDLE/RUNNING/MAINTENANCE/FAULT/OFFLINE及中文 |
| online、isMoving、movementDirection | 后端分别解释通信、实际运动和方向；无依据明确未确认，不将D201运行直接等同实际位移 |
| averageTension、averageSpeed | 后端计算的有效测量平均，t、m/min；带数量/质量说明 |
| updatedAt | 实际快照时刻，带时区；用于展示，不作数据过期判断 |
| winches、sensors | 四台与八测点，各自公开编号、实际名称、状态、方向/数值及来源关系 |
| faultSources | 已知故障对象、编码与原因，不能将系统普通故障复制成四台电机本体故障 |

系统和动力设备页面待机用IDLE；原代码/内部STANDBY由后端映射。动力设备只有operatingStatus及statusText作为工况权威，不让前端在多个旧status字段间选优先级。急停不是第六种工况，按钮和真实历史急停原因保留。

传感器返回status/statusText、quality、pressure、unit、alarmThreshold、safetyValue；pressure仍表示拉力t。阈值判断、传感器故障和机械拉力异常由后端区分：单传感器故障高亮该测点，不自动声称整台动力设备本体损坏。未配置阈值不能推导正常，明确缺失说明；不编生产阈值或新增远程保护算法。

当前真实代码仍只有`/api/cleaning/devices/{deviceId}/realtime`及其SSE，外层Result.data里面还有实时data，空值可能省略，同序号可能只发保活。上述页面路径、字段、IDLE、显式null和每秒完整快照是本轮适配目标，不是已实现事实。

## 5. 动力设备详情是查询快照

目标`GET /api/command-center/winch/detail`输入systemCode与winchCode。返回updatedAt/asOf、winch、两路sensors、currentHeight、currentMode、setSpeedMPerMinute、todayCompletedCount、runningHours、maintenanceAt及独立torqueForce。

- winch.operatingStatus/statusText为本机权威工况；真实名称直接显示。
- setSpeedMPerMinute为必返的真实有效设定速度，不拿当前实际速度、D65同步速度或额定速度补齐。只有已确认有效配置才返回正常完整详情；配置未就绪按接口明确说明未就绪，不造数值满足类型。
- ratedLoad/ratedSpeed从本期详情要求删除；不为未展示字段新增档案需求或接口占位。
- todayCompletedCount仍按既定口径：今日开始的生产上行记录中已确认完成数，返回countBasis=STARTED_DATE和文字说明；不是当日全部完成事件数。
- runningHours仅为本机有可靠区间依据的生产上行运动小时，未知为null或说明已确认部分。系统时长不由四机相加。
- torqueForce来自独立电机反馈及已确认公式，t；不以两索合计代替，不能标成N·m。

详情不订阅首页SSE，不做5秒刷新；进入、用户主动刷新/重试才读取。查询范围改变时才查询对应曲线，切换单位、图例或已加载记录只改变展示。

## 6. 统一拉力对比和悬停

### 6.1 一个接口提供所需来源和分组

目标`GET /api/command-center/winch/tension/trend`输入systemCode、winchCode、viewType=FORCE_COMPARISON、comparisonView。旧rangeType分支、独立run-comparison和torque-force/trend不再纳入本期正式契约；伺服仍由统一接口提供。

| comparisonView | kind | 后端准备的分组 |
|---|---|---|
| COUNT | BATCH，按运行 | 查询截至时刻本日开始的实际生产上行，说明进行中/已结束 |
| DAY | PERIOD，按统计周期 | 今日、昨日、本月、本年平均 |
| MONTH | PERIOD | 本月、上月、去年同期平均 |
| YEAR | PERIOD | 本年、去年同期平均 |

WEEK、MONTH、WHOLE为旧通用分组类型，本期不另开这几类查询。去年同期由后端按同一日历位置和已纳入数据的明确截止构造，返回实际范围与可比性，不把去年全年冒充本月同期。具体比较规则见对齐说明与接口文档。

返回kind、units、series、heightMin/heightMax、heightLimits、dataRange、asOf、updatedAt。每个unit带id/name、实际起止/dataThrough、empty和原因，运行组另有runState及后端结果说明；空组保留元数据并标empty=true，不生成0线或假去年数据。

### 6.2 四个来源由后端提供

| sourceRole | 页面含义 | 统计来源 |
|---|---|---|
| SENSOR1 | 钢绳1 | 本机已配置第一路独立测量 |
| SENSOR2 | 钢绳2 | 本机已配置第二路独立测量 |
| ROPE_TOTAL | 钢绳总拉力 | 后端已明确配对的两索集合，内部可仍用PAIRED_SUM标识 |
| SERVO | 伺服电机拉力 | 独立反馈按已确认公式换算 |

各series返回unitId、来源编号、实际name、unit=t、含points的segments和statistics。statistics包含averageTension、maxTension、minTension、validSampleCount及明确统计口径；无有效值时力值null，已知有效样本数为0。未计算不能伪装为0。

后端按稳定采集帧、已明确的本机身份/方向/采集一致性建立pointKey与配对读数。仅“时间接近”或“高度相同”不构成匹配，不猜时间容差，不因时间早晚拒收采样。不具备合计条件时ROPE_TOTAL=null及对应质量/原因；前端不任取附近点或补0相加。

悬停用后端给定pointKey直接定位已返回的来源读数；精确原始点接口也提交pointKey，由后端解析对应真实sampleFrameId，不能将周期平均桶当作现场帧。展示同一高度不同经过的点，仍以真实记录、连续段和采集顺序区分。

### 6.3 原始线、平均线和数量

原始UP点保留time、height、value、quality、方向/速度及分段。后端按采集顺序整理，不按高度重排；回退、换向、正常下行或断线之间不能画连续实线。回退提升原始留存但独立用途展示，默认生产均值排除它。

高度平均按实际本机高度、来源和已确认分箱规则构建；保存sum/count/min/max，平均=sum/count。跨日/月合并和与数量，速度用自己的有效数量；不平均平均值、不把两个独立来源的均值相加当总力平均。缺高度但有效的生产拉力仍进入测量摘要/极值，不能进入高度曲线。

每个高度桶sampleCount是该来源有效采样数；unit.sourceRecordCounts是各来源参与运行去重数；unit.recordCount是四来源并集的去重运行数。前端切换图例不重算这三种数量，右侧直接展示后端对应来源统计及明确口径。

最高/最低原始拉力、平均曲线最高/最低平均各自命名。平均点的time不得伪装现场采样时刻，使用实际周期/统计截止说明；未知限位显式null，不用0～30m绘图区填限位。

## 7. 上行列表、单次详情与全系统日期

目标列表为`GET /api/command-center/history/list`，输入systemCode、scope=RUN、startTime/endTime、endExclusive=true及page/pageSize（默认10）。默认按已确认开始时间筛选和倒序，唯一记录编号为第二排序键；未知开始的记录通过明确的观测口径查询，不偷换实际startedAt。

每条entry提供recordCode、实际/观测起止、durationSeconds、runResult及runResultText、endReason及endReasonText、startMethod及startMethodText、当次setSpeedMPerMinute/运行间隔快照、abnormalCount、maxTension/minTension及完整性说明。拉力t；未知事实返回null和说明，不从当前参数、当前阈值或当前设备状态反推历史。

前端直接展示最终结论，不通过exceptionEvents推断正常/异常完成。已确认完成且相关异常无缺口、无异常才能称正常完成；已知异常恢复后完成称异常完成；有明确退出原因才称终止。D3=50不提供五次过程，未确认处理次数不得补0或编造明细。

返回entries、total、asOf、dataRange；includeAvailableDates=true时提供全系统轻量日期目录。availableDates独立于当前页和当前startTime/endTime筛选，不能只列本页十条或所选月份。完整目录可分批获取，但必须返回目录覆盖范围、是否完整及继续游标，前端加载完之前不能声称已获得全部日期。目录来自已维护的记录日期索引，不扫描原始采样、不由前端推算。

只有下行异常的日期在告警/异常入口可查，不制造RUN撑日期。列表total是筛选记录总数，不是完整往返次数或样本数。

目标单次详情为`GET /api/command-center/history/detail`，输入systemCode、recordCode。后端返回entry、各设备sensors/servos、ropeTotals、各来源statistics、当次参数和有限异常摘要，以及实际height范围/已确认限位。概要、曲线和事件均有响应预算与完整性标记；首响应提供有界概览，继续加载/缩放读取局部，不能把截断数据说成整条记录完整。

曲线和事件分页不会改变后端abnormalCount；事件总数与当前页长度分开。正常下行不拼进上行曲线；无可靠关联的下行异常也不改写刚结束的上行结果。

## 8. 告警中心与归档比较

目标`GET /api/command-center/alarm-dashboard`按systemCode、日期、deviceCode（本接口的公开winchCode值）、sensorCode、category、view、page/pageSize在后端筛选、去重和排序。默认recordKind=ALARM；通过recordKind=EVENT、view=HISTORY可先分页查询全部真实事件，再查看eventCode详情，无RUN关联或非告警的下行事件也可追溯。页面保留独立告警中心与详情弹窗，不从标题关键词判断类别、阈值或是否恢复。

后端返回activeCount、seriousActiveCount、todayCount、todayRecoveredCount、asOf及实际统计范围。activeCount覆盖全部历史isAlarm=true且尚未确认恢复的告警，含恢复情况未确认项，不能仅查今天或把非告警事件计入；列表筛选不改变系统统计卡口径。告警项包含alarmCode、对象关系、类别/等级/状态、码与中文说明、触发值、触发阈值/版本、恢复和归档事实。归档不等于恢复，不以当前新阈值重判旧告警；无已确认等级/处理依据时返回未确认，不造保护阈值。

目标`GET /api/command-center/archive`一次返回左侧changePoints、右侧comparisonCurrent/comparisonPrevious/comparisonAxis及summary。查询分别表达左图、当前比较区间、参考比较区间的完整起止日期，后端回显左闭右开实际边界、范围、截至和可比性。

两图的数据对齐、周期比较和变化率由后端完成，前端不按数组下标拼不同周期。参考均值为0或样本不足时变化率为null及原因，不能替换极小分母。数据归档展示复用上行原始与预计算，不另存一套页面历史，不扩大为占位“数据分析”模块。

## 9. 日历预计算、时长和跨日归属

业务时区Asia/Shanghai，范围左闭右开；2026年10月为10月1日00:00到11月1日00:00，第四季度为10月1日到次年1月1日，下半年为7月1日到次年1月1日。自然月按真实日历和闰年，不固定30天。

记录次数及结果归开始日；测量归采集日；事件归明确发生/首次观测日；可靠运动区间按跨日交集拆分。22日23:58开始、23日00:08完成，记录及完成结果归22日；23日不新增一次开始。真实采样各归日期，不能把跨日参与数相加当月两次。

详情todayCompletedCount沿用今日开始记录中的完成数，后端说明STARTED_DATE。以后如需按结束日统计“今日完成事件数”，必须另定义字段，本轮不复用同名计数。

记录durationSeconds可能包括等待，不等于有效运动时长。runningHours只用有依据的PRODUCTION_UP运动区间，未知为null或明确已确认部分；D16/D66～D69会重置，采样数量也不能乘固定轮询间隔补工时。没有独立持久证据时SYSTEM运动时长为空，四机工时之和另有含义。

## 10. 保存、缓冲与查询预算

| 数据对象 | 保留内容 |
|---|---|
| 运行主记录 | 稳定编号、起止/结果、参数/身份快照、生产极值、事件数和缺口 |
| UP原始 | 帧标识、各归档本机的状态/方向、用途/分段、测量与有效性 |
| 异常/告警 | 对象定位、原因、触发阈值配置快照、恢复/归档事实、有限事件点 |
| 本机分日摘要 | 记录、本机、采集日、motion_role的和/数量/极值及有据时长 |
| 周期与高度桶 | 自然周期结果、来源统计、版本和实际覆盖 |

正常下行不连续落盘；下行异常只留必要触发/恢复/终止快照。同帧其他设备常规下行不因某台UP被顺带归档。页面对象、中文显示格式不整包重复存成原始数据。

有序入口必须在最新值覆盖前选出归档；选中数据可靠刷盘→统计保存器/DAO短事务→提交成功后确认消费。重放用稳定记录/采样/事件标识去重，后台统计覆盖重建，不重复累计。数据库不可用时已可靠接收的数据待补；尚未采到或尚未刷盘的数据不能保证断电恢复，磁盘满明确报告归档问题。

采集不比较当前时间、上一帧时刻、数据年龄或时钟偏差，不因延迟/跨日拒收或判离线；离线依据通信事实。采样时间仅记录、定位和归入历史周期。配对也不新增猜测的时间误差阈值。

所有页面查询均有限范围和返回预算：列表默认10条，COUNT按运行分组分批返回并说明已加载/总量；每来源及整响应有点数上限，缩减保留峰值/断段，返回实际粒度；日期索引与事件单独有界；前端不下载全年原始再计算。旧批次摘要不能还原的原始点不补造。
