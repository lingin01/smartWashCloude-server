# 实时数据与PLC点位契约（2026-10-26最新确认）

本文整理用户最新确认的PLC事实、实时展示来源和接入待测事项，供后续实时、历史与历史统计共用。本文是讨论阶段的业务契约，**不表示对应业务代码、现场点位映射或联调已经完成**，本次不修改运行代码，也不向PLC读写。

最新确认覆盖此前冲突口径：主历史一条对应整个M106自动运行周期；只在其中的上行阶段按每台0.5m选点；检修只显示实时数据。D10～D13仅展示PLC累计事实，不用来识别历史边界或生成日统计。此前出现的D16、M204本次最新清单未列，不作为本版的运行边界或核心计时判断源。旧文档中的“一次上行一条主历史”“M204主导往返完成”“M106只是辅助位”等表述不再适用本版。

## 1. 对象与通信范围

```text
系统（system）
└─ PLC通信设备（device，配置现场局域网IP）
   ├─ 动力设备1 → 拉力传感器1、2
   ├─ 动力设备2 → 拉力传感器3、4
   ├─ 动力设备3 → 拉力传感器5、6
   └─ 动力设备4 → 拉力传感器7、8
```

系统、PLC、动力设备和传感器分别绑定自己的内部身份；设备槽位1～4、传感器槽位1～8用于点位归属，不代替公开编号。上述传感器顺序须与现场接线配置核对。

同一PLC的实时读取和远程写入共用一条TCP会话，由统一I/O调度处理，急停请求优先。Unit ID已确认为**1**，端口沿用502；IP按实际局域网填写。后端必须部署在能访问该PLC地址的网络内。

通信在线/断开由TCP通信层提供；TCP连接中断表示后端与PLC传输通道中断。正常读到的点按已确认配置直接解释、换算，不另加逐测点“未读到、原值未知、未标定”的业务状态，也不新增采样过期或时钟偏差拒收规则。类型、字序、底部值属于接入前配置和实测事项。

共享TCP会话不等于所有D/M点来自同一个PLC扫描瞬间：D区和M区可能分不同请求读取。后端保存采集批次、读取/接收时刻和点位来源，时间表达为系统观测时刻；没有PLC提供的时间戳时，不冒充PLC内部实际切换时刻。

## 2. 本轮边界、异常和系统状态

| 点位 | 最新已确认含义 | 本版用途 |
|---|---|---|
| M106 | 0→1：整轮自动运行开始；1→0：整轮自动运行结束 | 主历史的起止边界；四台共同形成一条系统记录 |
| M60 | 1表示有异常 | 本轮异常观测事实；不单凭它结束主记录 |
| M61 | 1表示本轮异常结束；下一轮开始置0 | 后端锁存本轮已观测到的异常结束事实，不能只在结束瞬间读一次 |
| D201 | 1运行、2待机、3检修、4故障 | 系统当前状态；不代替M106运行边界，也不等于四台都在实际运动 |
| D202 | 总运行方向；原说明为“m201=1”，只在自动模式下变化，手动模式无变化 | 保留自动模式限定和原值；未提供完整枚举前，不自行定义上下行数值 |
| M3 | **1表示总故障** | 保留系统总故障事实；不自动推成四台各自都发生硬件故障 |
| D3 | 当前故障/保护原因码，详见下表 | 定位原因和事件；非0不统一等同本轮结束 |

M106期间可以包含上行、停止等待、回退、调平、再上行、下行等阶段。只要M106未结束，这些阶段不会各自生成一条新的主历史。实际方向由每台M120～M127决定，不能用M106=1或D201=1代替实际方向。

M61虽然说明为下一轮开始置0，但用户同时指出结束时读取可能已经复位，因此需在本轮持续观测并锁存：一旦观测到本轮M61=1，后续读到0不能抹去该事实。M60、D3及已经观测到的故障过程同样保留到所属记录结算；不能因结束帧故障码清0就把整个过程改成“从未异常”。M60异常发生与M61异常结束分别保留，不能互相替代。

首次连接或重连时直接读到M106=1，只能证明当时处于自动运行中，不能把连接时刻当成已知真实开始。断线前后的轮次归属、未观测边沿和异常信号不能凭累计次数补造。历史处理通道后续必须保留有序观测和边界，不能沿用“同设备只保留最新一帧”的展示合并方式来保证所有边沿都不遗漏。

|---|---|---|---|---|---|---|---|
| 1 | D203 | M120 | M121 | D53～D54 | D66 | D30、D31 | D70 |
| 2 | D204 | M122 | M123 | D55～D56 | D67 | D32、D33 | D71 |
| 3 | D205 | M124 | M125 | D57～D58 | D68 | D34、D35 | D72 |

- D203～D206：0待机、1运行、2故障，分别对应本机；系统状态与本机状态同时表达，不互相覆盖。
- 每台上/下行位：上=1、下=0为UP；上=0、下=1为DOWN；都0为没有上下行指示；都1保留信号冲突事实，不任选一个方向。没有方向指示不独立证明机械已经停止。
- 四台方向独立解释。D202在手动模式可能不变化，不能拿它的残留值覆盖本机M位。
- D53/55/57/59分别是一个有符号32位DINT的首地址，占连续两个D寄存器；不能把后半字当作另一台编码器。
- **D66～D69已确认INT、单位秒**，是各台连续运行时间，停下后重新计数；不是每台占两个字，也不是本轮累计工时。
- **D70～D73已确认INT**。它们是电机力矩来源原值，换算成等效拉力后单独展示。
- D201～D206、D30～D37、D10～D13和errorID等未明确的数据类型、符号和编码，保留为接入待测，不能因D地址相邻就自行认定32位。

实时展示覆盖自动上/下行、暂停及检修。检修运动只更新实时，不产生本版生产历史、0.5m历史点或生产历史统计。M106自动运行期间发生的异常回退/调平不因其方向变化被误判成检修。

## 4. 拉力、等效力、高度和速度

### 4.1 八路拉力与合计

D30～D37逐路使用用户公式，结果单位kg：

```text
单路拉力kg = (原值 - 10) × 0.001 × 101.9716
           = 原值 × 0.1019716 - 1.019716

本机总拉力kg = 本机传感器1拉力 + 本机传感器2拉力
系统总拉力kg = 同批八路拉力之和 = 同批四台本机总拉力之和
```

总拉力是传感器来源之和，不是两路平均值或八路平均值。换算为吨时除以1000，并明确展示单位。正常原值直接套公式；不因为换算结果为负就自动改成0或判为传感器损坏。

统计系统峰值时，先对每个采集批次求八路之和，再取其中最大值；不能把四台不同时刻的峰值相加。每台总拉力与单传感器拉力也分别保留其来源。

### 4.2 电机力矩换算的等效拉力

D70～D73逐台使用用户公式：

```text
电机等效拉力kg = (原值 × 0.35 × 163.0883 × 1.0) / (9.80665 × 0.16)
```

保留INT原值、公式和足够计算精度，显示时再舍入。结果标为“电机力矩换算的等效拉力（kg）”，不是N·m，也不加入本机两传感器总拉力或系统八路总拉力。电机等效力、单传感器拉力、本机传感器总拉力是不同数据来源。

### 4.3 四台独立编码器高度

每台使用自己的底部计数，四台底部值需分别实测：

```text
r = (本机编码器DINT原值 - 本机底部值) / 8192

r <= 12：      高度cm = r × 104.3
12 < r <= 24： 高度cm = 1251.6 + (r - 12) × 110.69
r > 24：       高度cm = 2579.88 + (r - 24) × 117.1

换成米：
r <= 12：      高度m = r × 1.043
12 < r <= 24： 高度m = 12.516 + (r - 12) × 1.1069
r > 24：       高度m = 25.7988 + (r - 24) × 1.171
```

12圈高度12.516m，24圈高度25.7988m，分段连续。不能用统一线性倍率代替整个分段公式。底部值不取首次读值或默认0冒充实测，也不把负高度自动截成0。用户描述正常每次行程约25～27m，这是容量/工况参数，不是已确认的机械限位或必须达到的结束高度。

没有独立系统/圆环高度点。需要展示“四机平均高度”时明确命名，不能把平均值当成另一个实际高度传感器。

### 4.4 DINT字序测试

PLC已设置D0/D1测试初值1234567890：

```text
1234567890 = 0x499602D2
高16位 = 18838（0x4996）
低16位 =   722（0x02D2）
```

现场读D0/D1，确认哪一个地址存高字、哪一个存低字，并选择正确字序还原该已知值。测试只读，不自动向PLC写测试值。编码器按DINT解读；软件支持字序配置不代表现场字序已经测出。

### 4.5 速度与计时

D66～D69是INT秒，结合本机同一连续运动段的高度变化计算观测区间平均速度：

```text
速度m/min = abs(本次高度m - 上次高度m) / (本次轴计时s - 上次轴计时s) × 60
```

计时差大于0时才有该区间速度。整数秒未增加时，不用0作除数，也不强行生成新的速度值；暂停重计、反向或新的连续运动段不能沿用前一段的时间/高度基准。“当前绝对高度÷当前运行秒数”不等于当前速度。

M106起止观测时间可形成整轮持续时间；各轴连续运行计时、上行运动时间和整轮持续时间含义不同，不能互相替代。D66～D69停后重计，不能直接取结束值作为整轮工时。实际INT计时量程、溢出和停止后何时清0仍需现场核对。

### D3=50的最新处理说明

用户最新点表保留原始标题**“五次尝试仍无法移动 告警重试”**。同时补充：遇到结痂时回退再尝试，可能调平；三次回原会提前结束；超过三轮持续告警；仍按设定间隔继续运行，之后完整完成上、下一轮才自动解除。这些原始说明同时保留。

这些说明分开保留，内部回退/重试、回原次数和多个自动轮次不能混为同一计数。**D3非0不统一触发后端结束，D3=50也不阻止后端记录后续按间隔开始的M106新轮次。**主记录仍以M106结束，异常结束事实结合M61锁存和实际过程表达。不能在没有独立尝试信号时按D3=50生成三条、五条或其他数量的重试明细。

“五次尝试”“三次回原”与“超过三轮”的具体计数对象、作用阶段及清零先后可由PLC现场进一步说明。本次不重建PLC内部重试算法，这些层级不影响按M106、M60、M61进行简单归档；也不能把D3清0认定为整轮必然正常结束。

## 7. 历史留点与实时的接口边界

- 每个M106自动运行周期形成一条主历史，记录整轮起止、过程、结果、参数和异常事实；不因四台参与而计四条，不因每次重新上行而新增主记录。
- 仅UP阶段按本机高度每0.5m选点。四台各自触发，任意一台需要保留时保存同批四台上下文，标明各台选中原因；同批另三台上下文不自动等同于它们的高度点。
- 保存目标节点和实际高度。例如跨过0.5m时实读0.52m，实际值保留0.52m，不插值补出一条假定0.50m测量。重复经过同一高度可有不同采集记录，不能用高度唯一键覆盖。
- 实时继续显示DOWN，但本版不因此自动保存完整下行曲线。检修只实时，不进入本版生产历史。
- 0.5m是长期曲线留点密度，不是采集频率。未留为曲线点的UP采集仍参与既定上行测量摘要；整轮过程/次数和各阶段测量范围在历史统计契约分别定义，不能把只保留的UP点称为整轮全量回放。
- 原始编码器、轴计时、八路拉力原值、四路电机原值及其换算结果保留来源，测量、参数、故障过程与远程操作日志分别承担各自作用。
