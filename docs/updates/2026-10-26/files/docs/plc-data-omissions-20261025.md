# PLC实时与历史流程的数据遗漏核对

2026-10-26补充已统一到[实时、M106整轮历史与统计](updates/2026-10-26/realtime-history-statistics-overview.md)及[最新点位](updates/2026-10-26/realtime-point-contract.md)。M106/M60/M61、D11～D13、D3=50与驱动器error ID已提供语义，不能继续列为PLC未给；实际业务传递、归档、查询和报表仍需实现。本页保留较早缺口核对过程。

日期：2026-10-25。核对基线：仓库`085f019`及当前工作区。按用户最新说明：正常读到的配置点直接处理；不新增缺失/未知/未标定等逐字段业务判断。通信状态由PLC TCP连接层提供，连接中断表示PLC通道中断。四台动力设备和八个传感器共用PLC通信通道，运行故障由PLC点位表达。

本次只核对数据链路和修正文档，未修改运行代码、连接PLC或执行数据库迁移。既有有效性字段、连接收发超时与协议解码处理未在本轮修改。

## 1. 对照原则

沿四个位置逐项核对：点位配置 → 采集对象 → 业务实时快照 → 历史对象与数据库。正常收到的数据仍可能因为没有业务字段、转换时未传递、缓存覆盖或只保存统计摘要而无法在后续使用。

现有可配置采集对象是一组通用PointValue；配置并读到某点不等于清洗服务会使用它。采集对象当前保留的是倍率/偏移后的value，没有独立的换算前原值字段；原值留存需要在解码/业务边界明确安排。

## 2. PLC已给出，但目前未完整贯通的数据

| 数据 | 当前链路现状 | 需要贯通的内容 |
|---|---|---|
| D201系统总状态 | 模板和业务转换仍以manualMode/running等旧字段为主，未直接处理D201 | 系统原始状态码及对应状态 |
| D203～D206四机状态 | 当前各机用可选winchRunning/winchFault布尔字段，未接四个新状态码 | 四机分别保存原码及本机状态 |
| M120～M127独立方向 | 当前只有一组up/down，四机快照共用同一direction | 四台各自的上下行信号及方向 |
| D53～D60编码器DINT | 已支持INT32解码，但当前业务只取winchHeight，不接编码器及分层换算 | 四台编码器原值、对应底部配置、计算高度；原始历史保留关联 |
| D66～D69轴连续计时 | 当前TelemetrySample没有对应字段，速度依赖直接读点 | 四台连续计时及与相邻高度的关联，用于区间速度计算 |
| D16～D17本次自动运行时间 | 当前实时与历史模型未承接该值 | 系统本次自动运行计时原值及已确认单位；不冒充累计工时 |
| D10完成上行次数 | 当前实时快照和历史链路未承接该值 | PLC上行完成计数原值及相关边界观测，不与后台记录数混名 |
| M204本轮完成 | 当前未采入模板、未进入实时模型、没有轮次消费与保存流程 | 完成位观测、对应往返轮次及一次完成事件 |
| D30～D37原始拉力 | 模板仍为D40～D47；通用解码只传换算后value | 新读点的八路原始值、换算拉力、两路传感器归属 |
| D70～D73电机力矩 | 业务有torqueKg，但模板symbol为空，未接本次给定换算 | 四台力矩原始值、独立等效拉力及对应原始历史 |
| M3与D3故障 | 已有总fault及字符串faultCode，但未完成本次D3分类到具体设备/传感器的映射 | 总故障位、原始D3码、对象、类别和说明；历史保存过程变化 |
| D300～D307电机故障细节 | 当前未接入本次点位及历史结构 | 读到的补充原码；具体含义以后续PLC说明解释，不猜映射 |

D202已提供自动模式限定描述，但没有完整方向枚举；应保留原值作为上下文，不能代替M120～M127。当前manualMode有基础字段，需要在实际接入配置中落实来源并传入运行整理，不能据此认定模式完全没有基础。

## 3. 业务过程中缺少的关联资料

这些字段由后端组织，不要求PLC额外提供同名字段。

| 关联资料 | 作用 | 当前情况 |
|---|---|---|
| 往返轮次编号与状态 | 将上行及后续下行关联为一轮，承接M204完成 | 旧历史结构虽有roundNo，但尚无按实际PLC事实生成/关联轮次的过程 |
| 一次上行记录编号 | 历史列表一行对应一次上行 | 缺少自动建立、结束和保存的生产流程 |
| 上行记录→所属往返关系 | 上行先结束，M204后更新同一所属轮次 | 尚未贯通，不应等M204后再新建重复上行记录 |
| 连续段与用途 | 区分正常生产、恢复提升、检修及换向/中断后的分段 | 当前实时转换不整理这些过程 |
| 采样批次/点与设备、传感器归属 | 将同一次读取所得数值联系到具体历史原始点 | 实时已有部分对象ID，历史仍以分段测量摘要为主，缺少完整逐点关联 |
| 当次参数快照 | 保存上行当时的启动时间、间隔、设定速度等 | 当前写入视图为内存WRITTEN_NOT_PERSISTED，未保存到当次运行记录 |
| 起止、异常及TCP断开/恢复边界 | 解释一次上行为什么结束、数据从何处中断与恢复 | 缺少与记录/轮次关联的持久事实；断开不能直接当作正常完成 |

系统、动力设备和传感器的拓扑表/ID已有基础。主要缺口是把这些身份与每条原始点、当次运行及轮次贯通，不是重新增加另一套设备结构。

## 4. 数据会在哪些环节消失

### 配置到业务转换

新点位没有配置/读取时，数据尚未进入程序。通用采集对象读到后，CleaningDeviceConverter只选择现有field转换为TelemetrySample；新增计数、计时和M204即使读入，若没有对应业务处理，仍不会进入业务快照和历史。

### 换算前后

ModbusTcpCodec当前返回raw×scale+offset后的数值，PointValue只带value。需要保存换算前D30～D37或D70～D73原值时，必须显式传递原值。编码器原值同样不能只换成高度后在后续丢掉。

### 实时缓存

PlcMessageBuffer.offerSnapshot按PLC编号覆盖上一帧。消费前有多帧到达时，旧帧可以消失；最新显示可采用该方式，但已选历史采样和M204边界需要在覆盖前进入有序处理。这个遗漏发生在已采到的数据进入后端之后。

### 历史汇总与落库

现有清洗历史对象和DAO主要保存分段起止、最小/最大/平均/最后值及样本数。原始点的顺序、逐点高度与运行计时、系统/四机状态和完成位不能从这些摘要恢复。

因此，即使历史表有记录，也不能据此说明完整原始曲线和本轮过程都已保存。应在规定的UP/异常/必要边界范围内保存原始事实，统计摘要另外生成。

## 5. 一批数据建议贯通的最小内容

```text
采集批次：系统/PLC身份、采集编号、时间、TCP连接状态
系统：D201、D202原值、M3、D3、D10、D16、M204
动力设备×4：本机状态、上下行位、编码器原值、轴连续计时、力矩原值
传感器×8：所属动力设备、拉力原值
换算结果：四台高度/速度、电机等效拉力、八路拉力、两索合计
历史关联：上行记录、所属往返、连续段/用途、当次参数
补充故障：D300～D307及明确对象
```

上面是处理与选定历史保存需要的资料，不要求把所有原始寄存器重复放进前端响应；也不表示正常DOWN测量需要连续落库。M204完成、TCP断开/恢复等必要边界可以单独保存。

## 6. 真正需要补充的PLC资料

### 已经提供，不再重复索要

- 系统D201及四机D203～D206状态含义。
- 每台M120～M127上下行信号。
- D53～D60编码器DINT、分层高度公式；D0/D1的1234567890字序测试办法。
- D66～D69连续运行计时单位为秒，停机后重新计；D16为32位本次自动运行时间，停止/中断后重新计。
- D30～D37拉力公式、D70～D73力矩换算公式。
- M3=1有故障，D3已列明的故障码分类。
- D10为完整上行次数；M204表示自动上去再下去一轮完成。
- 远程急停M15写1；历史一条记录是一次上行，并关联所属往返轮次。
- Unit ID=1；PLC IP按现场网络配置，允许通过局域网连接。站号已确认，IP只在部署时填写。

### 优先补充：历史边界与故障过程

不要求每项新增一个寄存器；已有点或现有点的组合能明确表达时，提供地址、值和触发/复位规则即可。

| 编号 | PLC需补充的具体说明 | 为什么需要 |
|---|---|---|
| P1 | 自动/手动模式由哪个现有点表示、0/1或枚举含义；怎样区分自动生产上行、恢复提升和手动检修 | 每台方向已知，但方向不能单独确定生产用途 |
| P2 | 每轮开始和本次上行开始的信号/组合；自动连续多轮时各轮如何划分，四台独立动作是否属于同一自动轮 | 建立正确的上行记录并关联所属往返 |
| P3 | 上行正常到位/完成的信号，或明确D10加1是否能作为这次上行正常完成依据；故障停机与正常到位如何区分 | 上行记录需在上行结束时结束，M204在下行之后才出现 |
| P4 | M204是保持位还是脉冲、持续多久、何时及由谁清零；故障、急停、中断退出是否也触发 | 防止一次完成重复处理或完成信号漏读，明确完成含义 |
| P5 | 中断/取消/恢复各由什么信号表示；恢复是原轮继续还是新轮，恢复提升与生产提升怎样区分 | 保证恢复动作不重复生成生产次数，不把暂停直接记成正常完成 |
| P6 | D3是当前故障还是最后一次故障、何时清0；多故障同时发生如何表示；D300～D307各值含义及复位方式 | 正确记录故障对象、持续和结束过程，保留电机故障细节 |

如果页面继续需要普通/严重两级告警，另外提供PLC等级来源及映射；不能从现有D3类别自行推断严重程度。若只展示本次已给出的故障类别，不强制增加等级点位。
