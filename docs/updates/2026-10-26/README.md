# 2026-10-26 数据库优化落实

本日后续更新已统一为[实时、M106整轮历史与历史统计](realtime-history-statistics-overview.md)，配套[最新点位](realtime-point-contract.md)和[统计契约](history-statistics-contract.md)。新口径一条主历史覆盖一次M106周期，M60/M61决定结果；不再以M204或D10定记录边界。**下面是较早完成的SQL实施记录，保留验证事实；SQL与业务代码尚未按此后续口径修改。**

本轮将已确认的方案落实为MySQL建表与增量升级脚本：系统→4台动力设备→每台2个传感器；历史一次上行一条并关联往返；每台按高度每0.5m留点；全采集流同时参与单次、分日统计。没有连接或修改现有现场数据库，没有向PLC读写。

## 留点和统计口径

每台分别按自己的高度选点。任意一台触发0.5m节点或必要起止、异常、极值、重连事实时，保留该次四机快照一行，记录每台选点原因和是否为高度点。同批其他读数用于当时系统总力的来源，不能自动成为其他设备的高度点或完整下降曲线。

各台分别保留上行/往返ID、设备和传感器身份、连续段、目标节点、实际高度、编码器、轴计时、原始/换算拉力和转矩、速度及方向。跨过0.5m时采到0.52m，实际高度仍是0.52m，不插值伪造测量。唯一来源键为`device_id + capture_id + sample_seq`，重放沿用原实例与序号；不使用高度唯一键覆盖暂停/恢复后再次经过的点。

本机总拉力=本机两传感器同批之和，系统总拉力=八传感器同批之和，转矩等效力单独统计。系统峰值是逐批总力的最大值，不能把四台不同时刻的峰值相加。每台有`run_id + sampled_at + id`查询索引；大采样表不增加大量逐行外键，保存器需要同事务核对归属。

0.5m只约束长期曲线留点。未入点表的采集也参与全流摘要，统计增量、保留点、边界与输入检查点需要分批事务提交，不能只在内存累计到结束。本轮提供版本和检查点字段，事务保存与重放实现仍待接入。

`cleaning_run_system_day`补足系统总力跨日基础摘要，按当天同批八索总力直接累计，不由各机极值或稀疏高度点反算。它合并成SYSTEM DAY，再以不重叠的低层摘要合并月/季度/年。不同规则版本是替代口径，不能相加。四台分别有设备摘要，系统上行次数只计一次。

上行次数归上海时区开始日，测量与持续时间按实际日期拆分，完整往返完成次数另计。均值通过sum/count合并，不平均各日均值。月按日、季度按月、年按月或季度展示，查询不能混加重叠周期。

全流原始帧未长期保存，不能凭0.5m点精确重算任意新口径的全流峰值/均值。既有摘要支持既定范围和版本的合并，改变来源或口径时须说明可重算依据。高度桶基于已保留点，与全流统计分开。

## 升级与兼容

空库使用[完整建表脚本](../../../src/main/resources/schema.sql)；已有7表且采用`device_id`的库使用[增量升级脚本](../../database/migrations/V20261026__upgrade_cleaning_v2.sql)。实际执行前选定库、备份并暂停写入。脚本不建库，不写演示账号、拓扑或现场编号。

升级只扩展3张拓扑表并新增10表，旧记录列值保持原样。旧公开编号允许NULL，不用内部ID冒充真实编号，新版页面接入前配置真实编号。不增加逐字段quality/unknown/未标定状态或采样过期规则。

预检覆盖已知基线、槽位、公共编号冲突，以及已有新表的列类型、可空性、主键、自增、必要索引、外键关联/RESTRICT和CHECK启用情况，结构不符时在第一个ALTER前拒绝。自定义CHECK表达式等非标准变更仍需单独审阅，不支持任意未知库自动转换。DDL自动提交，中断后处理原因再重跑，不依赖整段事务回滚。

新库InnoDB、utf8mb4_general_ci；升级沿用旧拓扑标识的utf8mb4排序规则。新业务DATETIME(3)由应用明确写UTC，业务DATE按Asia/Shanghai生成，不擅自转换旧历史时间。最低MySQL 8.0.16，以实际执行CHECK约束。

应用配置`spring.sql.init.mode=never`，不会随启动执行这些SQL。旧`migrate_legacy.sql`检测到新链路后拒绝清理，避免误删新方案复用的表名。

## 日志与容量

业务结果进入摘要/统计表；统计任务和软件错误进入应用日志；PLC故障进入事件表；远程操作进入持久审计。请求按系统及原始请求编号唯一，输入摘要供未来服务核对同号不同内容。写应答与实际执行分别确认，密码和令牌不进入记录。

本轮不增加全流长期入库、按天分表或自动删除任务。25～27m每台基础51～55个高度点；四机不同步影响同批共享程度，异常/恢复会增加点。此前按48次/日、含索引1KiB/行估计约0.99～3.95GB/年只是场景，不能保证1.5TB可用年数，仍需代表性数据实测并预留日志、备份、binlog及空闲空间。

## 后续接入边界

本轮完成数据库脚本及隔离验证。当前代码没有新表DAO、上行/往返状态机、0.5m选点器、全流摘要事务保存器、周期任务、持久审计调用或新版历史Controller，建表不会自动产生数据。后续沿PLC快照→上行/往返识别→选点与摘要事务→历史查询/统计→Controller逐段接入。
