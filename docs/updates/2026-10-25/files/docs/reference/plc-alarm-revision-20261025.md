# 分解槽抑制结疤智能体平台 PLC告警事件与红字修订统一说明

修订日期：2026-10-25。依据：本次提供的Word红字、当前页面代码，以及本次明确的PLC、后端、前端分工。交付格式为Markdown，Word原件未修改。

**PLC负责判断拉力状态，后端负责整理、保存并更新事件，前端负责展示。同一次持续越限始终使用同一个alarmCode；采样更新、事件升级、页面刷新都不能新增一次告警。**

本次前端已经增加独立最新/历史查询、事件编号去重和版本保护、侧栏红点、阈值编辑、请求提示收敛，并明确历史单绳极值。新增生产接口仍需后端实现及PLC联调，浏览器中的DEV演示不代表真实现场已接通。

## 1. 红字如何统一落实

Word共提取到9处含红字段落，其中包括告警目录行的3个标记单元格；结合相邻新增文字，整理为下列7项要求。红色表示需要理解和修订，不等于整段内容全部删除。

| 红字要求及原意 | 当前前端处理结果 | 后端或现场仍需配合 |
| --- | --- | --- |
| 告警中心进来就看最新，只按普通/严重筛选，展示PLC错误 | 默认最新告警；两等级勾选；原样显示错误内容；历史单独查询；不再展示旧统计卡、类型筛选和处理结果 | 实现独立最新/历史服务，直接提供PLC事件等级、原文和过程字段 |
| 故障需要侧栏红点，普通读数变化不能自行变成告警 | 告警中心图标增加红点，仅读取最新接口hasAttention；进入页面不会清除 | 由后端根据PLC事件或已确认连接事件给出hasAttention，不用页面“已读”代替现场状态 |
| 去掉旧告警路径，说明旧周期链接代表什么 | 移除旧`/command-center/alarms/:systemCode`路由；导航统一到`/cloud/alarms?systemCode=...` | 旧DAY/MONTH/QUARTER/HALF_YEAR/YEAR代表旧日/月/季度/半年/年汇总详情，仍返回单次记录列表，避免把它们误当现有页面 |
| 认证刷新及失效跳转需要修正 | 失效跳转`/login`；并发401共享一次刷新；消费新token、可选新refreshToken及expiresIn；失败不让等待请求悬挂 | 约定令牌轮换、有效秒数和失败码，后端继续做每次资源授权 |
| 连续操作只提醒一次，不持续弹提示 | 相同在途写请求阻止重复发送；首个重复操作提示“请勿频繁操作”，持续操作期间不反复提示；网络/业务重复错误也合并提示 | 真正的频率上限由后端按账号/接口判断；HTTP或业务429统一提示，不能仅依靠浏览器限制 |
| 两根钢绳预警、安全保护值需要可修改，判断交PLC | 动力详情新增修改阈值弹窗；编辑两路阈值、保存或取消；只有APPLIED回执更新生效值，PENDING保持原值 | 后端持久化、授权、下发PLC并获取生效确认；PLC按实际生效参数判断状态 |
| 历史最大/最小到底是8根还是单根 | 列表、详情明确为“单绳最大/最小拉力”，增加范围说明 | 后端返回本轮全系统8路单绳的有效采样极值，不是8路相加，也不随图表选择改变 |

## 2. 采样与事件分开

| 数据 | 产生与保存方式 | 前端用途 |
| --- | --- | --- |
| 实时拉力、高度、速度、方向 | 按真实采样节奏保存/推送，与浏览器是否打开无关 | 更新首页读数、设备快照与曲线 |
| PLC普通/严重错误信号 | 后端整理为有唯一编号、起止时间和更新版本的事件 | 新编号出现一条；相同编号更新原行和详情 |
| PLC连接异常 | 后端连接监测确认后形成明确事件，来源可标PLATFORM | 显示所属现场设备；浏览器请求失败不创建此事件 |

PLC没有发出告警信号时，即使后端收到一条看起来很高的拉力采样，也不能自行比较阈值新增故障事件。前端修改阈值、切换吨/公斤、刷新、打开详情同样不产生告警。

“普通”指PLC已经上报的普通事件等级，不是前端对一切波动附加的告警。一般信息提示与需要保存的PLC错误事件应按现场约定区分，不能把普通读数变化都塞入告警中心。

## 3. 一次持续过程只保存一个事件

以下为目标事件流程示例，描述后端应维护的事件身份，不表示当前前端已经实现PLC信号采集或后端状态机。

| 现场信号 | 后端保存 | 前端展示 |
| --- | --- | --- |
| 动力二号首次普通越限 | 新建A，记录开始时间，revision=1 | 新增一条普通事件 |
| 普通信号持续 | 更新A的更新时间及过程数据，revision递增 | 更新A，条数不变 |
| PLC将本次过程升级严重 | 更新A的等级/内容及最高拉力，revision递增 | 同一行改为严重，不新增第二条 |
| PLC明确本次越限结束 | 更新A的eventState=ENDED、endedAt和版本 | A保留在近期/历史；不新增结束事件 |
| 后来再次出现新的越限过程 | 创建新编号B | 新增另一条 |

**ENDED/endedAt表示现场这次过程结束，不代表工人在平台确认、处理或恢复了告警。** 页面没有确认、处理、恢复、消警按钮；关闭详情仅关闭弹窗。

若PLC提供事件编号，应沿用并纳入系统/控制器命名空间。若只提供普通/严重状态，后端必须依据开始、变化、结束信号维护编号；“严重降为普通但仍持续”是否属于同一过程应现场确认，不能单凭新拉力值拆分事件。

后端内部应保留传感器通道、控制器会话等标识，以区分同一动力设备下同时发生的不同过程。不能只按deviceCode把两条不同通道事件合为一条。页面仍仅显示所属动力设备，不展开内部通道或组件。

## 4. 事件字段约定

当前扩展沿用`CommandCenterAlarmItem`。为兼容既有数据，部分新字段在TypeScript中允许缺省；正式后端应保证编号、等级、内容、开始时间，以及用于更新顺序的版本/更新时间真实可靠。不能把“类型可缺省”理解为可以省略过程身份。

| 字段 | 含义及使用 |
| --- | --- |
| alarmCode | 稳定事件编号；A持续、升级和结束均不变；B必须是新编号 |
| systemCode、deviceCode | 所属系统和动力设备；页面按设备定位，不暴露内部部件 |
| deviceName? | 可选设备实际名称；现有标准设备编号也支持中文名称映射 |
| source? | PLC现场错误；PLATFORM仅用于后端已确认的PLC连接监测事件等明确来源 |
| runCode? | 所属运行轮次；跨轮连续过程的归属规则需另定，不以轮次改变自动换事件编号 |
| level | NORMAL普通、SERIOUS严重；旧MEDIUM当前兼容显示普通；不按拉力值推算 |
| type、content | 事件类型、PLC错误内容；前端不依据阈值或旧恢复状态改写错误文本 |
| occurredAt | 事件开始时间；持续更新不能反复改成“新发生” |
| updatedAt?、revision? | 本次事件更新时间、单调递增版本；防止迟到旧响应覆盖新状态 |
| eventState?、endedAt? | ACTIVE进行中/ENDED结束，实际过程结束时间；不是人工处理结果 |
| triggerValue?、peakValue?、peakAt?、unit? | 触发拉力、过程最高拉力及其时刻、t/kg；缺失不填0，也不拿触发值猜最高值 |
| threshold?、thresholdKind? | 发生时阈值及WARNING/PROTECTION类别；不从严重等级猜是哪条阈值 |
| direction?、occurredHeight? | 发生方向UP/DOWN/STOP、发生高度m，辅助结合曲线分析 |
| sensorCode?、sourceGroupNo?、sourceMetric? | 内部来源定位信息，可保留供后端关联，告警列表不展开 |
| state、handling、recoveredAt? | 旧数据兼容字段；当前告警页不展示处理/恢复流程，不用它们代替eventState/endedAt |

前端按alarmCode保留一条。revision不同且两者都有效时取更大版本；版本相同或缺省时再按updatedAt/occurredAt比较。最高拉力由PLC直接给出，或由后端在PLC已判定的事件窗口内整理有效采样得到；这类统计不等于后端重新比较阈值判断故障。

最新接口返回完整近期集合，前端只保留本次集合的成员，不把已经移出窗口的历史记录补回来。相同成员的旧版本不能回滚已见的新版本。打开的详情也按同编号和版本选择最新信息，不会因历史列表和近期缓存顺序不同而退回旧普通状态。

## 5. 独立最新查询

`GET /command-center/alarms/latest`，相对API基础地址；默认基础地址为`/api`。

| Query | 约定 |
| --- | --- |
| systemCode | 必传，当前系统 |
| deviceCode | API支持可选；当前共享订阅读取整套系统，页面本地选择所属设备 |

**不传TODAY、开始/结束日期或历史页码。** 后端返回现场实时/近期完整集合，包含跨日仍持续的事件；不能只取今天开始的记录。近期结束事件保留多久，由后端明确窗口。

| data字段 | 约定 |
| --- | --- |
| systemCode | 与请求系统一致 |
| asOf | 后端快照时刻，明确时区 |
| recent[] | 独立实时/近期事件完整集合，按编号更新 |
| hasAttention | 后端给出的侧栏关注标记；前端不从拉力、故障颜色或已读状态推断 |
| demo? | 演示标识 |

以下为契约示例，不是已接入PLC的现场记录：

```json
{
  "code": 200,
  "message": "数据获取成功",
  "data": {
    "systemCode": "QJXT-01",
    "asOf": "2026-10-25T09:02:00+08:00",
    "hasAttention": true,
    "recent": [
      {
        "alarmCode": "EXAMPLE-A",
        "systemCode": "QJXT-01",
        "deviceCode": "WJ-02",
        "source": "PLC",
        "runCode": "RUN-20261025-1",
        "type": "拉力事件",
        "content": "PLC上报的严重拉力错误原文",
        "level": "SERIOUS",
        "occurredAt": "2026-10-25T09:00:00+08:00",
        "updatedAt": "2026-10-25T09:02:00+08:00",
        "revision": 3,
        "eventState": "ACTIVE",
        "triggerValue": 0.91,
        "peakValue": 1.28,
        "unit": "t",
        "direction": "UP",
```

后续结束时仍返回EXAMPLE-A，仅更新revision、updatedAt、eventState及endedAt等字段。eventState是过程状态；示例保留的旧state/handling用于现有类型兼容，不增加任何人工操作入口。

侧栏与告警页共用同一份最新快照，首次订阅立即读取，页面可见时每15秒读取；多个消费者共用一个轮询和同一在途请求。最后一个消费者离开时停止轮询并取消在途请求；切系统先清除旧系统快照，迟到响应不能串系统。

最新页默认展示最新集合，可勾选普通/严重，按开始时间倒序，当前每页10条在前端分页；严重等级不会把旧事件强行排到新事件前面。后台更新第一页记录，翻到后页时保留当前查看快照以避免列表跳动；详情仍按共享最新版本读取。最新为空时显示空态，不拿历史查询补足。

## 6. 独立历史查询

`GET /command-center/alarms/history`。

| Query字段 | 约定 |
| --- | --- |
| systemCode | 必传 |
| deviceCode | 可选所属动力设备 |
| range | TODAY / 7D / 30D / CUSTOM；历史页默认30D |
| startDate、endDate | CUSTOM必传，YYYY-MM-DD，按上海发生日期首尾包含；页面范围1～366天 |
| levels | 逗号分隔NORMAL、SERIOUS，例如`NORMAL,SERIOUS`；不选等级应得到空结果，不能默认变成全部 |
| page、pageSize | 正整数，页面从1开始，每页10条 |

后端先按日期、等级、所属设备筛选，再稳定排序、分页。返回`data: { systemCode, asOf, historyRange: { startDate, endDate }, list, total, page, pageSize, demo? }`。total是筛选后的全量事件数，不是当前页条数；同一事件的持续、升级、结束不能各算一次。

CUSTOM必须回显实际执行的相同日期范围。页码/每页大小须与请求一致；前端拒绝跨系统记录、重复编号和不完整分页结构。历史列表不从recent补入其他范围的数据，切历史不把该页数据写回最新集合。页码、等级、日期或设备条件改变时重新请求，不在一页结果上冒充全量筛选。

最新页与历史页都只读：表列为发生时间、等级、告警内容、所属设备、查看详情。详情增加开始/更新/过程结束时间、运行轮次、触发/最高拉力、方向和高度等已有字段；字段未提供时不补造。页面没有内部部件列表及确认/处理/恢复按钮。

请求失败保留已经读到的记录并提示“当前显示上次加载的记录”；首次失败显示重试。浏览器网络失败、401或HTTP超时均不能由前端新增“PLC离线”事件。红点在失败时保留上次后端值，点击告警中心、切等级和关闭详情都不清除。

## 7. 阈值修改与PLC生效确认

动力详情“拉力数据”标题旁新增“修改阈值”。弹窗使用当前设备两路实际sensorCode，分别编辑alarmThreshold预警值和safetyValue安全保护值；输入固定为吨t，不受外部图表kg切换影响。

前端仅校验配置输入：两路来源编号完整且不重复、数值有限且大于0、每路预警小于保护。不把图表1.4t/3t上限当成物理安全上限。取消不写入，保存期间禁止重复提交和关闭，失败保留草稿。

新增生产契约为`PUT /command-center/winch/tension-thresholds`：

```json
{
  "systemCode": "QJXT-01",
  "winchCode": "WJ-02",
  "thresholds": [
    { "sensorCode": "PS-03", "alarmThreshold": 0.8, "safetyValue": 1.2 },
    { "sensorCode": "PS-04", "alarmThreshold": 0.8, "safetyValue": 1.2 }
  ]
}
```

返回统一code/message/data。data包含systemCode、winchCode、status、可选effectiveThresholds、configurationVersion、demo。

| status | 含义及页面处理 |
| --- | --- |
| PENDING | 已接受修改申请，尚待PLC生效；继续展示原已生效阈值，不能把提交值直接覆盖 |
| APPLIED | 后端已获得PLC生效确认；必须返回对应两路完整effectiveThresholds，页面按实际生效快照更新 |

configurationVersion只能是后端实际配置版本，不由前端伪造。回执身份、两路来源或数值不完整时，不覆盖当前快照。PENDING之后通过重新读取设备详情取得真实生效配置。

DEV保存使用按systemCode＋winchCode隔离的localStorage，只覆盖阈值；首页与详情按来源编号读取演示配置。读数、运动、平均值、状态及告警事件不随编辑重新计算。演示提示“演示阈值已保存”，不表示已向真实PLC下发；生产不读取浏览器演示配置。

## 8. 登录失效和频繁操作

认证失效跳转已统一为history路由的`/login`，不再使用`/#/login`。多个401共用一次刷新，等待请求均在成功/失败/取消后结束；请求只自动重试一次，登录和刷新接口不递归刷新。

刷新成功保存新token；后端提供有效新refreshToken时同步更新，缺省时保留原值；有效expiresIn按秒记录本地到期时间。刷新期间用户已切换会话时，旧刷新响应不能覆盖或清除新会话。这些是会话控制，不代替后端权限校验，也没有新增页面倒计时。

相同方法、路径、参数和请求体的在途POST/PUT/PATCH/DELETE，保留原操作、取消重复发送；第一次重复提示“请勿频繁操作”。持续点击时同类提示只显示一次，安静3秒后才允许再次提醒。原操作结束后可正常发起下一次；不同条件的合法请求不被当作同一操作拦截。

只读请求保留取消旧重复请求及调用方取消信号的机制，历史导出分页和共享最新轮询不弹“频繁操作”。后端HTTP/业务429也使用同一提示收敛。真正的请求频率限制仍需后端实施，不把在途去重说成完整服务端限流。

## 9. 历史单绳最大最小值

列表与单次概况使用后端`entry.maxTension/minTension`，文字明确为单绳最大/最小拉力。范围是**本轮全系统8条单绳的有效采样集合**：从中取一个最大值和一个最小值。

例如8根钢绳在整轮中出现过的最大有效采样为1.26t，页面最大值就是1.26t；不是把8路读数相加。极值可能来自不同钢绳或不同时刻，不要求最大和最小属于同一通道；也不是仅取当前图选中的动力二号。独立伺服和双绳派生合计不纳入这项单绳极值。

图表设备/来源选择、鼠标位置不重算这两个系统运行头字段；kg切换只换显示单位。历史导出列名同步表明单绳极值。有效质量与采样范围仍由后端给出统一口径。

## 10. PLC现场对接前必须确认

| 需要确认的问题 | 对事件保存的影响 |
| --- | --- |
| PLC能否提供稳定事件编号 | 有编号可沿用；否则后端必须收到可靠的开始、变化、结束信号才可维护过程 |
| 普通、严重信号的具体语义 | 明确哪些是普通提示、哪些是应保存事件；等级变化时是否同一过程；level代表当前等级还是过程最高等级 |
| 两个钢绳通道同时越限如何区分 | 后端内部保留通道/错误类型身份，不能按动力设备名称合并不同过程 |
| 结束信号何时发出 | 由现场过程结束决定，不能以页面关闭、一次读取失败或普通状态缺失推断结束 |
| PLC重启后编号和序号是否复用 | 需要控制器会话/启动标识或后端命名空间，避免把新过程覆盖旧记录 |
| PLC断联、补传、重复上报如何处理 | 断联不自动结束原过程；恢复后按原编号/版本去重和补数；连接事件与拉力事件分开 |
| 一次越限跨越两轮上下运行怎么办 | 不能仅因runCode变化换编号；需明确主归属及是否记录关联的多个轮次 |
| 采样与事件时钟、单位是否一致 | 定义时区、时间精度、t/kg、方向与高度来源，保证可与曲线关联 |
| 阈值修改如何确认生效 | 后端何时可以返回APPLIED、PLC回执/实际配置版本及并发修改规则 |
| 最新窗口与hasAttention口径 | 跨日进行中事件必须保留；近期结束事件保留期限、何时亮/灭红点由后端明确 |

在这些信号未确认前，不能声称后端能准确合并所有现场过程。已经实现的前端编号更新与版本保护只是接入基础，不替代PLC事件协议。
