新版逐点表及来源见[拉力对比处理方案](detail-force-comparison-processing.md)，事件及阈值规则见[PLC处理说明](plc-alarm-and-threshold-processing.md)。依据为[全部页面新版](reference/frontend-pages-report-20261025.md)及[PLC红字修订](reference/plc-alarm-revision-20261025.md)，不再以旧统计双表解释当前图形。

边界不变：生产上行与回退/检修上行分别标识，正常下行不保存连续测量，下行异常只留事件点。采集数据不做时间校验，时间只用于已有的记录、查询、曲线和统计。

## 1. 用户如何使用导出

在历史列表、单次详情、告警/异常列表和已有归档统计视图提供对应导出入口。所有请求、响应、文件名称以实际公开systemCode归属系统，动力设备用winchCode、测点用sensorCode；后端解析内部system_id/deviceId等关联，不让前端提交内部表名或固定写QJXT-01。默认导出已提交的查询范围；还没点击查询的日期草稿不影响任务。

- 列表“导出”：导出当前设备、日期、结果等筛选范围的全部记录，不只是当前页10条。
- “导出选中”：只有明确勾选时，冻结实际recordCodes/eventCodes，不把当前页默认当选中范围。
- 单次“导出本次数据”：使用实际recordCode，导出本次已经保存的明细，不因图表隐藏某台设备或来源而漏掉。
- 周期“导出统计”：导出已保存的周期结果；高度平均曲线使用独立明细文件，不与原始采样混称。

页面默认拉力单位t，库内仍kg；导出冻结用户提交的t或kg，并由后端转换、计算、生成最终列。之后切换页面单位不会改变已生成文件。实际名称、最终状态和中文说明、总拉力、均值、极值、事件数和比较结果均由后端提供，前端不重新推导后再写CSV。

新页面JSON保留必需可空字段并显式返回null；CSV中缺值为空单元格，并保留必要质量/原因列，有效0正常输出。常规列使用服务端固定业务模板，前端不提交物理表名、SQL或任意数据库列。

## 2. 四类导出分别生成什么表格

| 导出类型 | 一行表示什么 | 数据来源 |
|---|---|---|
| RUN_LIST，运行列表 | 一条上行运行记录 | cleaning_run_record及身份/异常摘要 |
| RUN_SAMPLES，上行明细 | 一次真实采集帧中的一台已归档动力设备 | cleaning_up_sample及记录身份快照；内部任务类型可继续UP_SAMPLES |
| EXCEPTIONS，异常事件 | 一次异常；必要快照另表展开 | cleaning_exception_event |
| PERIOD_STATISTICS，周期统计 | 一条系统/单机周期结果；高度桶另表 | cleaning_period_summary和cleaning_height_bucket |

页面exportType统一使用RUN_LIST、RUN_SAMPLES、EXCEPTIONS、PERIOD_STATISTICS；RUN_SAMPLES在后端映射内部UP_SAMPLES，不改变只保存上行的事实。具体请求字段见[接口说明](external-api-contract.md)。这是业务表格导出，不是数据库备份或将物理表SELECT全部列交给用户。各文件的粒度和单位明确，列表摘要文件不能称为原始采样文件。

### 2.1 运行列表文件

| 导出列 | 口径 |
|---|---|
| 序号、systemCode、系统名称、运行记录编号 | 使用本次实际系统及当时身份快照；序号仅为本次文件顺序 |
| 实际开始/结束、首次/最后观测时间 | 未确认实际边界为空，不能拿观测时间冒充 |
| 记录历时秒、格式化时长 | 与页面口径相同，不等于电机有效运动时长 |
| 过程状态、运行结果、终止原因及中文说明 | 直接使用后端结论，进行中/未确认保留原意，不一律显示正常完成 |
| 模式、已知启动方式及文字 | AUTO不等于定时启动，无来源为空 |
| 本次设定速度、运行间隔及配置来源 | 使用运行开始时真实参数快照，不用当前配置回填旧记录 |
| 异常事件数 | 不是处理尝试数，缺少尝试明细不补0 |
| 单绳最大/最小拉力及单位 | 本次生产UP全系统8条单绳有效采样集合的单个极值，不相加8路，不随当前所选动力设备/图例变化；不含电机、合计、回退/检修、下行快照 |
| 数据完整说明 | 已知缺口和边界未确认说明 |

进行中记录不填写未来结束时间；若显示截至快照的历时，列名必须说明截至快照，不冒充已结束总时长。单绳极值缺通道或观测有缺口时保留覆盖说明，不宣称取得所有未观测部分。附件无来源的五次处理次数不作为本版导出列。

### 2.2 上行原始明细文件

支持单次recordCode，也可在明确范围内导出多次上行。默认包含请求范围内实际保存的上行用途，逐行标识PRODUCTION_UP、RECOVERY_UP、MAINTENANCE_UP或UNCLASSIFIED_UP；若用户明确选择仅生产，作为筛选写入任务说明。

| 列组 | 导出列 |
|---|---|
| 归属 | 系统、recordCode（可空）、动力设备编号/名称、分组、采集实例、序号、采样帧标识 |
| 过程 | 采集时间、本机连续分段、本机运动用途、UP方向 |
| 测量 | 本机高度m、独立速度/同步速度及适用来源、钢绳1/2拉力、配对总拉力、电机等效力 |
| 质量与来源 | 各通道质量、实际钢绳/传感器身份、原始状态码、必要驱动原值和换算规则 |

一帧四台均归档时最多展开四行，不按每根绳拆成重复设备行；其他正常下行设备不被顺带导出。每行两索与电机来自明确对应的本机帧，缺失测量留空并保留质量，有效0保留。

配对总力由后端按已确认采集关联和本机两根独立有效钢绳计算，页面/文件来源名为ROPE_TOTAL，内部统计标识可继续PAIRED_SUM。统一使用sampleKey代替此前拟议pointKey，另保留真实sampleFrameId；不能只按相近时间或相同高度拼两路，也不新增猜测的时间容差或采样年龄校验。总力速度来自同帧本机已确认适用速度，不能相加两索速度或默认抄钢绳1；未知留空并保留原因。同步速度不标成四个独立速度，电机等效力不标成N·m。无高度的有效拉力仍保留在原始明细，不能因画不了高度曲线而从导出删除。

sampleCount用于表达测量有效数量：原始有效为1、无效为0，聚合为真实有效数；缺字段不默认1，GOOD/PARTIAL也须有测量有效依据。计算使用原始精度，导出单位换算后按模板格式化，不相加已经显示的两位字符串。全系统单绳极值、配对总力极值和伺服极值分别命名。拉力与速度各自保留质量，拉力缺失不自动删除仍有效的速度，不能从一条笼统quality补造其他通道。

### 2.3 异常事件包

`events.csv`在执行时一致快照中每个eventCode/alarmCode一行，含系统、所属设备、内部来源追溯、可空recordCode/runCode、source、PLC原文/实际等级、发生/首次观测/更新时间、revision、eventState和endedAt。同号持续、普通升级严重和结束均为一行最新快照，不展开成三次告警；后续新过程的新编号另算一次。ENDED说明现场过程结束，不把它导出成“人工已处理/已恢复”。

同时导出已知triggerValue、peakValue、peakAt、peakSource、peakCoverage、direction、occurredHeight，以及触发时threshold/thresholdKind/配置版本。PLATFORM仅用于后端已确认的连接监测等明确事件。后端不比较采样和数据库阈值新建故障；新参数PENDING/APPLIED不改写事件当时阈值，当前参数不能回填旧触发。没有峰值依据留空，不能拿triggerValue当整个过程最高值，也不凭严重等级猜保护阈值。

`event_snapshots.csv`按事件、必要阶段（触发/明确结束/已知峰值）、本机与真实采集帧展开有限事件点。原有业务若另有真实恢复/终止审计，可在明确列保留，不混作当前人工操作。没有现场读数不造0行；没有可靠运行关联仍可导出。DOWN事件可保留增量观测峰值及有限峰值点，但不写连续下降采样；peakCoverage为部分时不能声称完整全程峰值。

告警历史筛选来自`alarms/history`，非告警独立事件来自`events/history`，导出冻结各自实际筛选范围与稳定编号，不从latest的当前数组冒充全部历史。告警CUSTOM首尾日期包含，后台转上海开始日零点至结束日次日零点右开区间，并在任务/文件说明中写明。正常DOWN不补存，D3=13的设备归属不擅自改成电机4，D3=50不生成五次处理明细。

### 2.4 周期统计包

- `period_summary.csv`：系统/单机、DAY/MONTH/QUARTER/HALF_YEAR/YEAR、周期边界、运行各结果数量、唯一过程事件数量、已确认生产UP时长、原始均值/瞬时极值及有效数、数据覆盖、计算版本与待更新说明。
- `height_average.csv`：周期、本机、来源角色、sampleKey、高度桶边界、有效数量、数值之和、平均值、桶内原始最小/最大、速度及独立有效数、规则版本。

最新图形删除右侧均值/极值双表，不再强制导出或页面返回statistics/rawStatistics/ropeExtrema/defaultUnitId对象。已持久保存的摘要和高度桶继续可导出；如报表明确需要“最高/最低平均”，从完整基础桶均值集合取极值、另设列，不与原始瞬时峰值共列，也不从当前显示缩减点反推。采样数与参与运行数分别命名；不平均平均值，不相加每日参与数或同号事件revision当多次。

原始明细继续包含请求范围内所有已存UP用途，不能为了与生产统计数量一致删除回退/检修或缺高度原始。SYSTEM无独立依据的有效运动时长为空；统计尚未构建时说明未构建，不把占位行当0。图例、鼠标曲线、当前已加载页和显示单位都不改变已经冻结的任务范围。

导出读取已保存统计版本，不为文件生成重扫全年原始帧。当前周期保留实际覆盖/进行中说明；平均桶不冒充现场采样。归档比较若纳入文件，写明左图、当前、参考的完整范围及对齐口径；变化率后端计算，参考为0或不足以比较时留空并说明。

## 3. 统一使用后台导出任务

```text
页面提交已确认筛选和模板/单位
  → 大厅/安全检查 → 清洗服务编排
  → 统计服务内部导出器创建任务
  → 后台读取同一数据快照，分批写临时文件
  → 所有部分完整后发布CSV或ZIP
  → 导出记录列表显示完成 → 用户下载
```

四类导出共用这条流程。小范围可以很快完成，大范围继续后台执行，不另设计让浏览器循环分页拼表的路径。用户关闭页面后任务继续，重新进入可查看导出记录。

新附件报告前端CSV仍本地生成，没有现成后端文件接口；此前建议的GET history/export不作为另一条正式路径。结合已明确的导出记录需求，继续使用统一后台任务：

| 目标接口 | 输入与结果 |
|---|---|
| `POST /api/command-center/exports` | systemCode、exportType、已提交范围/recordCode、单位；返回已受理任务 |
| `GET /api/command-center/exports` | systemCode及分页/筛选；返回当前账号导出列表 |
| `GET /api/command-center/exports/{taskCode}` | systemCode及任务编号；返回真实阶段、范围、行数和已发布文件 |
| `GET /api/command-center/exports/{taskCode}/files/{fileCode}` | systemCode、任务、文件编号及鉴权；成功直接返回CSV/ZIP文件流 |

这里均是待实现路径，不继续把`/api/cleaning/devices/{deviceId}/exports`写成未来页面契约。普通任务响应使用code/message/data，文件下载成功使用文件流及Content-Disposition；失败在开始文件流前返回明确说明。

仍然只有清洗、命令、安全、统计四个业务服务；导出归统计模块内部辅助类和上层登记的后台任务，不增加第五个清洗业务服务，不让DAO回调上层，也不占用PLC读写线程。

## 4. 导出记录列表如何展示

可先在现有页面提供“导出记录”面板，列表分页读取，不要求同时建设新的完整导航页面。

| 列/操作 | 含义 |
|---|---|
| 任务编号、类型、查询范围、单位 | 本次导出的实际对象和固定条件 |
| 创建时间、数据快照时刻 | 排队提交和真正取数不是同一时刻 |
| 状态 | QUEUED排队、RUNNING生成、SUCCESS完成、FAILED失败 |
| 当前阶段、已处理行数 | 无可靠总量时不显示假进度百分比 |
| 文件数量、总行数、大小 | 文件行数不是运行次数，不同粒度分别计数 |
| 完成时间/错误原因 | 不给用户数据库堆栈 |
| 下载/重新生成 | 成功可下载；失败重做或成功后重新生成，得到新快照 |

默认查看登录账号创建的任务；创建、列表、下载都遵循当前系统和数据访问权限，不能仅知道taskCode就下载他人文件。

行数指数据行，不含表头。多文件的合计仅称总输出行数，各文件仍分别标识记录、设备帧、事件或高度桶粒度。

## 5. 增加一张技术表记录任务

现有设计为10张目标业务表。导出记录需要持久保存，再增加`cleaning_export_task`技术表，即目标10业务表＋1导出任务表；统计重算仍复用周期表标记，不另加统计任务表。当前实际7表不因本文发生变化。

| 字段组 | 建议内容 |
|---|---|
| 身份 | 内部id、唯一task_code、creator_user_id、system_id |
| 类型与范围 | export_type、filter_snapshot（有限JSON：已提交日期、记录选择、设备、结果、用途等） |
| 模板 | column_version、unit、file_format，固定表格列与单位 |
| 状态 | status、phase、processed_rows、实际output_rows；多文件行数分别记录 |
| 快照 | snapshot_at、必要统计/规则版本说明 |
| 文件 | file_manifest（文件名、粒度、数据行数、大小、存储键、校验值）、总大小、物化完成标记/版本 |
| 结果 | error_code/error_message、created_at/started_at/finished_at |

主键和task_code唯一键；列表索引建议`(creator_user_id, created_at, id)`，后台取任务使用`(status, created_at, id)`。文件内容存在持久文件存储，不以数据库大BLOB保存，也不在任务表复制全部原始采样。

任务账号从真实登录身份取得。公开systemCode由后端核验并解析内部system_id；任务保存提交时身份/显示名称及选择范围，保证文件归属可追溯。内部存储路径不作为任意文件访问路径由前端传入；下载按任务定位对应文件。本轮只确定页面目标路径，不声明接口已经存在。

## 6. 保证一个文件里的数据版本一致

点击时冻结筛选和单位，后台工作者真正开始取数时建立数据快照并记录snapshot_at。排队期间新增但符合范围的记录可以进入执行时快照；“导出当前查询范围”不承诺重现之前屏幕瞬间的全部字段值。明确选中记录时成员由recordCodes固定，内容仍按执行快照读取。

运行结果、事件等级/峰值/结束及revision、采样用途修正和周期汇总都可能更新。因此仅固定maxId、created_at、总行数甚至ID清单，只能限定成员，不能保证内容版本一致。

初版使用同一个MySQL REPEATABLE READ一致性读事务读取所需事实/统计，按稳定键分批查询并流式写临时文件；所有列来自同一快照。主记录与明细、事件快照、身份及规则也需同快照读取，不能后面再向实时表补列。任务进度等元数据由独立事务更新。

分批查询控制内存，不自动缩短这笔一致读事务。应设置导出并发与单任务规模预算；首版可用独立导出工作者顺序执行，避免与PLC采集争用资源。过大范围分文件并不意味着可悄悄换快照；超预算应说明需要拆分范围，不输出残缺文件。

一致读事务另有执行/持有预算，超预算终止本次快照并提示缩小范围，不能靠无限分片长期占用事务。快照内容完整落盘后结束读事务，最终ZIP打包在事务外执行。这是执行资源预算，不是校验采集时间或判断数据过期。

如果大范围分两阶段生成，先在一致快照中将最终列值/明确原版本完整物化为持久临时文件，再关闭读事务，在快照文件上完成格式化和打包。不能只物化ID后重新从变化中的表取值。

这些是导出执行和版本规则，不是校验采集时间；不会因数据早、晚、延迟入库而判无效。导出后补入或修正的历史在新一次导出体现，不悄悄修改已下载文件。

## 7. 文件格式、分片和下载

沿用附件UTF-8 BOM CSV，Excel可直接打开；一张业务表一个固定列结构。单文件返回CSV，多表或多分片用ZIP，附说明文件列出筛选、单位、时区、快照时刻、各文件粒度/行数、统计版本和缺口。

原始明细建议按行数和文件大小切片，例如初始按每片50万数据行规划，最终经测量确定。CSV格式本身不受Excel工作表行数约束，但Excel打开有行数上限，分片用于避免用户查看时截断，绝不是数据库只能存50万条。

读数据库、写文件、打包均采用有界缓冲/流式处理，不一次将全部行放入Java集合。发布顺序为：私有临时文件可靠写完并关闭→清单/数据行数/校验值核对→原子发布最终文件或完成清单→短事务将任务标为SUCCESS。行数按本次实际读取/写出计数核对，不要求为进度额外COUNT全表。未完成文件没有下载入口，不能先SUCCESS再落文件。

下载接口流式输出文件，前端不解析CSV成全部行、不用全部数据数组拼文件。大文件下载适配也需支持边接收边保存，不能仅把服务端流改成前端fetch.blob全量缓存。沿用登录授权，访问令牌不放URL。

列名写清单位和北京时间；缺测空白、有效0保留，CSV正确转义逗号/引号/换行，外部文本避免被表格软件当公式，合法数字仍按数值输出。文件名包含实际systemCode、类型、范围/recordCode和taskCode，不只使用可能重复的日期，也不固定套QJXT-01。

## 8. 失败、重启和重新生成

| 情况 | 处理 |
|---|---|
| 读取或文件写入失败 | FAILED并保存可读原因，不发布半文件 |
| 中断前快照未完整物化 | 原快照不能跨重启恢复，丢弃半成品；重新生成建立新快照，不拼接两次读取 |
| 最终列值已完整物化且有完成标记 | 可从这份不变数据继续文件生成，不能回实时表补行 |
| 服务重启 | 恢复任务列表，识别未完成任务，按物化状态重做或明确失败，不能一直显示假运行中 |
| 文件已发布但SUCCESS尚未提交 | 恢复时核对完成清单，补齐任务发布状态或回收未被有效任务引用的孤儿文件，不将半成品当成功 |
| 生成后数据补入/修正 | 保留原文件，新建任务重新生成；两个快照时刻分别显示 |
| 文件不存在/损坏 | 明确不可下载，可重新生成，不报告下载成功 |

首版不实现复杂断点续读：未完成物化的任务重做即可。派生文件的保留/清理策略需另外明确，本版不增加自动过期；可清理失败临时文件，不删除数据库历史。

## 9. 页面、数据库与文件的一致口径

运行摘要、原始上行、唯一过程事件及有限事件点、高度平均分别保留粒度。列表筛选与导出模板复用同一业务查询规则；PLC负责拉力状态，后端整理过程、统计和身份，前端不重新推断后写文件。单位只转换一次，原始/生产用途不混，配对总力不伪造，未知工时不补0。

验收应覆盖：实际systemCode/名称无硬编码；筛选范围跨页仍完整；勾选记录只导出选中项；图表隐藏不删原始明细；下行只有事件点；分段和用途能追溯；当时参数/阈值不被当前配置覆盖；ROPE_TOTAL及统计不由前端重算；补传/结果变化不混版本；同号持续/升级/结束只一条、事件峰值覆盖真实、ENDED不伪称人工恢复；无效值与0区分；未知工时为空；分片行数合计正确；半文件不可下载；重启不假成功；普通页面不加载全量数据库行。

本轮只补导出列表、列模板、快照、任务表和文件流程设计，没有新增表、接口或运行任务。具体源业务仍依赖前述上行历史与预计算链路实施。
