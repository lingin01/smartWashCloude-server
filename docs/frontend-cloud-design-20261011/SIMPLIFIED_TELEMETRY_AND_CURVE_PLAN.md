# 拉力上传与曲线筛选简化方案

日期：2026-10-11。状态：讨论与后续实施设计，不是已实现接口或已执行建表。

更新说明（2026-10-12）：本文件中的0.1m分桶、正常上下均留点及单独points[]/点表属于旧建议。当前讨论调整为500ms采集、正常上升0.5m真实留点、下降异常记录，优先复用records[]和历史三表；完整字段及待确认条件见 [完整数据流程与字段合同](END_TO_END_DATA_CONTRACT_20261012.md)。原方案保留作参考，不据此修改代码或重复建表。

依据同目录 README、CommandCenterContractDraft.java、cleaning_page_schema_draft.sql，以及盒子当前 command_service.cpp 的实际 JSON。原 41 个模型和追加 16 张表保留作完整参考，不要求第一阶段全部实现；本稿没有删除它们或修改运行代码。

## 1. 先确定最小目标

先做首页、单机详情、自动清洗轮次列表及拉力/速度趋势。核心对象只有三种：最新快照、自动作业轮次、该轮保留的测量点。

连续自动作业是一次 session；一次下降和上升是该 session 的一个 round。显示“今日第 3 次清洗，开始/结束时间”，内部仍以 sessionId+roundNumber 关联。单机检修不能算清洗轮次。

不先做任意指标混合、任意时间拼接、独立转矩换算曲线、复杂异常处理轨迹或全套预计算周期表。签名/固定校验码按既有独立交互方案处理，不与曲线查询对象混在一起。

## 2. 上传：保留摘要，增加真正的曲线点

### 2.1 当前最重要的缺口

| 来源 | 当前实际情况 | 最小处理 |
|---|---|---|
| 实时消息 | 2.0 已有 status、8 路索、4 路绞机及组平均 | 补圆环高度/有效性、真实方向/模式/轮次、单位，修正云端解析 |
| 历史消息 | 目前只发送分段时间、高度、状态和方向，没有拉力、速度、轮次 | 先把现有对象的 roundNumber、8 路拉力、4 路速度、有效性及完成口径写入 JSON |
| 历史分段摘要 | 对象中有 min/max/average/latest/sampleCount | 保留作区间摘要；它们不能还原区间内每一时刻、每一高度的波形 |
| 曲线点 | 当前历史 JSON 尚无实际保留点数组 | 增加同帧真实 points[]，否则只能显示区间摘要，不能假画连续高度曲线 |
| 云端实时解析 | 仍读取旧 state，并要求非空 sessionId | 对齐 status 2.0；无自动作业允许空 sessionId，不把缺字段默认成正常状态 |

上升与下降的拉力都需要保留。direction 由盒子/PLC 提供，服务器不能根据拉力、速度正负或数组位置猜方向。圆环高度必须来自 ringHeightMeters；groupAverageHeight 只是四机平均高度，不能替代。

### 2.2 建议的最小曲线点合同（新增草案）

继续使用 telemetry/history，不另建第三条采样 Topic。保留 records[] 摘要，附加 points[]。一次采样打包成一帧，而不是每个传感器发一条 MQTT 消息。

| 字段 | 含义 |
|---|---|
| streamId、pointSequence | 采样流及稳定点序号；同点补传身份不变，跨重启不碰撞。现协议未提供，须补齐，不由云端虚构 |
| sessionId、roundNumber | 自动会话与实际轮次 |
| sampleTimeMs | 真实采样时间 |
| mode、direction | 自动/检修及 UP/DOWN/STOP，枚举与盒子统一 |
| ringHeightMeters、heightValid | 同帧圆环高度与有效性 |
| ropes[8] | ropeId、sensorId、winchId、tensionKg、valid |
| winches[4] | winchId、speedMetersPerMinute、speedValid、tensionAverageKg、tensionAverageValid |

新字段名是建议合同，不是现有 JSON 已经支持。单位约定为 kg、m/min、m；协议版本变更后统一声明，不把旧 tension 的未知单位自动推断为 kg。

盒子负责保留适量真实点，不上传每个原始采样。采用已有降采样策略：稳定段稀疏保留，方向变化、轮次首尾、告警、极值和明显变化点额外保留。具体频率与变化阈值等现场采样数据确认，不在这里随意固定。重要极值不要被稀疏曲线丢掉，仍由摘要 min/max 留存。

“每隔 0.1 米选点/分桶”属于展示策略，不是要求 PLC 只采样 0.1 米，也不保证有毫米或厘米级物理精度。不能把长区间 average 按起止高度平铺成很多假测量点。

## 3. 曲线：时间负责筛选，高度负责横轴

现前端 power-detail 已使用高度横轴，建议沿用这一真实场景含义：在同一高度，比较不同轮次绞机拉力是否变化。

| 项目 | 简化规则 |
|---|---|
| 指标 | 拉力、速度两个页签 |
| 拉力来源 | 本机两索平均（默认）、传感器 1、本机传感器 2；一次只选一种来源 |
| 速度来源 | 当前选中绞机的实测速度；不是设定速度，也不是全组平均 |
| 方向 | 上升/下降单选，第一版不在同一条线上拼接两方向 |
| 横轴 | 圆环高度，m；由后端给范围、刻度、点坐标 |
| 纵轴 | 拉力 kg/t 或速度 m/min；后端给单位、范围、刻度、显示精度 |
| 今日 | 选择“今日第 N 次清洗”，当前进行中轮次也可选，显示真实起止时间；未结束时结束时间为空 |
| 本月 | 默认本月平均形态曲线；可选择自然周比较 |
| 本年 | 默认截至当前数据的本年平均形态曲线；可按月、季度、半年选择 |
| 叠加 | 最多 3 条所选轮次/周期曲线；可再加 1 条当前范围参考平均曲线 |

“本机两索平均”是同一帧两根索的平均，和“本月多轮的平均形态曲线”是两层概念。传感器 1 视图的参考线必须也是传感器 1 的历史平均，不能拿两索平均混作同一指标参考。

今日默认选择当前轮次；没有当前轮次时选最近一次，加今日已完成合格轮次的参考线。轮次列表可以有 20/100 条，但图上默认不全选。详情抽屉可查所有轮次，不要求鼠标浮层容纳全部记录。

完整单轮作业的另一个可选历史图可以按真实经过时间画，横轴为 elapsedSeconds，纵轴仍为测量值。TIME 与 HEIGHT 不叠加。第一阶段不做 0～100% 清洗进度轴，避免在实际行程/阶段未明确时伪造进度；这是一项待确认的简化选择，不改动旧进度设计的源码。

### 3.1 周/月/年只是选择范围，不是一月一个点

自然周采用周一到周日，与所选自然月取交集。首尾不满 7 天照实显示，不固定“每月四周”，不排除这些有效数据。

例如 2026 年 2 月的月内选择项是：2/1、2/2～2/8、2/9～2/15、2/16～2/22、2/23～2/28。日期、选择 ID 和范围文案都由后端返回。

选择一个周/月/季度/半年，得到的是该范围的多点高度形态曲线，不是只画一个平均值。一个季度的标量平均可以放摘要卡片，不能冒充一条完整曲线。

设备只运行几天，则只用实际数据；空周、未运行月份标为空，未到来的月份不可选。标题写“本月，截至 10 月 11 日”，不可补齐不存在的数据或宣称整月完整。

同比、环比第一阶段可以通过选择本期/上一期明确范围进行两线比较。自动增长率后置，免得半个月和完整上月直接比较；没有基期数据时不填 0%。

### 3.2 服务器如何生成周期曲线

使用一个可解释的规则，不先做多套算法：

1. 选定同一系统/绞机/测点指标、方向、自动模式、日期范围，排除不合格终态轮次和无效测量。
2. 建议展示高度桶宽 0.1 m，由配置确定，基于有效真实高度归桶；缺方向或高度不能进入高度曲线。
3. 每轮每个高度桶先得到该轮的形态代表值，再对该桶内实际有数据的轮次等权求平均。采用真实同帧盒子两索平均，缺一路时不补零。
4. 名称明确为“轮次等权平均形态”，而不是原始全过程精确平均拉力。不同轮数/覆盖高度的点返回参与轮次数。
5. 无点的桶为 null，曲线保留断口，不跨缺口填充或把上下行混合。同轮相同方向反复经过某高度时合并成该桶代表值；这是形态统计，不冒充完整时间轨迹。

第一版形态代表值可使用该轮该桶有效保留点的算术均值，但该值受降采样选点影响，应标记为展示估计，算法版本固定 HEIGHT_BIN_RETAINED_POINT_ROUND_EQUAL_V1；不是精确过程统计。完整平均/同比等数值必须来自盒子真实 sum/count 或时间权重，当前仅有四舍五入 average/sampleCount 时不反推精确总和。

若现场更需要精确高度桶均值，后续由盒子对原始采样计算固定高度桶统计再上传，同一查询合同可复用。不要为第一版同时实现精确高度桶、时间对齐、进度对齐三种方案。

## 4. 前端只选条件和绘图，计算留在后端

继续复用草案中的 WinchTrendQueryDto、TrendUnitVo、WinchTrendUnitSetVo、WinchTensionTrendSeriesVo 和点 VO，不为同一用途再造一套 41 个模型。

第一阶段查询只开放以下核心条件，其他旧兼容字段不作为新增页面能力：

| 条件 | 作用 |
|---|---|
| 系统/绞机 | 路径资源，经大厅验证归属 |
| scope + anchor | TODAY/MONTH/YEAR 及实际日期；映射现有 rangeType/anchor |
| metric + source | TENSION/SPEED；拉力 AVG/SENSOR1/SENSOR2；须在现有 DTO 补明确语义或 Converter 映射，不复用旧含混指标键猜测 |
| direction | UP/DOWN；当前草案 DTO 尚无，须补 |
| grouping | ROUND/WEEK/MONTH/QUARTER/HALF_YEAR；按范围限制合法组合 |
| unitIds | 后端返回的最多 3 个轮次/周期选择项，拒绝跨系统伪造 ID |
| displayUnit | AUTO/KG/TON；速度固定 m/min |

返回选择项、已选曲线、参考曲线、数据截止时间、能力说明以及坐标轴。现有轴模型需补轴标题、单位和 ticks；不是让前端调用 detailAxisRange 自定范围。点数建议每条上限 500，服务端超限时明确合并桶及算法说明，不简单截断末尾。

单条响应统一使用一个拉力单位，包含各曲线和阈值线；AUTO 在服务器按本次全部有效曲线决定，前端重新请求切换单位，不能自己乘 1000。公斤便于读出小变化，但只换单位不会自动放大曲线，真正影响可见波动的是后端返回的轴范围。局部轴标题提示“纵轴非零起点”，不能让单位切换暗示设备安全状态变化。

鼠标浮层显示：高度、方向、最多 3 条已选曲线和 1 条参考线；单轮显示时间/轮次，周期显示实际范围/参与轮次数，不为周期平均值伪造一个采样时刻。全部轮次信息放选择列表或详情面板。

现前端需要移除/替换的计算：按高度重新排序但不区分方向、value*scale、固定 0～25 高度缺省、前端计算纵轴范围及选择全部今日轮次。图表样式、颜色、展开浮层可以继续由前端处理。

## 5. 表结构按阶段实现，不一次落地 16 张

现有六张基础表继续使用。第一阶段拉力曲线优先增加/实现：

| 表 | 第一阶段用途 |
|---|---|
| cleaning_session | 连续自动作业归属，不每天重建 |
| cleaning_round | 每轮起止、完成结果、正常统计资格和实际配置版本 |
| cleaning_history_point | 稳定采样身份、真实时间、高度、方向、指标、有效性 |

区间摘要仍用 cleaning_telemetry_segment/cleaning_segment_measurement。曲线点使用 draft 中的长表，不额外建八张传感器表、四张绞机表或每个周期一张表。

第一版按条件直接查询历史点生成形态曲线；只有真实数据量表明查询变慢时，再启用 cleaning_round_metric/cleaning_metric_aggregate 的精确统计及缓存。不为每次筛选立即启动新线程。统计查询可以限范围/点数，沿用线程中心和已有统计服务。

命令、实际配置和告警所需 cleaning_command_record、cleaning_settings_revision、cleaning_alarm_event 按各自真实功能实施，并非没有必要；它们不应阻挡先完成拉力曲线。完整绑定历史、复杂异常轨迹、独立电机标定、检修记录等后置。暂不删除原 SQL，也不执行 CREATE TABLE；实际字段兼容迁移须另行实施。

## 6. 对 7 类上传消息的优先级

第一优先：实时、历史、命令回执；第二优先：告警及告警处置；第三优先：状态事件/作业汇总，尤其补轮次终态和实际配置快照。轮次统计资格缺失时只能显示观察到的点，不能把它纳入已完成合格轮次参考线。

“一次自动作业汇总”不代替“每轮开始/结束和资格”：仅有 session 的总轮数无法还原每轮时间、方向和曲线。实时数据也不代替可靠历史补传；云端不从断网缺失的实时包补造历史。

## 7. 实施顺序及验证

1. 双端统一 identity、单位、status 2.0、模式/方向/轮次、高度；补历史数组及真实保留点。
2. 接既有 MQTT→表示层→大厅→业务服务→温缓冲→DAO，建立稳定去重和事务保存，数据库提交后再发保存 ACK。
3. 先完成“单台绞机＋单轮＋单方向＋单指标”的真实曲线及轴 VO。
4. 用同一查询/对齐规则补今日轮次列表、月内周、年内月/季度/半年，多选最多 3 条。
5. 最后补精确均值/同比环比和性能缓存；无需先实现全部模型和表。

验收：无历史拉力时不给假曲线；上下行不混；圆环高度不被平均高度替代；缺测不补零；检修不计自动轮次；单轮和周期曲线区别明确；数据只有几天时不补满月；20 次清洗浮层仍只显示所选项；重复批次/点不重复保存；前端不计算平均、单位或轴范围。

本次仅写设计补充并核对源码，未修改 Java/C++/Vue 业务逻辑、未编译、未执行 SQL。HEIGHT 取代第一版进度轴、保留点估计形态、最多 3 条比较线等属于待用户确认的简化选择。
